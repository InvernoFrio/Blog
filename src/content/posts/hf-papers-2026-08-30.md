## 研究背景与动机

### 现有自改进方法的局限

长程智能体在执行任务时会产生大量可复用的经验——成功轨迹揭示了值得保留的程序知识，失败轨迹则暴露了需要避免的策略模式。然而，现有自改进方法存在一个根本性的时间盲区：

**现有方法都是"事后诸葛亮"。** 反思（Reflection）、基于评判的评估（Judge-based Evaluation）、以及自演化智能体框架（Self-evolving Harness），这些方法都将经验处理推迟到执行结束之后。新提取的知识无法帮助产生它的那次运行，也无法被立即应用和验证。其有效性只能在后续的 rollout 或独立评估中测试。

### 两种现有架构的不足

1. **单智能体自纠正**: 同一个智能体既要执行任务又要诊断自己的错误，执行细节占据了诊断所需的上下文空间，导致智能体难以识别和纠正无效策略。

2. **子智能体委托**: 虽然将执行与主智能体分离，但主智能体通常只在子智能体运行结束后才能收到最终摘要，无法在子智能体运行过程中进行重定向。

**核心问题**: 现有架构无法同时支持"实时纠正"和"专门的自改进角色"。

## 核心方法与创新点

### PILOT 架构概述

PILOT（**P**rogramming **I**mprovement through **L**ive **O**versight and **T**raining）是一个 supervisor-worker 框架，通过两个耦合机制实现实时自改进：

- **实时转向（Live Steering）**: supervisor 可在 worker 执行过程中重定向或中止 worker
- **实时自演化（Live Self-Evolution）**: 将执行过程中暴露的程序知识、项目惯例和失败模式蒸馏为可复用的技能和持久记忆

### 形式化定义

对于长程任务 $\tau$，智能体在环境 $\mathcal{E}$ 中执行，环境状态随 worker 的动作变化。模型参数 $\theta$ 保持冻结，持久框架 $H$ 包含：

$$H = (\mathcal{K}, \mathcal{M})$$

其中 $\mathcal{K}$ 为技能库（Skill Library），$\mathcal{M}$ 为记忆（Memory），两者跨 episode 持久化。自我改进的本质是 $H$ 的演化，而非 $\theta$ 的更新。

### 1. 实时转向：双向通道机制

Supervisor 通过实时双向通道与每个活跃的 worker 保持连接。该通道支持五种交互：

**Worker → Supervisor（3种事件）:**
- **通知（Notification）**: worker 自主决定何时报告进度、中间结果或潜在风险，执行继续
- **提问（Question）**: worker 认为下一步需要 supervisor 输入时暂停，等待回复
- **结果（Result）**: 运行时自动将 worker 的最终结果和 worker 编号送达 supervisor

**Supervisor → Worker（2种动作）:**
- **引导（Steer）**: 当实时证据表明 worker 的当前路径应改变时，supervisor 检查 $\xi_j$ 的相关部分，在 worker 的下一个 turn 排队注入指导
- **中止（Abort）**: 当继续 worker 会话不再有用时，supervisor 可中断活跃的 worker

**关键设计**: Worker 的上下文吸收执行细节和死胡同，而 supervisor 的独立上下文专注于目标、近期事件和偏离迹象。这种上下文分离解决了单智能体架构中"执行细节淹没诊断能力"的问题。

### 2. 实时自演化：闭环知识蒸馏

当 supervisor 在实时轨迹中识别出有价值的知识时，将其记录到 $\mathcal{K}$ 或 $\mathcal{M}$ 中，将框架从 $H$ 精炼为 $H'$。此后生成的每个 worker 都加载 $H'$，其轨迹再次暴露于实时转向和实时自演化，形成闭环。

$$H_0 \xrightarrow{\text{episode}_1} H_1 \xrightarrow{\text{episode}_2} H_2 \xrightarrow{} \cdots$$

**关键创新**: 知识蒸馏发生在执行过程中，而非执行结束之后。Supervisor 可以在 worker 仍在运行时就将发现的程序知识记录到框架中，实现"边做边学"。

### 3. 与现有方法的本质区别

| 特性 | 单智能体自纠正 | 子智能体委托 | PILOT |
|------|--------------|------------|-------|
| 执行与诊断分离 | ❌ 同一上下文 | ✅ 但异步 | ✅ 实时分离 |
| 实时重定向 | ✅ 但效果受限 | ❌ 事后才知 | ✅ 专用 supervisor |
| 执行中知识积累 | ❌ | ❌ | ✅ |
| 当前运行受益 | 部分 | ❌ | ✅ |

## 实验结果与分析

### 实验设置

**基准测试（3个长程任务基准）:**
- **Terminal-Bench 2.0**: 89 个可运行任务，要求智能体通过多步 shell 操作完成系统/工程目标
- **SWE-bench Multilingual**: 扩展到多语言的仓库级软件修复
- **SWE-bench Pro**: 比原始 SWE-bench 更长更难的仓库级 issue

**骨干模型（2个冻结开源模型）:**
- GLM-5.1（智谱）
- Kimi-K2.6（月之暗面）

同一模型同时用于 supervisor 和 worker，隔离了能力差距对结果的影响。

### 核心结果

#### 一次性设置（One-shot）

| 配置 | Terminal-Bench 2.0 | SWE-bench Pro |
|------|-------------------|---------------|
| PILOT (GLM-5.1) | **71.9%** | **最高** |
| PILOT (Kimi-K2.6) | **71.3%** | **最高** |
| 最强基线 (Pi) | 66.3% | 55.5% |
| **PILOT 平均优势** | **+5.3pp** | **+4.4pp** |

PILOT 在 6 个配置中的 5 个排名第一，最大领先优势达 **9.8 个百分点**。

#### 自改进设置（跨迭代累积）

这是论文最有说服力的实验。将 Terminal-Bench 2.0 的任务组织成迭代序列，每次迭代共享同一框架状态：

- **GLM-5.1**: 最佳通过率从 66.3% 提升至 80.9%（**+14.6pp**）
- **Kimi-K2.6**: 最佳通过率从 68.5% 提升至 80.9%（**+12.4pp**）
- 技能库分别增长 **21** 和 **31** 个可复用技能

#### 效率分析

| 指标 | GLM-5.1 | Kimi-K2.6 |
|------|---------|-----------|
| 平均输出 token 减少 | **42.9%** | **47.4%** |
| 每百万 token 成功评估提升 | **110.3%** | **134.0%** |

这意味着 PILOT 不仅提升准确率，还显著提高了 token 效率——智能体学会了用更少的 token 解决更多的任务。

### 与基线的对比分析

在相同的 GLM-5.1 骨干和相同初始技能库下，PILOT 与 Pi、OpenCode 的对比显示：

- PILOT 的框架演化能力远强于单智能体基线
- 累积经验转化为后续任务性能的效率显著更高
- 技能积累和复用能力形成了复利效应

## 与智能体认知模块的关联

### 1. 与记忆系统的关联

PILOT 的持久框架 $H = (\mathcal{K}, \mathcal{M})$ 本质上是一种**层次化记忆系统**：

- **技能库 $\mathcal{K}$**: 类似程序记忆（Procedural Memory），存储可执行的程序知识
- **记忆 $\mathcal{M}$**: 类似语义记忆（Semantic Memory），存储项目惯例和失败模式

这与我们之前分析的"零Token记忆操作"（2026-08-05）和"记忆认知陷阱"（2026-08-23）形成对话——PILOT 展示了一种**边执行边更新记忆**的范式，而非事后批量更新。

### 2. 与推理/规划的关联

实时转向机制本质上是一种**在线规划纠正**：

- Supervisor 维护对任务目标和进展的全局视图
- 当 worker 的局部行为偏离目标路径时，supervisor 提供纠正信号
- 这类似于人类认知中的"元认知监控"——一个独立的认知过程持续评估当前行为的有效性

### 3. 与认知架构的关联

PILOT 的 supervisor-worker 分离呼应了认知科学中的**双过程理论**：

- **Worker**: 类似 System 1（快速、自动、细节导向），负责具体执行
- **Supervisor**: 类似 System 2（慢速、控制、目标导向），负责策略评估和纠正

更重要的是，PILOT 将"自改进"从一个后处理步骤提升为一个**持续的认知过程**，这与人类学习的机制更一致——我们不是在完成一个任务后才学习，而是在执行过程中就不断调整策略。

### 4. 启发性思考

PILOT 的成功提出一个值得深思的问题：**智能体的自改进应该发生在什么时间尺度上？**

- **最粗粒度**: 任务结束后反思（Reflexion 等）
- **中等粒度**: 执行过程中的步骤级纠正（单智能体自纠正）
- **最细粒度**: PILOT 的实时转向 + 实时自演化

PILOT 的实验表明，更细粒度的自改进带来更好的效果。这暗示智能体认知架构的设计应该考虑**多层次、多时间尺度的自改进机制**。

## 总结与启发

### 论文亮点

1. **问题定义精准**: 准确识别了现有自改进方法的"时间盲区"，提出了"实时自改进"的概念
2. **架构设计优雅**: Supervisor-worker 分离既解决了上下文污染问题，又保持了实时性
3. **实验设计严谨**: 自改进设置的迭代设计完美隔离了"框架演化"的效果
4. **效率指标有说服力**: 不仅看准确率，还展示了 token 效率的巨大提升
5. **通用性强**: 跨两个骨干模型和三个基准的一致改进

### 不足与局限

1. **成本问题**: 双倍模型调用（supervisor + worker）的成本未在论文中充分讨论
2. **Supervisor 的能力瓶颈**: 当 supervisor 和 worker 用同一模型时，supervisor 的诊断能力受限于模型本身的元认知能力
3. **技能库的可控性**: 长期演化后，技能库可能变得庞大且难以管理，缺少技能遗忘或抽象机制
4. **评估任务的局限**: 主要评估编码和终端操作任务，对其他长程任务（如创意写作、复杂研究）的泛化能力未知

### 对智能体研究的启示

1. **记忆更新应是持续过程**: 当前很多智能体架构将记忆更新作为后处理步骤，PILOT 证明了"边做边学"的优势
2. **上下文分离的重要性**: 将执行上下文与诊断上下文分离，是提升长程任务性能的有效策略
3. **自改进需要闭环验证**: 知识不仅要被提取，还要在产生它的同一运行中被验证，这形成了一种"在线学习"范式
4. **效率与性能可以兼得**: PILOT 的技能积累机制让智能体学会"用更少做更多"，这对实际部署至关重要
