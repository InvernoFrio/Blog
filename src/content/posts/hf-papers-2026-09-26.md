一句话概括：**把"记住什么"的决策从写入时刻推迟到读取时刻，让记忆的形状由当前任务决定。**

## 二、研究背景与动机：写入时蒸馏的两个原罪

现有的智能体记忆系统（Reflexion 的口头反思、ReasoningBank 的推理策略、Voyager 的可执行技能、SkillOS 的技能策展等）几乎都遵循同一范式：任务结束后，把轨迹蒸馏成一个固定制品（reflection / workflow / skill / reasoning strategy），之后靠相似度检索复用。论文把这称为 **write-time curation（写入时裁决）**。

问题出在"裁决发生得太早"——此时未来查询还不存在：

1. **信息丢弃过早且不可逆**。写入时蒸馏必须决定哪些细节不值得留，而这个判断是在不知道未来任务的情况下做的。被丢弃的细节，如果后来的任务恰好需要，就永远找不回来了。
2. **一个固定摘要要服务无数个未来查询**。同一条轨迹往往蕴含多个可能的"教训"：一条家务轨迹对某个任务提供的是"加热/冷却"状态转移模式，对另一个任务提供的却是物品摆放策略。哪条教训重要取决于下游任务，而写入时根本不知道下游任务是什么。

此外，**训练写入时策展器还有长程信用分配问题**：存储决策的价值可能要到很多个任务之后某个相关查询到来时才显现，奖励信号被严重延迟。SkillOS 之类的方案不得不把相关任务人工分组来制造学习信号——论文指出其消融实验里任务分组本身就是主要性能来源之一，这有点"为了造奖励而造结构"的味道。

JitMem 的核心主张简单有力：**延迟裁决（defer curation）**。写入时只做无损的原始轨迹存储，什么都不丢；等当前任务 xₜ 到来、检索出相关轨迹后，再由一个记忆策展器（memory curator）结合任务条件合成紧凑的、任务自适应的记忆载荷（payload）。这与认知科学中"情景记忆是重建式而非回放式"的观点（Schacter & Addis, 2007）高度一致——回忆总是被当前目标和线索塑造的。

读取时裁决还顺手解决了信用分配：载荷在**同一任务**内被消费，奖励即时返回，策展器可以直接用任务成功率训练，无需分组、无需延迟回报。

## 三、核心方法与创新点

### 3.1 系统组成：四个组件，只有一个是可训练的

JitMem 工作在流式任务设定下：智能体依次收到任务 {x₁, x₂, …, x_T}，每个任务产生轨迹 ξₜ = (o₁, a₁, …, oₙ, aₙ) 和奖励 rₜ ∈ [0,1]。系统由四部分组成：

- **记忆库 ℳ**：存完整原始轨迹，不做任何摘要/反思/技能抽象。质量门控用 executor 充当 LLM-as-judge，只有判定成功的轨迹才入库（保证检索到的是正例示范）。
- **检索器 ℛ**：BM25 检索 top-k 条轨迹（只匹配任务描述、不匹配轨迹内容），轻量且与基线一致，不参与训练。
- **记忆策展器 πφ**：输入 = 当前任务描述 + k 条检索到的原始轨迹，输出 = 任务自适应的自然语言载荷 pₜ = πφ(xₜ, ξ̂ₜ)。载荷是"简报"：指出最相关的过往经验、抽取同类任务奏效的策略、给出针对当前任务的具体指引。**载荷是一次性的、不入库**。
- **执行器 πL**：冻结的 LLM，拿任务 + 载荷去执行，全程不更新。

整体目标是最大化累计任务成功：

$$\max_{\phi}\ \mathbb{E}\Big[\sum_{t=1}^{T} r_t\Big]$$

推理时每任务四步：**Retrieve → Curate → Execute → Update**。

### 3.2 策展器训练：GRPO + 即时奖励，信用分配间隔为零

训练流程是本文最漂亮的工程简化。对每个采样任务 xₜ：

1. 从固定训练库检索轨迹 ξ̂ₜ；
2. 策展器生成一组 G 个候选载荷 {pₜ⁽ⁱ⁾}；
3. **冻结的执行器**用每个载荷各做一次任务，返回基准原生奖励 rₜ⁽ⁱ⁾（ALFWorld / τ²-bench 为 0/1 成功率，WebShop 为连续分数）；
4. 用 GRPO 更新策展器，组内优势为：

$$\hat{A}_i = r_t^{(i)} - \mathrm{mean}_j\, r_t^{(j)}, \qquad \mathcal{L}_{\text{GRPO}} = -\frac{1}{G}\sum_{i=1}^{G} \hat{A}_i \cdot \log \pi_\phi\big(p_t^{(i)} \mid x_t, \hat{\bm{\xi}}_t\big)$$

（无 value 网络，且沿用 Liu et al. 2025 的做法省略标准差归一化。）

关键性质：**rₜ 是同一任务 t 的载荷 pₜ 的直接函数，中间没有任何时间步**——策展器动作与奖励之间的时间差为零。对比写入时记忆：第 s 步的存储决策要等第 t ≫ s 步某个查询命中那个制品才被打分。训练不需要内容质量辅助奖励、不需要任务分组、不需要回报整形，曲线稳定收敛。

技术细节：训练库是**固定**的（用基础执行器跑一遍训练集、按真值标签保留成功轨迹），保证奖励只反映载荷质量而非"恰好能检索到什么"；代价是轻微的训练/测试分布偏移（测试库会长出带策展器的轨迹），论文用"分阶段刷新记忆库"量化了这个偏移（收益有限，见下）。

### 3.3 三个设计选择，三个消融各自成立

| 设计选择 | 消融做法 | 性能下降幅度 |
| --- | --- | --- |
| 任务条件化（把 xₜ 喂给策展器） | 移除任务描述，退化为查询无关摘要器 | 免训练版 −3.1（ALFWorld）/ −4.6（WebShop）；RL 后扩大到 −11.4 / −10.4 |
| 质量过滤存储（只存成功轨迹） | 存全部轨迹并标注成败标签（ReasoningBank/SkillOS 做法） | −1.5~−2.9（ALFWorld）/ −2.3~−3.4（WebShop） |
| 原始轨迹存储（不预先蒸馏） | 入库前先做 ReasoningBank 式蒸馏 | −1.7~−2.9（ALFWorld）/ −6.8~−8.2（WebShop） |
| RL 学到的确实是"蒸馏经验" | 强制检索器返回空集 | 掉到甚至低于未训练版，最多 −14.8 / −15.2 |

特别值得注意的是第一行：**RL 训练放大的恰恰是"利用任务信号"的能力**，而不是"压缩轨迹"的能力——去掉任务条件后 RL 版退化得比免训练版更狠。这证明奖励在教策展器"按需取用经验"，而非通用摘要。

## 四、实验结果与分析

三个基准：ALFWorld（文本具身控制，140 测试任务）、WebShop（网页购物，500 实例）、τ²-bench（多轮对话工具使用，航空/零售/电信）。对比无记忆执行器和三个写入时基线：ReasoningBank（策略蒸馏）、MemP（多粒度记忆项）、SkillOS（RL 训练的技能策展器）。三种冻结执行器：Qwen3-8B、Gemini-2.5-Pro、GPT-5.4。

### 4.1 主结果（成功率 SR，3 次不同任务顺序的均值）

| **JitMem（RL）** | Qwen3-8B | **77.4（+16.2）** | **61.1（+20.5）** | **32.8（+16.3）** |

### 4.2 四个关键发现

1. **同为零样本策展器，读取时裁决已经赢了**。JitMem-base（Qwen3-8B）在 ALFWorld 上 60.5 vs ReasoningBank 55.7；Gemini 策展器在 WebShop 上 61.0 vs SkillOS-gemini 41.0。更有说服力的是"弱策展器胜强基线"：GPT-5.4 执行器下，Qwen3-8B 当策展器的 JitMem-base（79.3）超过用 GPT-5.4 当策展器的 ReasoningBank（77.9）和 SkillOS-gpt（70.0）——**增益来自范式而非模型强度**。
2. **RL 训练叠加增益且更省**。同用 Qwen3-8B 基座，JitMem 77.4 vs SkillOS 61.2（ALFWorld）、32.8 vs 16.5（WebShop），而 JitMem 只用任务奖励，SkillOS 需要额外判官模型造内容质量奖励 + 任务分组。
3. **策展器跨执行器迁移**。用 Qwen3-8B 训练的策展器直接服务 GPT-5.4，只比用 GPT-5.4 直接训练的差 1.4 SR（86.7 vs 88.1）——它学到的是通用策展策略而非执行器特定模式，一个策展器可以养多个执行器。
4. **上下文更省、执行更短**。ALFWorld + GPT-5.4 执行器上：JitMem 每任务输入 9.8K token / 11.6 步，对比 ReasoningBank 19.7K / 16.2 步、SkillOS-base 22.4K / 16.9 步、无记忆 17.8 步。相对写入时方法输入 token 省 50.3%–56.3%、步数降 28.4%–31.4%。

**τ²-bench 的诚实负面结果**：在 Airline 和 Retail 域，所有记忆方法相对无记忆都没有超出方差的提升，只有 Telecom（复杂多步策略核验）拿到 +11.0。论文的解释很到位：**读取时裁决的价值在于合成过程性指引，而不是简单事实检索**。

**其他消融**：分阶段刷新训练库只带来 +2.8（Qwen3-8B）/+0.9（GPT-5.4）的边际收益，说明固定训练库已足够；测试库热启动（预填 100 条训练轨迹）收益可忽略，策展器对冷启动检索稀疏的情况处理得很好。

**定性分析**是最直观的证据：同一条"加热/冷却物体"的经验轨迹，被"把热土豆放进冰箱"检索到时，策展器突出状态转移策略（先加热再放置）；被"把报纸放进沙发"检索到时，则突出放置类指引（核验目标位置）。写入时制品只能固化其中一种叙事，读取时裁决可以两个都生成。

## 五、与智能体认知模块的关联

这篇论文对智能体认知架构的启发相当系统：

- **记忆模块**：它提出了一个根本性的设计准则——**"存什么"与"用什么"要解耦**。无损情景存储 + 按需重建，比"写入时抽象 + 检索时复用"更接近人脑情景记忆的工作方式（重建式记忆，被当前目标塑造）。这提示我们：智能体的长期记忆库更应该像"经历档案"而非"经验笔记"。
- **推理/规划模块**：载荷本质上是"为当前问题定制的过程性简报"——它提供的是策略与流程指引而非事实，与规划器需要的输入形式天然匹配。定性分析里 RL 训练后涌现出环境特定的过程语义（先走到台灯处、再用它检查碗），说明即时任务奖励能诱导出"可执行的程序性知识"。
- **信用分配与学习**：把记忆策展的长程信用分配"归约为单步"，是一个可迁移的方法论技巧。凡是"决策的价值在未来才显现"的模块（经验蒸馏、技能归纳、工具库维护），都可以考虑把决策推迟到价值兑现的时刻，用即时奖励训练。
- **模块化认知架构**：策展器与执行器解耦带来了跨执行器迁移（差距仅 1.4 SR），这支持"认知组件应当可插拔、可复用"的架构观——记忆系统不该和某个特定骨干模型绑死。
- **认知科学互文**："同一经验、多种教训"的观察与认知科学中记忆重构理论呼应，为智能体记忆研究提供了跨学科的理论支点。

## 六、总结与启发

**亮点**：
- 范式级的洞察："何时裁决记忆"比"如何裁决记忆"更根本，且这个时机问题有一锤定音的答案——读取时刻。
- 训练范式极其干净：单一任务奖励、GRPO、无分组、无辅助判官，信用分配间隔为零。
- 实验充分：三基准 × 三执行器 + 免训练/RL 对照 + 四项消融 + 效率统计 + 迁移验证，还包含对自己不利的 τ²-bench 分域结果。
- 未训练的 JitMem-base 就已超越多个 RL 写入时基线，说明"开源"的收益来自架构而非调参。

**不足与开放问题**（论文自述 + 我的补充）：
- BM25 检索是瓶颈，记忆库变大变杂后按任务描述关键词匹配会失灵；语义检索 / 学习型检索器是自然的下一步。
- 每任务多一次策展器调用，增加延迟与成本；载荷格式是手工设计的、按基准固定。
- 只做每任务一次的裁决，未来可扩展到轮次/步级的动态重构（随着新观测到来更新载荷）。
- 质量门控依赖 executor-as-judge 判成功，判错会污染记忆库；失败轨迹中的"反面教材"价值被直接丢弃（虽然消融显示保留失败轨迹反而更差，但那可能是标注方式的问题）。
- τ²-bench 上无训练版为限（缺少标准训练划分），范式在多轮对话场景的上限尚未验证。

**对后续研究的启发**：把"记忆写入策略"这整个子领域的注意力，部分转移到"记忆读出策略"上；同时，"把延迟信用分配改写为即时信用分配"这一技巧值得在技能归纳、工具维护、自我改进等长程问题中复用。对于构建智能体认知系统的实践者，一个直接可用的工程启示是：**别急着把经验总结成文档，先存原始轨迹，等知道要解决什么问题再总结。**
