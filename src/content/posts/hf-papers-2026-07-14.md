## 研究背景与动机

当前 AI 智能体在短任务上表现令人印象深刻——修个代码 issue、执行几条 shell 命令、完成一个 coding ticket，都能做到高成功率。但现实世界的 workflow 往往是**长周期**的：复现一篇论文的实验结果、从 GitHub 仓库搭建完整环境、审计复杂的多模态数据集、调试编译器工具链、驱动多阶段 ML 训练流水线……这些任务需要数百步操作、持续数十分钟到数小时，智能体必须反复读写文件、运行脚本、检查中间输出、修正计划、从错误中恢复。

现有基准存在两个关键盲区：

1. **时间跨度太短**——Terminal-Bench 2 的任务平均 20-30 分钟、20-30 个 episode 就能完成，严重低估了真实工作流的难度
2. **评估信号太稀疏**——只看最终结果的 pass/fail 意味着：一个完成了 90% 中间步骤但在最后一步失败的智能体，和一个从头就失败的智能体得到相同的零分

这导致我们无法理解当前智能体在长工作流上到底能走多远，也不知道它们在哪里崩溃。

## 核心方法与创新点

### 基准设计：46 个长周期终端任务

Long-Horizon-Terminal-Bench (LHTB) 包含 46 个任务，横跨 9 大类别：

- 交互式游戏
- 实验复现
- 软件工程
- 多模态分析
- 科学计算
- 地球与气候科学
- 机器人学
- 材料科学
- 芯片设计 (EDA)

每个任务都在 Docker 容器化的终端环境中运行，智能体只能通过 shell 命令与环境交互。关键设计原则是：**任务被分解为细粒度的评分子任务**，而非简单的 pass/fail。

### 密集奖励评分机制

这是本文最核心的创新。每个任务的评分函数为：

$$R = \frac{\sum_{k=1}^{K} w_k \cdot r_k}{\sum_{k=1}^{K} w_k}$$

其中 $r_k \in [0,1]$ 是第 $k$ 个子任务的归一化得分，$w_k$ 是非负权重。子任务分三类：

1. **二值子任务** — 严格布尔检查（如单元测试是否全部通过、服务是否在预期端口响应），$r_k \in \{0, 1\}$
2. **连续/阈值子任务** — 用于量化目标（如复现指标是否在容差范围内），随误差线性衰减到 0，提供有意义的部分学分
3. **Episode 聚合子任务** — 用于战役式任务（如游戏关卡），统计成功 episode 的比例，衡量智能体能否**稳定可靠**地执行长周期行为

任务被判定为"解决"的条件是 $R \geq \tau$（默认 $\tau = 0.95$）。

### 反过拟合设计

为防止智能体对表面测试用例过拟合，公开检查只验证命令行行为、文件格式和少量简单示例，且权重较低。**大部分奖励来自隐藏的压力测试**——动态生成更难的输入和 schema 变体（嵌套 manifest、gzip+base64 包装、重命名字段、缺失值、注入噪声、旋转/裁剪图像、异常帧等）。智能体不能通过硬编码输出或只修补公开用例拿高分，必须实现**鲁棒的解析、核心算法和端到端的 artifact 生成**。

## 实验结果与分析

### 评估规模

使用 Harbor 框架 + Terminus-2 agent harness，评估了 15 个前沿模型：GPT-5.5、GPT-5.4、GPT-5.3 (Codex)、DeepSeek V4 Pro、Gemini 3.1 Pro、GLM 5.1/5.2、Kimi K2.6/K2.7 Code、MiniMax M3、Qwen3.7 Max、Qwen3.6 Plus、Doubao Seed 2.1 Pro、Hy3、Grok 4.20。

### 核心数据

| 指标 | 数值 |
|---|---|
| 平均 token 消耗/任务 | **9.9M** |
| 平均 episode 数/任务 | **231** |
| 平均执行时间/任务 | **85.3 分钟** |
| 最强模型 (GPT-5.5) pass@1 ($R \geq 0.95$) | **15.2%** (7/46) |
| 最强模型 pass@1 ($R \geq 1.0$) | **10.9%** |
| 所有模型平均 pass@1 ($R \geq 0.95$) | **4.3%** |
| 所有模型平均 pass@1 ($R \geq 1.0$) | **1.7%** |

这些数字比 Terminal-Bench 2 高出一个数量级——后者平均只需 20-30 分钟、20-30 个 episode。

### 失败模式分析

论文的定性分析揭示了一个关键发现：**智能体失败通常不是因为每个局部步骤都错了，而是因为它们无法可靠地持续推进、验证完成度、在预算内完成长周期任务**。密集奖励使得以下差异变得可见：

- **超时驱动的未完成进度** vs **过早停止** vs **薄弱的自我验证**
- 智能体在局部操作上可能做得不错，但在"维持全局一致性"和"判断何时真正完成"上表现糟糕

## 与智能体认知模块的关联

这篇论文对智能体认知架构研究有几层重要启发：

### 1. 长程规划是核心瓶颈，而非局部推理

当前 LLM 智能体在单步推理上已经很强，但在需要**数百步持续规划**的任务上仍然崩溃。这直接指向认知架构中**规划模块**的不足——我们需要的不是更好的单步推理，而是能够维护和更新长期计划、在遇到障碍时灵活调整的规划机制。

### 2. 记忆与上下文管理的必要性

每个任务消耗 9.9M tokens，这意味着智能体需要在极长的上下文中保持对关键信息的追踪。这与我们之前讨论的**主动记忆机制**（如 Remember When It Matters）高度相关——被动的上下文窗口扩展不够，智能体需要结构化的记忆系统来决定什么信息值得保留、什么可以丢弃。

### 3. 自我验证与元认知

论文发现智能体在"判断自己是否真正完成"上表现薄弱。这指向认知架构中**元认知模块**的缺失——智能体需要能够检查自己的工作、评估进展、决定是否需要回溯或重新规划。

### 4. 世界模型的长周期可靠性

虽然这篇论文不是直接关于世界模型的，但其发现与之前我们讨论的"世界模型运动学 vs 动力学"问题形成呼应：在长周期任务中，智能体对"自己做了什么、效果如何"的内部模型可能严重偏离现实。

### 5. 密集奖励作为训练信号

密集的子任务评分不仅对评估有价值，对**训练**同样重要。这为强化学习训练长周期智能体提供了天然的奖励塑形 (reward shaping) 方案——将稀疏的最终奖励分解为密集的中间信号。

## 总结与启发

**亮点：**
- 填补了长周期终端任务评估的空白，任务设计非常贴近真实工作流
- 密集奖励评分机制是重要创新，让部分进度变得可见
- 反过拟合设计（隐藏压力测试）确保评估的鲁棒性
- 对 15 个前沿模型的全面评估提供了清晰的基线
- 失败模式分析直指核心问题：不是局部推理差，而是全局持续性不足

**不足：**
- 46 个任务的规模仍然有限，可能无法覆盖所有类型的长周期工作流
- 90 分钟的超时设置可能对某些任务不够公平
- 论文未深入探讨**什么样的认知架构改进**能够真正解决这些瓶颈
- 缺乏对智能体"计划修订"行为的细粒度分析——我们不知道智能体是在坚持错误计划还是在频繁切换但都不成功

**最大的启示：** 当前 AI 智能体的能力曲线在短任务上已经陡峭上升，但在长周期任务上仍然接近地面。这不是模型能力的问题，而是**认知架构**的问题——我们需要更好的规划、记忆、自我验证和错误恢复机制。LHTB 为衡量这些能力提供了第一个真正有挑战性的标尺。
