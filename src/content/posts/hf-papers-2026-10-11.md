## 研究背景与动机

当前主流的机器人策略几乎都把一个"模型"留在控制回路里，主要有两条路线：

1. **VLA（视觉-语言-动作模型）**：如 RT-2、OpenVLA、π₀/π₀.₅，把观测直接映射到动作，映射关系隐含在权重里。问题是不可检查、不可编辑，每一点改进都要新数据 + 重新训练；而且在新任务上微调会**抹掉旧任务能力**（论文引用的实验显示 π₀.₅ 在五个真实任务上顺序微调后平均分从 86.9 掉到 31.4）。
2. **Agent Harness（智能体挂具）**：如 Agent-as-Policy、Harness VLA，让 VLM 在运行期做决策或指挥 VLA。它比 VLA 多了一层显式文本记忆，但 VLM/VLA 仍是黑盒——动作怎么推出来的无法完全检查；而且每个决策都要调用大模型，随机性大、成本高、行为难以复现。

第三条路线是 **Code-as-Policy**：让模型写代码来控制机器人。但已有工作要么**每个 episode 在线现写代码**（Code-as-Policies、ProgPrompt、PyRUA-Lean 等），状态还依赖外部黑盒感知模型（检测器、SAM）；要么**离线写一个程序但状态来自外部**（RHO 用 SAM/Molmo，EmbodiedSWE 直接读模拟器 oracle 值）。状态的不确定性不受代码控制，测错了也只能"将就"。

作者的洞察很直接：**具身世界本质上是一台图灵机**。图灵机 = 一条存储符号的磁带 + 一组固定规则；规则不变、只换磁带，同一套规则就能处理任意输入。对应到物理世界：世界状态（物体位姿、空间关系）和机器人状态（关节角、末端位姿、可达域）就是磁带，策略就是规则。而这些状态其实**都是可观测的**——机器人状态来自本体感知，物体位姿可以从 RGB 图像结合已知物体几何恢复出来。既然状态可以精确表示，那"规则"为什么还需要一个模型在环？写成代码不就行了？

这就是 **Code-Only-as-Policy（COAP）**：代码自己从图像和本体感知中**测量并跟踪**机器人、环境、任务三类状态，并据此做出全部决策；同一份代码跨 episode 复用，不同任务共享一个代码库，运行期无 VLM/VLA。

## 核心方法与创新点

### 1. 具身图灵机：状态即磁带，代码即规则

COAP 维护一个显式状态 x_t，分三部分：

| 状态成分 | 内容 | 更新来源 | 图灵机对应 |
|---|---|---|---|
| 环境状态 | 每个物体的位姿、尺寸、类别、空间关系；每条记录带误差、来源、时间戳 | 感知层代码从图像测量 | 磁带 |
| 机器人状态 | 关节角、末端位姿、夹爪开度、双臂可达位姿 | 本体感知（每步） | 磁带 |
| 任务状态 | 当前阶段、物体-手臂分配、重试计数、任务须保留的信息（如杯下颜色） | 任务代码执行中更新 | 图灵机内部状态 |

源代码 θ 构成规则，定义状态转移：

$$(x_{t+1}, a_t) = F_\theta(x_t, o_t)$$

关键在于 **θ 在运行期是冻结的，只有 x_t 在变**。新的 episode 布局只改变"磁带"（状态），同一段程序在所有布局（包括 held-out 测试布局）上都适用。这一下就把"泛化"从权重空间转移到了**状态表示 + 代码鲁棒性**两个可检查的维度上。

### 2. 代码自己测状态：状态是"可编程"的

感知代码不依赖任何学习模型：从边界像素发射相机射线，与桌面平面 z=z₀ 求交得到桌面位置

$$p = c + \lambda d, \quad \lambda = (z_0 - c_z)/d_z$$

再把已知 3D 形状的候选物体在位置和偏航角上做位姿拟合，取与观测区域重叠最大的匹配。相机模型、网格、桌面高度都是随基准发布的常量，写死在规则 θ 里；**随 episode 变化的才是状态**。测量结果持久化进 episode 级 WorldState：被机械臂遮挡的物体保留最后一次测得的位姿；需要毫米级精度的任务在最终接近前用腕部相机复测。

这带来一个质变：**状态错了可以修**。测量出问题，编码智能体改的是测量代码，状态会随迭代越来越准——而不是像 SAM/检测器那样把不确定性交给黑盒。

### 3. 共享代码库与 RSI 闭环

- **可复用**：所有任务操作同一形态的状态（§3.1），且代码分层、依赖只向下（任务程序 → 物体族 → 操作原语 → 感知 → 运动规划）。新任务运行的代码 **83% 来自共享库**。
- **抓取原语库**：Top / Side / Handle / Rim / Edge / Cloth 六类抓取方法（分别被 28/6/3/3/4/1 个任务程序使用），由"接近方向 × 接触方式"定义。
- **RSI 闭环**：编码智能体（Opus 5.5 Max）在固定规则下离线开发代码库——不允许为单个 episode 写 hack、测试期不许用 oracle 状态、不碰基准测试集——自主完成"总结—写码—调试"，无人在环。
- **并行分支搜索**：每轮 k，各智能体在自己的 git worktree 里检查失败运行记录的状态，定位出错的变量或规则，提出 diff Δ，形成可运行的搜索前沿：

$$\mathcal{C}_k = \{\theta_k + \Delta_{k,1}, \ldots, \theta_k + \Delta_{k,m}\}$$

  每个分支先过两道 CPU 检查（数值场景下每个阶段是否达到目标状态；每个路径点的 IK 与碰撞检查），再在验证 episode 上并行评测。合并准则：

$$J_q(\theta_k + \Delta; V_q) \ge J_q(\theta_k; V_q) + \epsilon_q$$

  即在保证其他任务不回退的前提下只合并真正提升的改动——**像软件工程师改进程序一样改进策略**，测试过的行为就是运行时的行为。

## 实验结果与分析

**基准**：RoboDojo 的 42 个双臂操作任务，五个维度：记忆（6）、精度（8）、开放指令（8）、泛化（12）、长程（8）。主指标成功率（SR）与进度分（Score）。

**总体结果**（节选主要对手，完整榜单 24 个方法）：

| 方法 | 类型 | 记忆 | 精度 | 开放 | 泛化 | 长程 | Overall SR | Score |
|---|---|---|---|---|---|---|---|---|
| **COAP（本文）** | 纯代码 | **89.9** | **75.1** | **64.1** | **65.7** | **56.4** | **70.24** | **73.9** |
| PhysicalRSI | Agent Harness + VLA | 46.6 | 32.5 | 24.9 | 15.6 | 37.3 | 31.38 | 36.27 |
| Simate-beta | VLA | 33.0 | 26.9 | 8.5 | 27.9 | 43.4 | 27.96 | 33.95 |
| Rex-M1 Preview | VLA | 48.2 | 23.8 | 6.1 | 26.1 | 33.0 | 27.44 | 33.79 |
| Awomo-0.5 | World Action Model | 41.2 | 33.5 | 22.9 | 23.8 | 26.8 | 29.64 | 35.34 |
| GPT-6 Astra | 直接作具身策略 | 38.7 | 4.0 | 31.0 | 30.5 | 8.2 | 22.48 | 28.97 |
| π₀.₅ | VLA | 4.7 | 5.5 | 1.7 | 8.2 | 14.7 | 6.93 | 11.44 |

COAP 总成功率 70.24%，比 SOTA（PhysicalRSI，31.38%）**高出 38.9 个百分点**，且**五个维度全部第一**。

**按任务长度分组的成功率（%）**：

| 步数上限 | 任务数 | COAP | Agent Harness | VLA | GPT-as-policy |
|---|---|---|---|---|---|
| 200–500 | 12 | 78.1 | 47.3 | 21.9 | 26.5 |
| 550–800 | 15 | 78.4 | 30.6 | 38.0 | 26.9 |
| 900–1900 | 15 | 52.0 | 13.2 | 22.1 | 14.8 |

COAP 在所有长度组领先；最长任务组所有方法都掉，但 Agent Harness 掉得最狠（47.3 → 13.2）。

**执行效率与失败恢复**：

- 每个 episode 中位数 **352 次决策**，中位调用仅 **0.3 ms**（多数只是交付已规划的动作）；每 episode 约 25 次感知/规划调用占了 99.4% 的决策时间。对比"每个决策都要过一遍 LLM"的 Agent Harness，量级差异是决定性的。
- 出错时的处置：12% 重试后**救回**（失败步骤主要是抓取打滑 49%、搬运中掉落 32%）；22% 重试后仍失败；42% 主动发现并报告原因；1% 撞步数上限。也就是说失败大多被显式状态 + 回溯重试机制兜住了，剩下的也能给出可读的失败归因。

**开发过程**（四个任务的 RSI 时间线）：make_toast / hang_mugs / sweep_blocks / fill_pen_holder 从首次评估到首次合并分别只用 5.8 / 6.8 / 7.9 / 2.7 小时，成功率随合并持续爬升（如 make_toast 50→77，sweep_blocks 0→60→50）。

**错误分析**：失败归为五类——感知错误（未识别随机外观、终检出错、物体分裂/合并）、接触错误（滑脱、推不到位、释放时倾倒）、逻辑不完整、代码设计差（固定尺寸过滤、固定夹爪宽度、固定匹配阈值）、未知。上界也由此清晰：**状态表示的准确度 × 代码逻辑的鲁棒性**。标准布局上验证集成功率 76.7%、测试集 74.9%，泛化差距很小。

**逐任务亮点**：cover_blocks、press_by_number、swap_T、play_Xylophone、solve_equation、pour_by_language 等一批任务 90–100%；但 hang_mugs 32%、sweep_blocks 28%、pack_objects_into_box 0.7%、organize_table 0%——开放结构的整理类任务仍是硬骨头。另有两个任务（plug_in_charger、store_tools_in_toolbox）连程序都没有。

## 与智能体认知模块的关联

这篇论文对智能体认知研究的启发，比"机器人"三个字大得多：

1. **记忆 = 显式变量，而非上下文文本**。COAP 的记忆是结构化状态记录（带误差、来源、时间戳的世界状态 + 任务状态），遮挡时保留最后观测、必要时复测。这比"把记忆塞进 prompt"更接近认知科学里工作记忆 + 情景记忆的分工，而且**可审计、可回溯**——失败可以直接定位到是哪个变量、哪条规则错了。
2. **世界模型 = 可编程的测量，而非黑盒预测**。它没有学一个"想象未来"的网络模型，而是把环境状态显式化、可测量、可修正。这与"世界模型要服务于决策"的立场一致：对决策真正重要的是**当前状态的准确表示**。
3. **推理与规划 = 显式规则 + 反思性调试**。决策逻辑写成代码后，"推理"变成了可检查的控制流；改进不是靠祈祷 prompt 生效，而是靠**失败回溯到状态 → 定位规则 → 提 diff → 回归测试 → 合并**的工程化循环。这是元认知（监控失败、归因）与技能学习（库的累积）的可操作化版本。
4. **自我改进需要可控的介质**。RSI 最大的风险是改坏了不知道。代码的优势在于：每次改动显式、可测、可回滚，且**"测试过的行为就是运行时的行为"**——对照 RoboRSI（RSI 闭环里仍是 VLM 决策），黑盒的不确定性让测试与运行脱节。这为所有做自改进的智能体系统提了个醒：**先把状态和规则外化，再谈递归改进**。
5. **闭环数据引擎**。COAP 跑通后在 CPU 上无模型并行执行，稳定批量产出成功轨迹，且每条轨迹自带显式状态和每个动作的决策依据，可直接训 VLA、监督 Agent Harness 内的模型。"显式策略先于学习策略"，是一种新的数据飞轮。

## 总结与启发

**亮点**：

- **视角漂亮**：具身图灵机的抽象把"泛化"从玄学变成了两个可工程化的量——状态表示准确度、代码鲁棒性。
- **数字硬**：70.24% vs 31.38%，五维全胜；决策延迟 0.3 ms 级；验证/测试差距仅 1.8 点。
- **RSI 叙事完整**：并行分支搜索 + 合并准则 + 回归保护，让"编码智能体改进具身策略"第一次有了软件工程级别的纪律性。
- **诚实的数据引擎定位**：不把代码策略当终点，而是 VLA/Harness 的高效数据源。

**不足**：

- **泛化上限明确**：仍需少量任务特定逻辑；开放整理类任务（organize_table 0%、pack_objects 0.7%）几乎全挂；两个任务连程序都没写出来。"状态可测量"的前提在杂乱、长程、开放场景里并不总成立。
- **依赖已知物体几何与固定相机模型**，对未知物体、形变物体（布料类只 1 个任务）不友好。
- **开发成本没有完全货币化**：RSI 用了 Opus 5.5 Max 级别的编码智能体 + 并行 GPU 分支评测，wall-clock 短但算力开销不小（论文自己也说分支越多越快拿到合并、但费 GPU）。
- 是技术报告，暂未见公开代码/数据链接，复现门槛待观察。

**对后续研究的启发**：如果你在做智能体的认知架构，这篇最值得抄的不是机械臂控制，而是**"把状态和规则外化成可测试的白盒，再让智能体在这个白盒上做递归改进"**的工作流。对记忆研究：状态记录要带来源和误差，支持回溯与复测；对世界模型研究：显式可测的状态可能比隐式预测更"够用"；对自改进研究：没有回归测试的自改进是危险的，介质越显式，递归越安全。COAP 还暗示了一个有趣的方向：**先用代码把任务"解到 70%"，再蒸馏给神经策略去啃剩下 30% 的开放性**——两种范式不是替代，而是接力。
