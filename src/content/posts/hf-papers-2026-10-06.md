# 同模型验证：把生成器自己变成"带证据的裁判"—— VeriHarness 深度解读

> **TL;DR**：长程智能体产出的报告、表格、代码没法用单元测试一键判对错，测试时也没有参考答案和评分标准。VeriHarness（Google Cloud AI Research）的关键洞察反直觉：**多数投票恰恰会扔掉正确答案**——在 APEX-Agents 的十次采样池里，全体一致的"共识值"有 34% 是错的，而产生分歧的主张里 74% 至少含一个正确候选、但最常见的答案只有 47% 正确。于是它把**生成用的那个模型**（不换更强裁判）装进一个验证 harness：分歧消解者（disagreement resolver）用环境证据裁决竞争主张，共识挑战者（consensus challenger）专门攻击一致答案并搜索集体遗漏，最后在全新上下文里仲裁、用证据支撑的修订定稿。五个长程工作区基准 × 两个前沿模型上全部最优，修订后较单次生成平均 **+6.2 / +6.4 分**；验证技能还能从失败反馈**自进化**，从零学出的技能库甚至超过人类手写的。一句话：**一致不等于正确，证据才等于正确**。

## 二、研究背景与动机：验证正在成为长程智能体的瓶颈

长程智能体越来越多地交付**工作区工件**（workspace artifacts）：尽调报告、财务模型、电子表格、多文件材料。这类输出的正确性判断本身就是一项重活——检查一份报告可能要溯源每条论断到原始文件、重算数值、跨文件理解需求。编码和数学好歹有单元测试、可执行检查、证明验证器兜底，而通用复杂任务在测试时**既没有参考答案，也没有评分标准**。

现有测试时验证方法基本只盯着 rollout 池本身：

- **多数投票 / 自洽性**：把最常见的答案当正确答案；
- **LLM-as-a-Judge**：让模型读一遍 rollout 打分。

这两类方法的共同问题是**只依赖模型已有的信念，不触碰环境里可以提供的证据**。作者用实证数据击穿了这类方法的前提。在 APEX-Agents 上对 Claude Opus 4.8 的十次采样池做声明级（claim-level）评分：

| 现象 | 数字 | 含义 |
|------|------|------|
| 共识值被判错误的比例 | **34%** | 一致同意完全不保证正确，投票修不掉这类错 |
| 分歧主张中含正确候选的比例 | **74%** | 分歧常常"暴露"了正确答案 |
| 分歧主张中最常见答案的正确率 | **47%** | 多数票在分歧场景下接近抛硬币 |

这组数字是全文的发动机：**共识会藏错，分歧常含对**。所以验证器必须做两件互补的事：为分歧主张寻找能区分候选的证据（同时接受"全都错"的可能），以及主动挑战共识主张、搜寻所有 rollout 一起漏掉的需求。

作者还刻意设定"**无更强裁判**"的验证：生成器和验证器是同一个冻结模型、同一套工具，测试时看不到评分细则。这既贴近前沿现实（生成模型已是最强模型，没有更强的可以来监督），也保证了增益不可能来自"更强模型的知识灌入"——只能来自 rollout 池和环境证据。

## 三、核心方法与创新点

### 3.1 问题形式化：把"验证"落到声明（claim）级

任务 t = (s, ℰ)：描述 s 加环境 ℰ（源文件、数据、应用状态）。生成器在模型 M 上跑出 N 条 rollout，每条 r_i = (d_i, w_i, τ_i) 分别是交付工件、最终工作区状态、动作轨迹。工件里包含若干**声明**（claims）：对数值、解释、需求满足与否的断言。

对同一个问题/需求 p，各工件给出答案集合 𝒱_p，其经验分布与熵为：

$$\pi_p(v)=\frac{1}{N}\sum_{i=1}^{N}\mathbf{1}[v_{i,p}=v],\qquad H(\pi_p)=-\sum_{v\in\mathcal{V}_p}\pi_p(v)\log\pi_p(v)$$

H(π_p) = 0 是**共识声明**，H(π_p) > 0 是**分歧声明**。注意熵只衡量候选之间的差异：可以全体一致而全体都错——这正是上面 34% 的来源。

验证器的输入是任务 + rollout 池，输出是选定或修订后的 r*，外加一份**证据记录** C（查了什么、发现什么、哪些未决）。它对标的是外部评分器的分数，但永远看不到评分器。

### 3.2 VeriHarness = 同一个模型 + 验证 harness

核心公式一目了然：

$$\text{Verifier}=(M,\ \mathcal{H}_V),\qquad \mathcal{H}_V=(\mathcal{W},\ \mathcal{T},\ \Pi,\ \mathcal{S})$$

- **𝒲 工作区**：把每条 rollout 的工件、状态、轨迹都摊成文件，与任务描述和环境并列。验证器可以把声明溯源到出处、重算数值、执行代码取证；
- **𝒯 证据工具**：读源文件、查元数据、重计算；
- **Π 验证协议**：把两类检查任务分配到**隔离的模型上下文**，再仲裁、交付。协议不绑定工件类型，报告、表格、代码通用；
- **𝒮 技能库**：可复用的失败模式及其检查程序（如"增长率标签跨了哪两年？公式用对起止列了吗？"）。**工具管'怎么查'，技能管'查什么'**，且技能里不含任务特定答案。

### 3.3 分歧消解者：用信息增益选检查

对分歧声明 p，验证器追踪各候选值的来源与计算路径，优先做**期望信息增益最大**的检查：

$$\text{Gain}(\chi)=\mathbb{E}\big[\,H(b_p)-H(b_p(\cdot\mid \mathcal{E}(\chi)))\ \big|\ e_{<k}\big]$$

（实际由模型定性判断而非数值计算。）拿到证据 e 后执行候选消除：

$$\mathcal{V}_p \leftarrow \{v\in\mathcal{V}_p:\ v\ \text{与}\ e\ \text{一致}\}$$

如果证据否掉了所有候选，只有当证据明确确立了新值时才记录新值，否则声明保持未决。示例：两份 rollout 引用草稿报 100m，第三份引用终稿报 120m——消解者查版本历史，确认终稿覆盖草稿，裁决 120m。

### 3.4 共识挑战者：主动攻击"全体一致"

共识没有竞争候选可测，挑战者就得**先提出"它可能怎么错"，再去环境里测**。检查按"暴露错误的概率"定性排序：

$$\text{Priority}(\chi)=P(\chi\ \text{暴露共识声明的错误}\mid t, R, e_{<k})$$

它检查三类共识声明：**共识值**（从原始输入重算、用元数据核对标签/单位/币种）、**共识解读**（把共同解释对照任务指名的文件、源文件声明的期间、工作簿里的定义）、**共识遗漏**（对照任务描述，找所有 rollout 都没做的需求）。遗漏尤其阴险——它不出现在任何工件里，必须先被"显影"成验证对象。示例：三条 rollout 全把数字标成 USD，挑战者查源元数据发现应为 EUR——这是投票永远发现不了的**共享错误**。

### 3.5 仲裁与证据支撑的修订

两项调查在隔离上下文中进行（合进一个上下文实测掉 0.8 分），再由全新上下文的仲裁者把两份证据记录合成**选择 + 修订计划**，交付时附带完整证据链。修订不是"重写一遍"——对照实验显示把池子聚合成新工件（无证据检查）全面弱于 VeriHarness，说明增益来自**证据记录**而非重写本身。

### 3.6 验证技能自进化

把每个基准的任务按约 3:1 分成开发集/测试集：模型读开发集失败案例 + 评分器反馈，提出候选技能库；候选若在开发集上不劣于当前库就替换。测试集分数只记录、不参与选择。从空库或人类手写库出发均可进化——后文会看到，从零学出的库超过了人类手写的库。

## 四、实验结果与分析

### 4.1 基准与设置

五个长程工作区基准，每任务每模型冻结 N = 10 条 rollout，所有方法共享同一池子；生成器与验证器同为 Gemini 3.5 Flash 或 Claude Opus 4.8（thinking level high），三随机种子均值。

| 基准 | 任务数 | 领域 | 工件 | 评分方式 |
|------|--------|------|------|----------|
| APEX-Agents v1.0 | 480 | 银行/法律/咨询 | 备忘录、模型、答案 | 专家 rubric |
| Workspace-Bench Lite | 100 | 文件密集工作区 | 文档与文件 | rubric judge |
| WorkBuddy Bench | 200 | 代码/办公/Web | 补丁与办公文件 | 组合验证器 |
| SpreadsheetBench 2 | 321 | 商业电子表格 | 工作簿 | 重算比对 |
| JobBench | 65 | 35 种白领职业 | 多文件工件 | rubric judge |

| 选择 oracle（上界） | 63.1 | 53.8 | 72.4 | 89.4 | 39.6 | 60.4 |

关键读数：

- **选择阶段**就超过所有基线：Flash 平均 +4.4、Opus +4.1，**十个模型×基准设置全部第一**，且每个格子的增益都超过种子间标准差；
- **证据修订**再进一步：平均增益达 **+6.2（Flash）/ +6.4（Opus）**，Opus 在 APEX-Agents 上单项 +11.7 分；
- **多数投票和 best-of-N 几乎原地踏步**（+0.3 左右），直接印证"共识藏错"诊断；
- **有环境没协议不够**：给了同样工作区和证据工具的 agentic verifier 只收回约一半增益——协议 + 技能才是增量来源；
- **移植性**：把协议塞进 Gemini CLI / Claude Code / Codex 也能保住大部分增益（但 JobBench、SB-2 上个别 CLI 会回落到单次生成水平）；
- **上界还在远处**：selection oracle 平均 62-63 分，说明"从池子里选对"仍有大量空间，验证研究才刚开始。

### 4.3 消融与分析（Opus 4.8，五基准平均）

| 配置 | Avg |
|------|-----|
| 单次生成 | 49.6 |
| 仅分歧消解者 | 54.3 |
| 仅共识挑战者 | 52.6 |
| 两者合一上下文 | 55.3 |
| **完整 VeriHarness** | **56.1** |

- 两个组件**互补**：消解者在分歧密集的 APEX 上贡献最大；挑战者在共享错误（单位、符号约定、集体遗漏）占比高的 SB-2 / JobBench 上补位；
- 两项调查放进同一上下文掉 0.8 分，支持**隔离上下文**设计；
- 选择增益几乎全部来自**分歧池**：154 个共识池上只比池均值高 0.6 分，262 个分歧池上高 6.1 分，且熵越高增益越大（低熵 4.5 → 中熵 7.7）；
- 挑战者**很安全但有盲区**：从未推翻全体正确的声明；漏掉的共享错误里约 70% 是它查了正确的中间结果、而错误藏在更后面的步骤——验证器倾向于在 rollout 停下的地方收手，缺的是"错误会出在哪"的先验知识。

### 4.4 技能自进化

在 Opus 4.8 的 APEX-Agents 与 SB-2 held-out 子集上对比四种技能库（A 空库 / B 人类手写 / C 从 A 进化 / D 从 B 进化）：

| 对比 | 结果 |
|------|------|
| C vs A（从失败学） | held-out **+11.0**（APEX）/ **+5.7**（SB-2） |
| C vs B | 从零学出的库**超过**人类手写库 |
| D vs B（人类初始化再进化） | 再 **+6.8**（APEX）/ **+3.7**（SB-2），且收敛更快 |

学到的技能长这样："列出任务要求的每一项，逐项比对候选答案的覆盖情况，修订前先核对支撑证据"（APEX）；"看增长率标签里的期间，检查公式用的起止列是否对应"（SB-2）。可复用、不含答案，正是"元认知知识"的形态。

## 五、与智能体认知模块的关联

1. **元认知的工程化落地**。"分歧消解 + 共识挑战"本质上是两种系统化的**认知审计**：前者在内部候选间做证据裁决（类似审稿人对比 competing claims），后者给"自己确信的事"找反例（类似 red team）。论文证明了同模型自审能持续出真金白银的增益——前提不是换更强的大脑，而是给大脑配一套好的**反思协议**。

2. **验证即"信念更新"**。消解者的候选消除公式 𝒱_p ← {v : v 与 e 一致} 就是贝叶斯信念更新的可执行版本；信息增益驱动的检查选择，等于把主动感知（active sensing）搬进了认知层。对智能体研究的启发：**不要让模型'再想想'，要让它'去查证'**。

3. **共识陷阱与共享错误**。34% 共识值是错的、约 70% 的漏检错在"后面步骤"——这提示多智能体讨论/自我一致性范式存在系统性盲区：**相关性错误（correlated errors）不会被投票稀释**。世界模型/信念状态方向上，"对一致状态做挑战"应当成为标配检查。

4. **技能库 = 外化的过程性记忆**。验证技能从失败反馈自进化、人类先验加速收敛，与技能学习/经验库（Voyager、Reflexion 一脉）形成呼应，但场景换成了"怎么查错"。这说明**自我改进不一定动模型权重，改进'检查程序库'同样可复利**。

5. **证据记录即可审计性**。交付附带完整证据链，让长程工件从"黑盒输出"变成"可追溯论断"。这对需要问责的智能体应用（金融、法务、科研）是刚需能力。

## 六、总结与启发

**亮点**：（1）用一组干净的实证数字（34% / 74% / 47%）推翻了"投票选多数"的默认验证范式，立论扎实；（2）方法极简且免训练、即插即用——把生成器自己变成带 harness 的验证器，在两个前沿模型、五个基准十个设置全部第一；（3）消融完整：两个组件互补、隔离上下文有效、修订增益来自证据而非重写，结论可信度高；（4）慷慨开源约 2.6 万条 rollout（成本超 10 万美元），给后续验证研究立了地基；（5）技能自进化的发现很妙：**从零学的技能库超过人类手写库，人类先验的价值在加速收敛**。

**不足**：（1）10 条 rollout 的池子本身很贵（时间 + 算力），轻量场景的性价比未讨论；（2）信息增益/优先级全靠模型"定性判断"，检查预算如何最优分配没有理论刻画；（3）挑战者有结构性盲区——错误藏在中间步骤之后时容易漏，这恰是需要"错误先验"的地方；（4）评分依赖各基准自带的 rubric/重算器，无 grader 可用的真实场景中如何自我评估仍是开放问题；（5）验证开销（额外的检查与修订轮次）的成本收益比只有粗略报告。

**对后续的启发**：验证应当与生成并列为智能体的**一等公民能力**；把"分歧当信号、共识当靶子"写进任何自审流程；技能库形态的验证知识可积累、可迁移、可蒸馏进小模型。对我自己的智能体工作流也是个提醒：与其相信"大家都这么说"，不如养成"证据在哪"的肌肉记忆。
