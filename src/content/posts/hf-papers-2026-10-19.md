## 一、论文基本信息

- **标题**：Mosaic: Multi-Session Agentic Reinforcement Learning
- **链接**：[arXiv:2610.22174](https://arxiv.org/abs/2610.22174)（2026-10-15 提交，cs.CL / cs.AI / cs.LG）
- **项目主页**：<https://lark-ai-lab.github.io/Mosaic/>
- **作者**：Minrui Xu, Xinyu Zhou, Xiang Long, Haochen Tan, Zhijiang Guo（通讯）
- **机构**：香港科技大学（广州）LARK 实验室、华为 Foundation Model Lab、香港城市大学、香港科技大学
- **代码/数据**：项目主页已公开；训练数据使用 REDSearcher_RL_1k（1,000 条高难度深度搜索任务），评测基准为 BrowseComp

## 二、研究背景与动机

Agentic RL（用在线 rollout + 奖励反馈训练 LLM 智能体做多轮推理、工具调用、环境交互）近两年收益显著，GRPO 及其变体是其中的主力方法。但几乎所有主流方法都隐含一个假设：**一条 rollout 轨迹 = 一个连续累积的上下文 = 一段训练样本**。

这个假设正在被推理侧的工程实践打破。现代智能体 harness（如各类 coding agent）普遍使用两类技术：

1. **Context compaction（上下文压缩）**：当累积历史逼近上下文窗口上限时，把历史压缩成一段较短的前缀，并以这段新前缀作为后续动作的条件继续执行。压缩本身就"重写了"条件上下文，事实上开启了一个新 session。
2. **Subagent forking（子智能体分叉）**：主智能体把子任务委派给子智能体，子智能体在自己的上下文里执行并回传结果，产生分支 session。

也就是说，推理时的轨迹天然是**多 session** 的，而训练时却按单 session 处理——训练/推理分布失配，既损害一致性，也限制了优化空间。

一个自然的补救是**广播（broadcasting）**：把轨迹级的 outcome 优势直接复制到所有 session 的每个 token 上。这能用，但监督太粗——它不区分各个 session 的贡献，也无法引导"该把计算预算花在哪个 session"。轨迹跨的 session 越多，信号就越糊。

于是本文提出问题：能否把"session"作为轨迹内的一个显式优化单元，让 RL 的信用分配跨过 session 边界？

## 三、核心方法与创新点

Mosaic 的总体思路是**无 critic 的分层优化**：轨迹级管"全局、长期、结果导向"，session 级管"局部、短期、边际贡献"。两者叠加成最终的训练信号。

### 3.1 形式化：多会话轨迹与广播基线

一条轨迹 τᵢ 被表示为 Nᵢ 个 session 的集合 τᵢ = {sᵢ,ⱼ}（j = 1..Nᵢ），每个 session 内部仍是标准的"动作-观察"交互序列。在 Megatron 等训练框架里，每个 session 对应一个独立的训练 segment，因此目标函数按 session 汇总、以 token 数加权，保持同一 prompt 组内各 rollout 权重相等。广播基线即令所有 session 的优势都等于轨迹级 GRPO 优势 Âᵢᵗʳᵃʲ = (Rᵢ − μ_G)/(σ_G + ε)。

### 3.2 轨迹级：session 感知的优势估计

session 数 Nᵢ 是探索程度和结构复杂度的代理量，但**不能直接当奖励**：一是原始数量未必反映有意义的差异；二是"少用 session"还是"多用 session"应该取决于任务成败，否则策略会学会刷 session 数。据此论文给出三条排序约束：

- **C1**：成功轨迹里，session 用得越多成本越高，优势应越低；省着用的应得更高优势。
- **C2**：失败轨迹里，session 用得太少可能意味着探索/执行不足，应得更低优势；失败但充分探索的应得更高优势。
- **C3**：任务结果必须始终占主导——session 用得多不能让失败轨迹反超成功轨迹。

具体构造上，把组内轨迹按结果分成成功组 G₁ 和失败组 G₀，在各自组内把 Nᵢ 映射为居中秩 uᵢ ∈ [−1, 1]（用秩而非原始数量，对长尾轨迹更鲁棒），再定义调制因子：

> Âᵢˢᵃᵗ = (1 − ρ·uᵢ) · Âᵢᵗʳᵃʲ，其中 0 ≤ ρ < 1

因为 1 − ρ·uᵢ ∈ [1 − ρ, 1 + ρ] 恒为正，session 信号只调幅度、不翻符号，C3 天然满足（成功轨迹 u 越大优势被压低，失败轨迹反之，恰好实现 C1/C2）。

关键细节是**同质组兜底**：当一组 rollout 全对或全错时 GRPO 优势为 0，样本效率为零。Mosaic 在全成功组用 −β₁·uᵢ（继续奖励省 session），全失败组用 β₀·min(uᵢ, 0)（只惩罚探索不足、不给失败者正优势）。这一步把"浪费掉的同质组"重新变成有区分度的训练信号。

### 3.3 session 级：基于边际信息增益的优势塑形

轨迹级信号对同一轨迹的所有 session 仍是同一个标量，偏稀疏。Mosaic 把每个 session 看作一次**状态转移** sᵢ,ⱼ = (vᵢ,ⱼ₋₁ → vᵢ,ⱼ)（v 是以可见前缀上下文为核心的智能体状态），并分出三种类型：普通 session（常规推理/工具调用）、压缩 session（把全量上下文压成短前缀）、子智能体 session（委派与结果回传）。

过程奖励用**无 critic 的边际信息增益**定义。设 y* 是任务真实答案，用更新前的策略 π_θ̄ 定义"答案似然势函数"：

> Φ(y* | x, v) = (1/L) Σ_ℓ log π_θ̄(y*_ℓ | x, v, y*_<ℓ)

直观含义：给定当前状态 v，策略有多容易写出正确答案。一个 session 若补进了有效证据、滤掉了噪声、或带回了高质量子任务结果，势函数应上升。于是 session 级即时奖励为输出态与输入态的势差（stopgrad）：rᵢ,ⱼ^Δ = Φ(vᵢ,ⱼ) − Φ(vᵢ,ⱼ₋₁)。

两个精巧的设计：

1. **按 session 类型分别做组内归一化**。三类 session 的边际增益分布天然不同（普通 session 靠检索增益，压缩 session 看保留/去噪的权衡，子智能体 session 受执行与回传双重影响）。若全局归一化，均值偏低的压缩 session 会被系统性压低；类型内归一化让每类都有正负信号。
2. **排除最后一个 session**。终局 session 的输出态通常含最终答案，正确的答案会让似然陡增、污染边际增益分布，故其塑形信号置 0。

最终 session 级优势 = 轨迹级优势 + λ_r × 归一化塑形信号：Âᵢ,ⱼˢᵉˢˢⁱᵒⁿ = Âᵗʳᵃʲ + λ_r·r̂ᵢ,ⱼ，再替换广播式 session 优势进入 token 级目标。

一句话总结层级分工：轨迹级给长期结果信号，session 级给局部边际信号——前者防跑偏，后者管分配。

## 四、实验结果与分析

**设置**：基准为 BrowseComp（1,266 道需要持久深度搜索的高难题目，天然诱发多 session 轨迹）；基座模型 Qwen3.5-4B，ReAct 式智能体循环，工具为 search（Serper）与 visit（Jina Reader）；训练集 REDSearcher_RL_1k（1,000 条任务），训练 1 epoch，batch size 16，组大小 8；超参 ρ=0.2, β₀=0.1, β₁=0.2, λ_r=0.1。判定器用 deepseek-v4-flash。

**主结果**（BrowseComp 准确率 % / 平均 session 数）：

| 方法 | 推理方式 | 单会话 | 多会话-压缩 | 多会话-子智能体 |
|---|---|---|---|---|
| Qwen3.5-4B | 基座 | 23.22 / 1.00 | 24.80 / 1.70 | 21.64 / 2.98 |
| GRPO | 单会话训练 | 31.99 / 1.00 | 34.68 / 1.24 | 31.91 / 2.09 |
| IGPO | 单会话训练 | 28.52 / 1.00 | 31.36 / 4.12 | 24.64 / 3.26 |
| Broadcasting | 多会话训练 | — | 35.31 / 3.17 | 31.44 / 4.43 |
| **Mosaic** | 多会话训练 | — | **38.86 / 2.35** | **32.46 / 3.77** |

几个关键观察：

- **多会话能力不会从单会话训练里"自发泛化"出来**：单会话 GRPO 加上多会话推理（即 test-time scaling）只把压缩场景推到 34.68，仍低于直接多会话训练的 35.31。要会用 session，就得在多 session 轨迹上训。
- **Mosaic 全面胜过广播**：压缩场景 38.86 vs 35.31，相对提升约 10.1%；而且平均 session 数反而从 3.17 降到 2.35——**性能更好、执行更省**。
- **对比 IGPO**（同样用信息增益做过程监督，但施加在 turn 级）：Mosaic 在 session 级做塑形不仅准确率更高（38.86 vs 31.36），还大幅降低了计算边际增益的 wall-time（每个 session 只需两次势函数评估，而非每 turn 一次）。

**消融**：轨迹级 session 感知优势和 session 级塑形各自都有贡献；两者叠加在压缩场景有明显额外增益，在子智能体场景只有小幅增益。作者的解释很诚实：压缩轨迹是线性的，而子智能体轨迹更接近 DAG，一个 session 可能影响多个后继，"边际增益"作为即时奖励会偏离真实贡献。

**机制分析**：混合结果组里，成功轨迹的优势随 session 数递减、失败轨迹递增，成功者始终占优，符合 C1–C3 的预期；同质组的兜底机制提供了区分性信号。类型条件归一化纠正了全局归一化对压缩 session 的系统性偏置。

**行为模式**（最有启发的发现）：

| 方法 | 准确率↑ | #Sessions | 正增益 session 占比↑ | 每 session 增益↑ |
|---|---|---|---|---|
| 基座（compact） | 24.80 | 1.70 | 37.36% | 0.30 |
| Broadcasting（compact） | 35.31 | 3.17 | 47.74% | 0.86 |
| **Mosaic（compact）** | 38.86 | 2.35 | 59.92% | 0.89 |
| 基座（subagent） | 21.64 | 2.98 | 27.39% | 0.41 |
| Broadcasting（subagent） | 31.44 | 4.43 | 41.15% | 0.74 |
| **Mosaic（subagent）** | 32.46 | 3.77 | 51.04% | 0.80 |

多会话优化带来的收益**与 session 效用、分配质量相关，而不是 session 数量的单调上升**。广播把三个指标全推高（包括数量）；Mosaic 则在不增加 session 数的前提下把"正增益 session 占比"从 47.74% 提到 59.92%。用作者的话说：核心问题不是"该用几个 session"，而是"执行的每个 session 能榨出多少有效进展"。

## 五、与智能体认知模块的关联

这篇论文对智能体认知架构研究有三点直接启发：

1. **上下文管理不只是工程技巧，而是可优化的认知动作**。context compaction 长期被视为 harness 层的"续命"手段，Mosaic 把它升格为一个可以被 RL 信用分配覆盖的状态转移。这与"记忆的写入/压缩/遗忘应当被学习"的观点同构——压缩 session 的本质就是有损记忆巩固，而边际信息增益恰好是衡量"这次巩固保住了多少可用状态"的标尺。
2. **子智能体分叉 = 认知架构里的委派与合并问题**。论文指出 subagent 轨迹是 DAG，边际贡献估计会失真——这其实是多智能体信用分配在单体智能体内部的投影。对研究 hierarchical agent / supervisor-worker 架构的人来说，"fork-merge 过程中信息如何无损传递"是一个被 RL 目标显式化后才看得清的学习问题。
3. **"session 效用"是元认知层面的资源理性**。Mosaic 的 C1/C2 约束本质上是在训练智能体形成一种预算感：成功了就别折腾，没把握就多探索。这正是元认知中"何时继续、何时换路子、何时该停"的量化版本。论文讨论部分提出的统一方向——在有限上下文预算下学"什么信息该被带到下一步"——几乎就是可训练的工作记忆管理理论。

## 六、总结与启发

**亮点**：

- 问题定义先行：第一个把"多会话 agentic RL"形式化为独立设定，指出训练/推理失配，这个 framing 本身就有长期价值。
- 方法优雅且便宜：全程无 critic，轨迹级用秩调制、session 级用两次似然评估，比 turn 级过程监督（IGPO）更强还更省。
- 分析到位：不止报点，还给出"session 效用/分配"的机制解释，把性能增益归因到行为模式而非玄学。

**不足**：

- 规模有限：只在 Qwen3.5-4B + BrowseComp 上验证，4B 模型上的结论能否迁移到大模型和 coding harness（论文自己提到的 Claude Code 类黑盒场景）待考。
- 边际信息增益需要真实答案 y*，只适用于可验证任务；开放式任务如何定义势函数是悬而未决的。
- 子智能体场景增益有限（32.46 vs 31.44），DAG 结构下即时奖励与真实贡献的偏差是实打实的硬骨头。

**对后续研究的启发**：论文讨论部分点出的三个方向值得跟踪——(1) 跨 session 状态转移（compaction/fork/merge）作为统一学习目标；(2) 异步训练下多 session rollout 的组构建与陈旧样本处理；(3) 面向部分黑盒 harness（丢弃推理 token、丢弃工具响应等破坏上下文连续性的机制）的多会话 RL。另外，"session 效用而非 session 数量"这一结论对所有做长程智能体的人都是一句实用忠告：优化目标应该锚在每个计算单元的产出上，而不是计算单元的数量上。
