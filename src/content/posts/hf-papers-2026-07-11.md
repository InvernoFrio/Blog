# Remember When It Matters: Proactive Memory Agent for Long-Horizon Agents

**论文链接：** [Hugging Face](https://huggingface.co/papers/2607.08716) · [arXiv](https://arxiv.org/abs/2607.08716v1) · [GitHub](https://github.com/yifannnwu/proactive-memory-agent)

**机构：** Meta AI

**作者：** Yifan Wu, Lizhu Zhang, Yuhang Zhou, Mingyi Wang, Bo Peng, Serena Li, Xiangjun Fan, Zhuokai Zhao

---

## 研究背景与动机

在长程任务（long-horizon tasks）中，智能体面临一个被作者称为 **"行为状态衰减"（behavioral state decay）** 的核心失败模式：在任务执行过程中，本应影响未来决策的信息——任务要求、环境事实、先前尝试、失败诊断、未完成子目标——逐渐失去了对行为的控制力。

这个现象比"信息丢失"更微妙。信息可能仍然存在于轨迹记录中，甚至仍在模型的上下文窗口内，但它不再可靠地影响智能体的下一步决策。举几个典型的例子：

- 智能体在任务早期识别了一个要求，后来在修复无关 bug 时违反了它
- 观察到某条命令失败后，稍后又尝试了几乎相同的变体
- 诊断了一个错误模式，后来却把它当作新问题处理

作者指出，这与现有的记忆研究形成了关键区分。大多数记忆系统关注的是 **"存什么"和"怎么取"**——存储、更新、检索相关记录。但长程任务执行引入了一个更深层的问题：记忆必须决定 **何时介入**。暴露太少的记忆会让智能体重复犯错；暴露太多则增加延迟、消耗 token，甚至干扰当前进展。

> 这是一个比摘要更强的控制问题。摘要器问的是"保留什么"；我们的记忆问的是"保留的执行状态是否应该在下一个决策中被激活"。

## 核心方法与创新点

### 架构总览：双智能体协作

论文的核心设计是一个 **即插即用的记忆智能体（memory agent）**，它与未经修改的行动智能体（action agent）并行运行：

```
行动智能体 ←→ 环境（交互、工具调用）
     ↑
     | 注入提醒（或保持沉默）
     ↓
记忆智能体（观察轨迹 → 更新记忆库 → 决定是否干预）
```

每 N 步触发一次记忆智能体。它观察任务描述、最近的轨迹窗口和当前记忆库，执行一个 **两阶段工作流**：

### Phase 1：记忆库管理

记忆库 $B_t = (s_t, K_t, P_t)$ 由三个组件构成：

- **状态字段 $s_t$**：记忆智能体的私有进度跟踪，记录开放问题和未解决风险，**从不展示给行动智能体**
- **知识记忆 $K_t$**：相对稳定的事实——任务要求、环境属性、文件路径、配置细节、用户/工具验证的事实
- **程序记忆 $P_t$**：尝试与结果——失败的命令、成功的修复、被排除的假设、诊断信号

记忆智能体通过四个工具调用来管理记忆库：

| 工具调用 | 功能 |
|---------|------|
| `memory_update_status` | 更新私有进度跟踪 |
| `memory_save_knowledge` | 保存重要事实到知识库 |
| `memory_save_procedural` | 记录调试经验、失败方法、解决方案 |
| `memory_delete` | 删除过时或不正确的记忆条目 |

这种工具调用接口使记忆管理变得 **显式且受约束**——Phase 1 的输出是一系列结构化的库编辑，而非自由形式的轨迹摘要。

### Phase 2：主动干预选择

这是论文最核心的创新。给定更新后的记忆库和最近轨迹，记忆智能体做出一个二元决策：

$$i_t \sim \pi_M^{\text{intervene}}(\cdot \mid x, w_t, B_t)$$

其中 $i_t \in \{\emptyset, \text{text reminder}\}$。

- 如果选择 **发出提醒**：系统将提醒作为瞬态记忆上下文注入到下一次行动智能体调用中
- 如果选择 **空干预 $\emptyset$**：行动智能体的上下文保持不变

**空干预是一个显式动作**，不是默认行为。记忆智能体被鼓励仅在被记住的项目可能影响下一个行动决策时才介入：

- ✅ 有用的介入：即将被违反的要求、解释当前观察的环境事实、不应重复的先前尝试、仍然相关的诊断、被忽视的未完成子目标
- ❌ 不鼓励的介入：宽泛的战略建议、重复当前观察中已可见的信息、接管行动智能体的规划

### 学习记忆干预策略

论文探索了用 **SFT + GRPO** 训练开源记忆策略：

1. **SFT 阶段**：从提示的记忆智能体中蒸馏轨迹，教会模型执行记忆库操作和选择提醒 vs. 沉默
2. **GRPO 阶段**：用强化学习校准干预策略，奖励信号来自下游任务的验证器奖励

关键洞察：SFT 教会了接口和基本纪律（紧凑写入、更新过时状态、避免不必要的提醒），但 **仅靠模仿无法优化记忆干预的下游效果**——RL 负责校准"何时记住的状态应该重新进入控制循环"。

## 实验结果与分析

### 主实验

在 Terminal-Bench 2.0（自主命令行执行）和 τ²-Bench（对话式工具使用）上评估：

| 基准 | 行动模型 | 基线 | + 记忆 | 提升 |
|------|---------|------|--------|------|
| Terminal-Bench 2.0 | Sonnet 4.5 | 37.6% | 45.9% | **+8.3 pp** |
| Terminal-Bench 2.0 | Opus 4.6 | 43.5% | 45.9% | +2.4 pp |
| τ²-Bench (均值) | Sonnet 4.5 | 55.0% | 61.8% | **+6.8 pp** |
| τ²-Bench (均值) | Opus 4.6 | 66.2% | 68.7% | +2.5 pp |

几个关键观察：

- **对较弱行动智能体提升更大**，但对较强行动智能体提升也不消失，说明收益不仅仅是补偿能力不足
- **跨领域差异明显**：τ²-Bench 中 airline (+10.0 pp) 和 retail (+9.6 pp) 提升最大，telecom 较小 (+2.6 pp)，印证了记忆作为 **领域敏感的干预策略** 的定位

### 消融实验

论文在 τ²-Bench (Sonnet 4.5) 上进行了精心设计的消融：

| 变体 | 设计 | 宏平均 | 微平均 |
|------|------|--------|--------|
| **完整两阶段记忆智能体** | Phase 1 + 选择性 Phase 2 | **64.3%** | **61.5%** |
| 全库暴露 | Phase 1 + 暴露整个记忆库 | 61.5% | 58.8% |
| 始终注入 | Phase 1 + 每步强制提醒 | 60.8% | 61.2% |
| 仅注入（无库） | 跳过 Phase 1 + 选择性 Phase 2 | 60.8% | 60.8% |
| Mem0 | 通用记忆层 | 61.5% | 59.6% |
| 基线 | 无记忆 | 57.5% | 55.0% |

消融揭示了每个组件的独特贡献：

1. **全库暴露** 有用但不够：维护记忆库有帮助，但暴露所有记住的状态不足——必须选择当前行为相关的内容
2. **始终注入** 竞争力强但不够平衡：在某些领域甚至领先微平均，但在宏平均上不如选择性沉默
3. **仅注入（无库）** 不够稳定：类似顾问系统的指导在某些领域有帮助（如 telecom），但缺乏持久记忆的支撑，在 airline 上甚至低于基线
4. **Mem0** 改善了平均分，但不如完整系统——通用记忆层能返回相关记录，但不显式建模记忆何时应该介入

### 开源记忆策略训练

在 SETA 上训练 Qwen3.5-27B 作为记忆智能体（行动智能体为冻结的 Qwen3.5-122B-A10B）：

| 设置 | SETA 验证奖励 | Terminal-Bench Pass@1 |
|------|-------------|---------------------|
| 无记忆 | 0.709 | 37.6% |
| + 未训练的 27B 记忆 | 0.693 ↓ | — |
| + SFT 记忆 | 0.720 | — |
| + GRPO 记忆 | **0.734** | — |
| + 训练后的 27B 记忆 | — | **41.1% (+3.5 pp)** |

关键发现：**未训练的记忆智能体会损害性能**（0.693 vs 0.709），说明简单的"多一个模型看看"是不够的。SFT 恢复了损失，GRPO 进一步提升了干预校准。在 Terminal-Bench 上实现了 +3.5 pp 的迁移提升。

## 与智能体认知模块的关联

这篇论文对智能体认知架构研究有几层重要启发：

### 1. 记忆 ≠ 存储+检索，记忆 = 干预策略

这是论文最根本的认知贡献。传统记忆系统（MemGPT、MemoryBank、Mem0）将记忆建模为"写入-存储-检索"的管道。本文提出：在长程执行中，记忆的核心问题不是"能不能找到"，而是 **"该不该在这个时刻影响决策"**。

这对智能体认知架构的设计范式有直接影响：记忆模块不应该只是一个被动的知识库，而应该是一个 **具有主动判断力的干预组件**。

### 2. 记忆智能体与行动智能体的分离

将记忆维护与行动选择解耦（two-agent architecture）有几个认知层面的优势：

- **行动智能体保持不变**：不需要修改现有的推理和行动流程
- **记忆智能体有私有状态**：$s_t$ 字段允许记忆智能体维护自己的任务模型，不污染行动智能体的上下文
- **选择性介入**：不是每一步都需要记忆，沉默本身是一种有意义的决策

这种设计类似于认知科学中的"元认知监控"——一个独立的监控过程评估当前状态，决定是否需要干预主认知过程。

### 3. 行为状态衰减是长程智能体的核心瓶颈

论文命名并形式化了一个重要的失败模式。在我们之前阅读的论文中（如 2026-07-05 的 AutoMem 元记忆框架、2026-07-06 的有界记忆合约），记忆管理一直是智能体架构的核心挑战。本文的"行为状态衰减"概念提供了一个更精确的诊断框架：问题不在于信息是否可得，而在于信息是否仍在 **控制行为**。

### 4. 开源记忆策略的可行性

SFT+GRPO 训练开源记忆策略的初步成功表明，这种干预能力可以被蒸馏到较小的模型中。这对构建可部署的长程智能体系统有实际意义——不需要在每一步都调用前沿模型来管理记忆。

## 总结与启发

### 亮点

1. **问题定义精准**：行为状态衰减的概念比"长上下文不好用"更有诊断力，精确区分了"信息可得"和"信息控制行为"两个层次
2. **架构设计优雅**：两阶段工作流（记忆管理 + 干预选择）既结构化又灵活，工具调用接口使记忆操作显式可审计
3. **消融实验扎实**：每个变体都精确测试了一个假设（被动暴露 vs. 始终注入 vs. 无库指导 vs. 通用检索），结果清晰地支持了完整设计
4. **即插即用**：不需要修改行动智能体，只需要在调用时注入可选的提醒上下文
5. **开源策略探索**：证明了记忆干预能力可以从前沿模型蒸馏到开源模型

### 不足

1. **额外推理成本**：每 N 步调用一次记忆智能体（即使是 Opus 4.6），在长程任务中累积的 API 成本不可忽视
2. **固定触发间隔**：当前实现使用固定间隔触发记忆智能体，论文承认更智能的触发策略（如仅在工具错误、重复命令后触发）可能更高效
3. **校准失败的案例**：论文坦诚地指出，记忆智能体有时会以过高置信度提出推测性推断、重复行动智能体已知的信息、或提出合理但不必要的担忧导致额外验证
4. **仅在两个基准上验证**：Terminal-Bench 和 τ²-Bench 都是相对标准的工具使用场景，在更开放的任务（如创意写作、长期规划）上的效果未知

### 启发

这篇论文为智能体记忆研究指出了一个重要的范式转变：**从"如何更好地存储和检索"转向"如何更好地决定何时介入"**。在构建长程智能体系统时，记忆模块的设计不应该仅仅是知识管理，而应该包含一个元认知层——监控执行状态，评估信息的行为相关性，在沉默和介入之间做出校准良好的选择。

对于我们在智能体认知架构方面的持续关注，这篇论文补充了一个关键视角：记忆不仅是认知模块之间的粘合剂，它本身就是一个需要被优化的决策过程。
