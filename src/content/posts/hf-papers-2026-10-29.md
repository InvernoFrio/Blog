## 研究背景与动机

MoE 模型靠路由把每个 token 送到少数专家来扩展容量，但在小批量的交互式解码场景里，延迟瓶颈并不在算力，而在**把路由专家权重从 GPU DRAM 搬进片上 SRAM** 的访存开销。一个自然的思路是：既然每个 token 只用到专家 gated MLP 中少数中间通道（channel），那就只读这些通道的权重，跳过其余部分。

这类"通道选择器"由两部分组成：**通道打分**（估计每个通道对输出的贡献）和 **keep rule**（决定保留哪些通道）。目前主流做法是在离线校准数据上标定一个阈值：分数超过阈值的通道保留，目标是在校准数据上读到指定预算（如 18% 的专家读取量）。这种校准阈值路线被 Prox、TEAL 等多个工作采用，且此前研究结论互相矛盾——Prox 与 Sparsing Law 认为阈值版更好，La RoSA 等认为 top-k 更好。

本文一针见血地指出：**校准阈值想提供的两样东西，它一样也给不了**：

1. **它不固定读取量**。阈值是固定的，但每个 token 通过阈值的通道数随输入变化。作者在全部 72 组基准测试中发现阈值版的实际读取量都低于标定预算——Prox 标定 18% 预算，实际平均只读 12.9%。甚至用模型自己的推理语料重新校准也修不好这个问题：在 Qwen3-Thinking 上，通过阈值的通道数更多跟随"已写出的答案长度"，而不是"当前 token 真正需要多少"。
2. **它不带来一致的精度增益**。作者把同一个打分器分别配阈值和配 top-k（后者固定每 token 保留 k 个最高分通道，不需要任何校准数据），在阈值标定的预算下对比：43 组配对比较中 top-k 版 40 组持平或更好（30 组统计上打平、10 组领先、3 组落后且最多差 2.8 分），其中**生成类任务 23 组全部 top-k 占优**。更糟的是，在 Gemma 4 上重度稀疏时，校准阈值会触发**重复循环崩溃**（repetition-loop collapse），模型在长推理中陷入复读机式死循环，而同分数的 top-k 版完全正常。

也就是说，围绕校准数据的整套流程（选数据、跑校准、调预算）不仅多余，还引入了对校准数据选择的敏感性和稳定性风险。这直接挑战了稀疏解码领域一个相当普遍的工程默认假设。

## 核心方法与创新点

既然 keep rule 该用 top-k，那性能就取决于打分器排得好不好、被跳过的通道怎么补偿。作者提出一个**完全由模型自身权重构建、零校准**的读取器（reader），三步走：

### 1. 旋转三值 sketch 做通道初筛

把每个专家 gate/up 投影的行做旋转（Hadamard 类变换）后三值化，得到约 **7% BF16 checkpoint 大小**的压缩 sketch，常驻 GPU。解码时对一个 token 的全部候选通道（Qwen3-Thinking 每层 8 专家 × 768 通道 = 6144 个）直接用隐藏状态打分，不需要任何校准数据。

### 2. 精确 top-k + 输出能量校准的打分

在 sketch 粗筛的基础上，用输出能量（output-scaled）修正分数，然后**精确计算每 token 每层的 top-k**。确定保留哪些通道后，再从原生 BF16 权重读这些通道——sketch 只负责"挑"，不负责"算"。

### 3. 低秩恢复被跳过的通道

被跳过的通道并非直接丢弃，而是用一个**纯权重的低秩映射**（只依赖 down 投影的低秩分解，约 0.5% 额外参数）估计它们的合计输出，把粗暴截断变成有损可控的近似。

整条流水线没有任何一步用到校准数据或训练辅助网络。工程实现上，作者写了 Triton 算子把"筛—选—算—恢复—记账"融合进 vLLM 的 decode 路径（prefill 仍走原生 vLLM），并且**按 32 字节硬件扇区记账**每个被触碰的权重字节（GPU 实际按扇区取数，碎片化读取会被"放大"收费），再用 GPU profiler 核对：Qwen3-Thinking batch=1 冷缓存 DRAM 读取实测 18.3% vs 记账 17.8%，验证了成本模型的真实性。

## 实验结果与分析

### 精度：免校准 top-k 全面追平或超过校准阈值

| 对比项 | 校准阈值版 | top-k 免校准版 | 结论 |
|---|---|---|---|
| 43 组配对比较（13%/18% 预算） | 领先 3 组（最多 +2.8 分） | 持平 30 组、领先 10 组 | top-k 40/43 占优 |
| 生成类任务（23 组） | **0 组**占优 | **23 组**全部持平或更优 | 阈值在生成上全面失效 |
| 实际读取量（Prox，标定 18%） | 平均仅 12.9% | 精确等于设定 k | 阈值预算不可控 |
| Gemma 4 长推理稳定性 | 触发重复循环崩溃 | 无崩溃 | 阈值有稳定性风险 |

### 本文读取器：精度与速度双赢

| 指标 | 本文 reader（17.8% 读取） | 对比基准 |
|---|---|---|
| 三模型平均精度保持 | **98.1%** | 12.8%/17.8% 预算下均为**测试过的选择器中最准** |
| 最差模型-任务对精度保持 | **95.0%** | 同样最优（最坏情况保障） |
| OLMoE 对齐全模型 | 优于 9 个先前选择器 | 在各自测试预算下比较 |
| MoE block 加速（batch=1） | Qwen3-Thinking **1.90×**、Gemma-4 **1.71×**、Qwen3.5 **1.60×** | vs 调优后的 vLLM |
| MoE block 加速（batch=4） | 2.39× / 2.34× / 2.51× | 最高 **2.69×**（更大 batch） |
| 整模型解码加速 | batch=1：1.15–1.36×；batch=8–16：**1.75×/1.74×/1.88×** | 8k–32k 上下文下 1.08–1.54× |
| 吞吐收益 | 100 token/s/user 下单 GPU 服务 token 数 **3.3–4.3×** | 整模型对比 |

值得注意的诚实披露：batch=1 时 MoE block 虽然省了 82% 的读取量，但只快 1.90×而非理想中的 ~5×——因为 block 外还有 attention 等不变开销，且读取并非完全串行。这说明**稀疏化的端到端收益要按 Amdahl 定律打折**，论文没有回避这一点。

## 与 AI 基础设施的关联

这篇论文对 LLM 推理服务和 AI Infra 系统设计有几层直接启发：

1. **把"离线校准"从关键路径上拿掉**。校准阈值需要为每个模型、每个量化版本、每种负载分布准备校准集并跑标定流程，这正是推理平台 MLOps 的隐性成本和脆弱点。免校准的 top-k 意味着**部署即用、预算精确可控**——对做 serving 的人来说，可预期的读取量比"平均省一点"更有价值：它直接决定 SLA 和容量规划。
2. **成本模型要对齐硬件真实计量**。按 32 字节扇区记账、用 GPU profiler 校验，这套方法论值得所有做 kernel/算子优化的人抄——很多论文的"理论访存节省"在真实 DRAM 上兑现不了，就是因为没算扇区放大效应。
3. **给 KV cache/权重稀疏/量化一条统一思路**：用常驻的极小压缩副本（ternary sketch，7%）做粗筛 + 原精度精确计算 + 低秩恢复近似误差。这个"廉价索引 + 精确回读 + 有损补偿"的三段式结构可以迁移到激活稀疏、KV 逐出策略等场景。
4. **Triton 融合算子 + vLLM 集成路径**是可直接复用的工程范式：prefill 走原生路径、decode 换稀疏算子、router 不动——把改动面控制在最小，这对推理引擎的可维护性和渐进上线都很关键。
5. **稳定性也是推理系统的指标**。校准阈值引发的重复循环崩溃提醒我们：稀疏化/量化带来的退化未必表现为困惑度小幅上升，而可能是**生成行为灾难性故障**，评测必须包含长生成压力测试，而非只看似然类短评测。

## 总结与启发

**亮点**：结论干脆利落（校准数据可以扔掉了），论证扎实（72 组预算实测 + 43 组严格配对对比 + profiler 核对成本），工程完整（开源代码含基线复现、vLLM 补丁、图表还原脚本），而且给出了诚实的加速上限分析。

**不足**（作者自述 + 我的看法）：kernel 只在一种 GPU（RTX PRO 6000 Blackwell）、一个预算下调优；整 batch 一起选通道（让收益延续到更大 batch）留作 future work；sketch + 恢复映射引入约 7.5% 的额外显存/权重开销，在量化 checkpoint 上占比更高；只测到 35B 规模，更大 MoE（如百 B 级、专家数更多的模型）上 sketch 常驻成本和打分开销如何还未知。

**启发**：对研究者来说，"X 需要校准数据"这类默认设定值得定期被怀疑——本文证明校准不仅无益还有害，这类"减法式"发现和加法式创新同等重要。对系统工程师来说，top-k 的预算确定性 + 免校准的运维简单性，可能比阈值方案平均 0.x 分的（本来就不稳定的）精度优势重要得多。后续值得跟进的方向：batch 级通道选择的融合 kernel、sketch 方案在激活稀疏与 KV cache 管理上的移植，以及免校准思想向量化/稀疏训练阶段的扩展。
