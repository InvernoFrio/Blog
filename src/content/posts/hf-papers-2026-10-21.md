## 一、论文基本信息

- **标题**：MemT-1.0: Towards Memory-Native Evolution
- **链接**：[arXiv:2610.26825](https://arxiv.org/abs/2610.26825)（2026-10-19 提交，cs.CL / cs.LG，66 页）
- **作者**：Zhiyu Li、Zeyu Zhang、Linyun Liu 等七十余人（通讯/团队负责人方向含 Zhi-Qin John Xu、Junchi Yan、Feiyu Xiong 等）
- **机构**：MemTensor 团队（MemOS 记忆操作系统团队），前作为记忆基础模型 Metis
- **代码**：[github.com/MemTensor/MemT-1.0](https://github.com/MemTensor/MemT-1.0)
- **模型**：[HuggingFace 模型合集](https://huggingface.co/collections/MemTensor/memt-1)（MemT-1.0-Nano / MemT-1.0-Flash）

## 二、研究背景与动机

基础模型的能力正在不断从外部系统"内化"进模型本身：推理从思维链提示内化为可训练的推理模式，多模态从外挂编码器内化为原生能力。**记忆**是下一个候选：智能体需要在长期交互中积累信息与经验、持续适应，但今天的主流方案都把记忆放在模型"外面"：

- **全文上下文（Full Context）**：把历史全部塞进 prompt，KV cache 与 prefill 成本随历史线性增长，上下文窗口有硬上限；
- **RAG / 记忆系统**（MemOS、Mem0、Graphiti 等）：把历史存成文本块或图，查询时检索，但检索召回不稳定，且存储随交互累积；
- **参数化记忆**（Temp-LoRA、ICAE、MemoryLLM 等）：把历史写进参数或压缩表示，但往往只挑"重要 token"做选择性存储，信息保真度和稳定性都不足。

作者的核心判断是：**"该记什么"不应靠启发式选择，而应成为模型计算的内在部分**——即"记忆原生演化"（memory-native evolution）。他们在前作 Metis（记忆基础模型的开山之作）基础上推出 MemT-1.0，用更稳定的记忆更新机制、可扩容的记忆结构、完整训练管线与推理基础设施，把记忆做成模型的一等公民能力。

## 三、核心方法与创新点

### 3.1 架构总览：动态局部记忆 + 可训练超记忆

MemT-1.0 在多步交互场景下建模：第 t 步输入 X_t 生成 Y_t，同时状态化的"模型参数"（含记忆状态）被更新并传入下一步。每个被选中的 Transformer block 附加一个 **native memory block**，与原始注意力**并行**计算：

$$A^{(l)} = A^{(l)}_{\text{ori}} + A^{(l)}_{\text{mem}}$$

其中记忆注意力输出 MemoryAttention 只依赖当前步的隐藏状态和**记忆状态 M_t**（形状为 H_kv × d_k × d_v 的多通道矩阵，新轨迹开始时清零）。记忆模块参数 φ（Q/K/V 投影、擦除/写入/遗忘门等）在训练时优化、推理时固定；在线演化的是动态记忆状态本身。这构成"局部记忆存在线信息、超记忆提供记忆能力"的双层结构，沿袭 Metis 但移除了 query-key 归一化、扩展为多通道。

### 3.2 稳定的 token 级记忆更新：GDN-2 + 对称化修正

与 Metis 用 token 选择来决定"记什么"不同，MemT-1.0 采用基于 **Gated DeltaNet-2（GDN-2）** 的 token 级增量更新，每一轮交互内逐 token 更新记忆状态。核心更新式（省略层/步/通道下标）：

$$\tilde{M}_i = [I - U_i^\top U_i] \cdot D_i \tilde{M}_{i-1} + U_i^\top(\omega_i \odot V_i), \quad U_i = \sqrt{\beta_i} \odot K_i, \quad D_i = \text{Diag}[\exp(\lambda_i)]$$

- **K、V**：预注意力隐藏状态经 L2 归一化投影得到记忆 key 与 value；
- **β（擦除门）、ω（写入门）**：sigmoid 门控，决定旧记忆被覆盖多少、新信息写入多少；
- **λ（遗忘门）**：由 -exp(s) ⊙ Softplus(...) 参数化，保证衰减率恒为负，实现记忆衰减；
- **稳定机制**：把 GDN-2 原始更新中会漂移的擦除项替换为对称化的 $[I - U^\top U]$ 形式，防止记忆状态在长序列更新中发散（附录 C 给出对称化修正的完整推导）。

记忆**利用**过程则简单得多：查询 Q 与记忆状态做线性读出 $R = QM / \sqrt{d_k}$，经 RMSNorm 后与输出门 G（SoftCapSiLU 激活，软上限 τ=2）相乘，逐通道拼接后与原始注意力输出相加。**读出是固定大小的**——不随历史长度增长。

### 3.3 Mixture-of-Storage（MoS）：把记忆容量做成可扩展维度

类比 MoE，MoS 把每个记忆块扩展为 E 个**并行记忆专家**，每个专家有独立的动态记忆状态与超记忆参数。与稀疏 MoE 不同，MoS 采用**稠密路由**：所有专家都参与计算，路由概率决定信息如何读写不同专家。读和写用**两个独立路由器**，但共享同一组可训练的专家地址矩阵 C，保证"写进哪个槽位"与"从哪个槽位读"语义对齐——写入时路由概率直接调制擦除门、写入门，读出时按路由概率加权融合各专家的读出。消融显示 4 专家配置在后训练后期比 2 专家平均分高 2.0–2.7 分。

### 3.4 训练管线：34B token、off-policy 蒸馏与"骨干准备"

- **骨干准备（Backbone Preparation）**：对 DeepSeek-V4-Flash 先做一轮能力诊断式后训练（能力画像 → 干预归因 → 按失败类型配数据），126.5K 轨迹 / 2.4B token，六项监控基准平均提升 6.3 分。作者对失败做了很有意思的分析：骨干**从不**解出的任务，准备后也只有 1.6–4.0% 准确率——后训练提升的是**可靠性**，而**新信息**必须由原生记忆供给。这个分工论证正是"记忆原生"的立论基础。
- **数据**：34B token，其中 20B CPT（长文本语言建模）+ 14B 后训练（记忆原生语言建模、存取监督、记忆任务三类，统一为 context-query-answer 格式）。
- **目标函数**：CPT 用 CE；后训练用 **off-policy 知识蒸馏**——教师是持有完整文本历史的冻结骨干，学生只看到当前输入 + 记忆状态 M_t，最小化截断 Top-64 教师分布的前向 KL（外加 CE 项）。这等于让"看得到全文的自己"教"只带记忆的自己"：**记忆的状态表示被训练成对全上下文行为的等价压缩**。

### 3.5 工程：分块 WY 更新 + 快照读 + 完整步窗口

记忆更新是逐 token 的有序 rank-1 操作，朴素实现极慢且吃显存。作者用 chunked WY 把小更新聚合成三角求解，并把"写"与"读"解耦：同一步内所有 query 读同一个入向状态快照 M_t，写的过程照常分块推进。MoS 的专家投影按"完整步窗口"分组执行，窗口边界传递可微 FP32 状态。32K token pack、单卡实测：2 步窗口把峰值显存从 47.83 GiB 降到 9.49 GiB（-80%），前向+反向时间只增 1.6%。

## 四、实验结果与分析

### 4.1 记忆能力：11 个基准，参数化记忆第一

评测协议：先把完整历史按时间顺序写入记忆（推理时**不给任何历史文本**），再回答问题。按轨迹长度分四组：

| 方法（参数化记忆组） | <16K | 16–32K | 32–64K | >64K | **AVG** |
|---|---|---|---|---|---|
| **MemT-1.0-Flash** | 61.6* | 97.5* | 33.5 | 17.4* | **50.60** |
| **MemT-1.0-Nano** | 57.4 | 95.7 | 38.7* | 15.5 | **46.97** |
| Temp-LoRA | 44.3 | 98.0 | 35.7 | 12.0 | 38.08 |
| Doc-to-LoRA | 57.2 | 70.2 | 16.5 | 3.5 | 30.93 |
| δ-mem | 37.5 | 90.8 | 20.1 | 7.1 | 31.20 |
| MemoryLLM | 22.7 | 37.4 | 46.8* | 6.3 | 25.26 |

*（各列缩写：MB/IM、PM/PSB/LCM、PMS/MMR/MO、LME/MAB/BEAM；粗体略，Flash/Nano 分列第一第二）*

Flash 与 Nano 分别以 50.6 / 47.0 分位列参数化记忆方法**前两名**，领先最强基线 12.5 / 8.9 分，且在 >64K 的三个长程基准（LongMemEval-S、MemoryAgentBench、BEAM-1M）上领先该组。但作者很坦诚：**最强的文本记忆系统（MemOS 68.55）仍明显领先**——显式历史证据 vs 压缩状态，保真度差距是下一阶段的主攻方向。

### 4.2 通用能力：加记忆不降智

在"噪声设置"（先往记忆里灌无关信息）下对比骨干：

| 模型 | MMLU-Pro | GPQA | IFEval | LongBench v2 | BCB-Hard | LCB-v6 | AVG |
|---|---|---|---|---|---|---|---|
| MemT-1.0-Flash（相对 DS-V4-Flash） | -1.8 | -0.6 | +0.9 | +0.2 | +2.0 | -0.7 | **0.0** |
| MemT-1.0-Nano（相对 Qwen3.6-35B-A3B） | -1.6 | -1.5 | +3.3 | -2.0 | +2.0 | -5.8 | **-0.9** |

Flash 平均零损失；Nano 掉 0.9 分且退化集中在 LiveCodeBench v6。干扰记忆下的抗噪能力需要按任务逐项评估。

### 4.3 消融：更新粒度 > 更新规则

| 变体 | AVG | Δ |
|---|---|---|
| MemT-1.0-Nano（完整） | 46.97 | – |
| w/ GDN-2（去稳定机制） | 46.43 | -0.54 |
| w/ GDN（换更新规则） | 46.72 | -0.25 |
| w/ BE（双向编码） | 45.43 | -1.54 |
| **w/ TL（turn 级更新）** | **40.98** | **-5.99** |
| w/o CPT（只后训练） | 44.85 | -2.12 |
| **w/o PT（只 CPT）** | **36.28** | **-10.69** |

两个关键结论：**token 级增量更新是灵魂**（换成 turn 级聚合掉 6 分），而具体的更新规则形式影响不大；**后训练贡献 10.7 分**，CPT 作用是给后训练提供好的初始化。

### 4.4 效率与存储：固定状态的复利

- **端到端延迟**（含历史准备 + 生成 128 token）：32K 历史处与全文上下文打平，64K 提速 1.20×、128K **1.86×**、256K **3.99×**；
- **查询 TTFT**：MemT-1.0-Nano 稳定在 104–112 ms，全文上下文 128K 时涨到 257 ms（2.44×）、256K 时 445 ms（4.19×）——因为读出状态尺寸固定；
- **存储**：128K 历史下每轨迹常驻状态比全文 KV cache 小 **66 倍**（Flash 的 FP32 状态也只有 1280 MiB），且不随交互增长；低秩 SVD 实验显示记忆状态可压缩性很好，PersonaMem 在中等秩就饱和。
- 缩放行为：后训练数据两轮持续涨分（36.65 → 46.80），MoS 专家数 2→4 在后期带来 2–2.7 分提升——记忆能力存在自己的 scaling 维度。

### 4.5 智能体应用：经验写进记忆，不占上下文

从 41,057 条成功 SWE 轨迹中提炼 **1,040 条结构化程序性经验**（触发条件、步骤、前置约束、验证方法），用反事实执行构造 42,403 条训练样本（原轨迹失败、注入经验后成功的延续），蒸馏训练让模型把经验**写入原生记忆**后指导行动。SWE-bench 结果（每任务 3 次独立运行）：

| 基准/时机 | 方法 | pass³ | 平均成功率 | pass@3 |
|---|---|---|---|---|
| Verified / 执行前 | 无经验骨干 | 54.00 | 66.07 | 77.60 |
| Verified / 执行前 | 文本经验 | 61.60 | 68.87 | 76.40 |
| Verified / 执行前 | **原生记忆** | **61.60** | **69.33** | 77.40 |
| Verified / harness 触发 | **原生记忆** | **62.80** | **69.73** | **77.80** |
| Multilingual / 执行前 | **原生记忆** | 53.67 | 62.89 | 72.00 |
| Multilingual / harness 触发 | **原生记忆** | **55.33** | **63.56** | 73.00 |

pass³（三次全对）提升最显著：Verified +7.6~8.8pp、Multilingual +8.3~10pp——**经验内化主要提升的是执行的一致性与可靠性**，且效果与把经验明文放进上下文相当甚至更好，harness 中途触发的动态注入同样有效。

## 五、与智能体认知模块的关联

- **记忆**：这是目前"记忆内化"路线最完整的一份工程答卷。它给出一个明确的架构答案：记忆不必是外挂数据库，可以是随交互演化的固定大小状态；但文本记忆系统仍然领先的事实也提示，**记忆保真度（fidelity）与选择性保留**才是当前瓶颈，与本期另一篇 TokenWorth（"记住是有代价的"）的问题意识正好互补——一个解决"存哪里/怎么存"，一个解决"该不该存"。
- **认知架构**：动态局部记忆（在线状态）+ 超记忆（可训练能力）的分层，非常像认知科学里工作记忆/长期记忆 + 记忆管理策略的分工；读写分离的两个路由器共享专家地址，本质上是一个可微的"记忆寻址协议"。
- **长程任务与经验学习**：把 SWE 经验写进记忆而非 prompt，直接缓解长程任务的上下文膨胀问题；harness 触发式注入（检测到失败信号才写记忆）是一种"元认知监控驱动的记忆写入"，值得在长程智能体里推广。
- **世界模型/知识蒸馏**：off-policy 蒸馏里"全上下文教师 → 记忆状态学生"的框架可以泛化：任何"贵但准"的信息获取通道（检索、工具、规划器）都可以当教师，把结果蒸馏进廉价的固定状态读出。

## 六、总结与启发

**亮点**：(1) 把记忆从"工程外挂"升级为"模型计算的原生维度"，架构、训练目标、推理服务三层自洽；(2) 消融扎实——明确指出 token 级更新粒度而非更新规则形式是性能来源，后训练而非 CPT 是记忆能力的关键；(3) 效率账算得清楚：固定状态带来 TTFT 不随历史增长、存储可控，这对持久智能体部署是实打实的卖点；(4) 智能体实验用 pass³ 指标，抓住了"经验复用提升一致性"这个容易被平均成功率掩盖的收益。

**不足**：(1) 与显式文本记忆系统仍有约 18 分的平均差距，长程细节保真度未解决；(2) 经验库依赖外部构造，"自主持续学习"仍是 open problem；(3) 写记忆本身有计算开销，省了上下文不等于省了总成本；(4) Nano 在干扰记忆下 LiveCodeBench 掉 5.8 分，抗噪性未完全解决。

**启发**：记忆原生演化的闭环还差一环——本文的"骨干准备"（经验进权重）与"原生记忆"（经验进状态）是两条平行路径，作者自己也把"二者的闭环"列为未来工作。谁能做出**写入时机自适应、保留价值可学习、状态保真可审计**的记忆机制，谁就更接近真正的长程自我进化智能体。对做智能体记忆系统的同学，这篇最值得抄的三个设计是：对称化稳定更新、读写分离共享地址的路由、以及"全上下文教师蒸馏记忆学生"的训练范式。
