## 研究背景与动机

GUI智能体需要在两个时间尺度上保持记忆：**情景记忆**（episodic memory）从已完成任务中提取可复用经验，**工作记忆**（working memory）维持当前交互中的约束和进度。然而，回放完整轨迹代价高昂——反复截图和动作序列会迅速膨胀策略上下文。

**潜在记忆**（latent memory）提供了一种紧凑方案：将多模态轨迹压缩为少量连续token。但现有方法存在三个根本问题：

1. **压缩丢失问题**：将每条轨迹映射到固定的记忆块，重要细节可能在压缩过程中丢失
2. **固定读出问题**：同一个记忆块需要服务不同的决策阶段，无法针对性地暴露相关信息
3. **信任缺失问题**：检索到的不相关轨迹可能误导智能体

这些问题在实际GUI任务中尤为突出。以购物场景为例：搜索商品A和B时，价格信息在搜索阶段是关键证据，但在"加入购物车"阶段，只需要记住较便宜的那个。固定的记忆表示无法适应这种决策阶段的变化。

## 核心方法与创新点

FocusMem的核心思想是**将潜在记忆的职责分解**为三个独立模块：

### 1. 角色感知的内容基底（Role-Aware Content Basis）

**问题：** 现有方法对情景记忆和工作记忆使用相同的查询向量，无法控制角色特定信息的保留。

**方案：** 为每种记忆角色引入专属的基础查询：

$$Z_i^{\text{fixed}} = C_\Phi(s_i; Q_{r_i}^0) + e_{r_i}, \quad r_i \in \{\text{epi}, \text{work}\}$$

其中 $Q_{r_i}^0$ 控制角色依赖的信息提取，$e_{r_i}$ 标识来源。

**训练信号：** 结合两种监督——
- **语义KL损失**：$L_{\text{sem}} = \sum_{i,j} D_{\text{KL}}[p_{\text{raw},ij}^{\text{sem}} \| p_{\text{lat},ij}^{\text{sem}}]$，转移广泛可言语化的轨迹内容
- **功能性伪目标**：$L_{\text{func}} = -\sum_i \log \Pi_\theta(\hat{v}_{r_i}^i | Z_i^{\text{fixed}}, \rho_{r_i}^{\text{func}})$，强调控制相关信息（情景记忆侧重可复用决策，工作记忆侧重状态变化）

**直觉：** 语义监督确保"记住了什么"，功能性监督确保"记住了对决策有用的东西"。两者互补。

### 2. 状态条件读出（State-Conditioned Readout）

**问题：** 即使关键细节在压缩后保留下来，固定的表示也可能无法在当前决策状态下暴露它。

**方案：** 引入轻量级状态-项目适配器，生成基于当前状态的残差查询：

$$\Delta Q_{t,i} = A_\eta(u_t, \text{Pool}(H_i), e_{r_i})$$
$$Q_{t,i} = Q_{r_i}^0 + \Delta Q_{t,i}$$
$$Z_{t,i}^{\text{dynamic}} = C_\Phi(s_i; Q_{t,i}) + e_{r_i}$$

由于残差同时依赖当前状态和编码的项目，**同一条轨迹可以在不同状态下产生不同的潜在表示**。

**关键设计：** $A_\eta$ 的输出初始化为零，优化从角色感知的固定读出开始。这确保了训练的稳定性。

### 3. 证据信任门（Evidence Trust Gate）

**问题：** 状态条件读出决定了暴露记忆的哪部分，但暴露的证据可能仍然具有误导性、过时或与当前任务不兼容。

**方案：** 引入块级信任模块 $T_\xi$，对每个决策导向的记忆块评分：

$$g_{t,i} = T_\xi(u_t, \text{Pool}(Z_{t,i}^{\text{dynamic}}))$$

推理时，仅保留 $\sigma(g_{t,i}) > \gamma$ 的块。

**训练策略：** 使用HardConcrete掩码，并注入高置信度的不相关情景项目 $\mathcal{N}_t$：

$$L_{\text{gate}} = -\sum_{i \in \mathcal{N}_t} \log(1 - \sigma(g_{t,i}))$$

普通检索项目不接收显式正标签——它们的效用信号来自动作目标。梯度在 $Z_{t,i}^{\text{dynamic}}$ 处停止，确保门控监督学习块使用而不直接重塑其内容。

### 两阶段训练

- **Stage A：** 建立角色感知的内容基底，禁用查询残差和门控
- **Stage B：** 从Stage A初始化，启用状态条件读出和信任门，更新完整记忆路径

## 实验结果与分析

### 主要结果

在5个GUI智能体基准上（MMInA-Wikipedia、MMInA-Shopping、DeepShop、WebVoyager、Online-Mind2Web），FocusMem一致超越所有基线：

| 方法 | 记忆类型 | 总体SR |
|------|---------|--------|
| No Memory | 无 | 28.5% |
| ReasoningBank | 文本记忆 | 31.7% |
| Retrieved Full Trajectory | 原始多模态 | 33.2% |
| CoMEM-style | 情景潜在 | 35.3% |
| Mem-W-style | 双源固定潜在 | 42.5% |
| **FocusMem** | **分解潜在** | **48.3%** |

FocusMem比无记忆基线提升近20个百分点，比最强的Mem-W-style提升5.8个百分点。

### 组件消融

在MMInA-Shopping上的累积消融：

| 设置 | SR | 步骤↓ |
|------|-----|-------|
| No Memory | 41.0% | 9.4 |
| + Fixed | 45.5% | 9.0 |
| + Content | 50.5% | 9.0 |
| + Readout | 54.5% | 8.5 |
| + Gate | 59.0% | 8.4 |

三个组件各自贡献4-5个百分点的增益，且效果可叠加。

### 内容可恢复性探针

语义监督和功能性监督保留了互补信息：
- 仅语义监督：语义恢复68.9，对齐恢复58.6
- 仅功能监督：语义恢复60.7，对齐恢复69.4
- 两者结合：语义恢复74.6，对齐恢复74.1

### 证据扩展实验

当轨迹上下文从Oracle Core扩展到完整轨迹时：
- Fixed读出：准确率下降22-25点
- Dynamic读出：准确率仅下降6-12点

这证明状态条件读出在信息需要与额外轨迹阶段竞争时最为有效。

### 信任门污染实验

当注入不相关情景轨迹时：
- 无门控：性能急剧下降
- FocusMem：在最大污染下仍保持9-11点优势
- 门控通过率从86%降至35%，表明门控有效地抑制了受污染的记忆块

## 与智能体认知模块的关联

FocusMem对智能体认知架构研究有重要启发：

### 1. 记忆不是单一模块

传统智能体架构常将记忆视为一个整体。FocusMem证明**记忆的形成、读出和信任是三个独立的职责**，需要分别优化。这与认知科学中记忆的多阶段处理模型一致。

### 2. 状态条件处理是关键

同一份经验在不同决策阶段需要暴露不同信息。这启发我们：智能体的记忆检索不应只是"找到相关文档"，而应是"在当前状态下，从相关文档中提取什么"。

### 3. 信任机制不可忽视

检索到的信息不等于有用的信息。FocusMem的信任门机制为智能体提供了**主动拒绝过时或不兼容记忆的能力**，这对于长期运行的智能体尤为重要。

### 4. 冻结策略的训练范式

FocusMem在训练记忆模块时保持GUI策略冻结。这种"记忆与策略解耦"的范式可能适用于更广泛的智能体架构——我们可以独立优化智能体的"认知基础设施"而不影响其核心能力。

## 总结与启发

**亮点：**
- 问题定义清晰：将潜在记忆的失败模式分解为三个独立且可操作的职责
- 方法设计优雅：三个模块各司其职，且通过两阶段训练保证稳定性
- 实验全面：包括消融、可恢复性探针、证据扩展和信任污染等多角度分析
- 实用性强：仅优化记忆路径，策略保持冻结，易于集成

**不足：**
- 仅在Qwen3-VL-8B上验证，跨模型泛化未探索
- 信任门的污染测试使用的是"明显不相关"的轨迹，更微妙的不匹配情况未覆盖
- 评估依赖Gemini-3.1-Pro作为裁判，可能存在评判偏差

**启发：** 这篇论文的核心洞察——**有效的潜在记忆不仅取决于压缩什么，还取决于保留什么、暴露什么、以及允许什么**——为智能体记忆架构设计提供了清晰的指导原则。在构建长期运行的智能体时，我们不应满足于"记住更多"，而应追求"在正确的时间，以正确的方式，暴露正确的信息"。
