## 研究背景与动机

### 智能体技能的"遗忘"问题

在当今的 LLM 智能体生态中，**技能（Skill）** 已成为扩展智能体能力的核心机制。一个技能本质上是一个可加载的资源包，包含任务特定的流程、脚本、参考资料和输出约定——类似 Claude Code、Codex、Hermes 等系统中的专业化单元。

然而，技能开发从来不是一次性事件。环境会变、API 会更新、边缘情况会涌现，技能需要持续的调试和适配。**核心问题是：现有方法在改进技能时只保留最终产物，丢弃了决策历史。**

这导致了一个严重的后果：

```
后续智能体继承了最新版本的技能，
但不知道：为什么做了这次修改？哪些替代方案被否决了？
评估证据是什么？为什么接受了这个结果？
```

如图1所示，当环境变化时，后续优化可能会重复之前已经成功的修复（但该修复已不适用于当前的失败模式），从而使未来的优化更加困难。

### 两条现有路线的局限

| 方法类型 | 代表 | 问题 |
|---------|------|------|
| 合成式构建 | Skill-Creator | 一次性生成，无迭代反馈 |
| 反思式优化 | Hermes-SE (GEPA) | 迭代改进但只保留标量信号 |

两条路线都把输出视为"更好的制品"，丢失了持续维护所需的决策上下文。

## 核心方法与创新点

### 1. 双仓库架构

SkillHone 维护两个关联的仓库：

$$\mathcal{M} = (\mathcal{T}_{\text{opt}}, \mathcal{T}_{\text{eval}}, \mathcal{D})$$

其中：
- $\mathcal{T}_{\text{opt}}$：**优化智能体团队** — 维护技能仓库，提出诊断驱动的修订
- $\mathcal{T}_{\text{eval}}$：**评估智能体团队** — 运行候选技能，导出脱敏问题报告
- $\mathcal{D}$：**运行时调度器** — 路由证据和审查请求，记录决策结果

**关键设计：角色隔离**

评估子智能体可以检查探针和踪迹、运行候选技能，但只能返回**脱敏证据**（redacted evidence）给优化侧。优化子智能体使用这些证据和历史决策记录来形成诊断和修订草案，但**无法访问隐藏的探针目标或验证器**。

这种分离防止了实践反馈成为直接的记忆目标——优化侧不能"作弊"地看到答案。

### 2. 持久决策历史

这是 SkillHone 最核心的创新。每个开发步骤被表示为一个**决策记录**：

$$h_t = (q_t, r_t, e_t, o_t)$$

其中：
- $q_t$：**诊断**（diagnosis）— 当前技能在什么方面失败了？
- $r_t$：**候选修订**（candidate revision）— 提议的修改方案
- $e_t$：**脱敏评估证据**（redacted evaluation evidence）— 实践反馈
- $o_t$：**结果**（outcome）— accept / revise / reject / defer

累积的决策历史为 $\mathcal{H}_t = \{h_1, \ldots, h_t\}$。

**决策记录 ≠ 版本差异（diff）**

这是一个重要的概念区分。diff 只展示文件如何变化；决策记录将变化与以下内容关联：
- 它针对的问题（诊断）
- 用于评估它的证据
- 最终的决策及理由

### 3. 算法流程

```
Algorithm 1: SkillHone

输入: 初始技能 S₀, 技能仓库 ℛₛ, 评估仓库 ℛₑ
初始化: ℋ₀ ← ∅

for t = 0, ..., T-1 do
  ① 评估调度: 运行 A(·; Sₜ) 在 ℛₑ 上，导出 Êₜ
  ② 优化调度: 检索 ℋₜ，提出 (qₜ, rₜ)
  ③ 评估调度: 返回 rₜ 的脱敏证据 eₜ
  ④ 决策: oₜ ∈ {accept, revise, reject, defer}
  ⑤ 如果 accept: Sₜ₊₁ ← Apply(Sₜ, rₜ)
  ⑥ 更新历史: ℋₜ₊₁ ← ℋₜ ∪ {(qₜ, rₜ, eₜ, oₜ)}
end for

return Sₜ, ℋₜ
```

### 4. 核心洞察

当新报告 $\tilde{E}_t$ 到来时，优化子智能体检索相关的历史记录 $\mathcal{H}_{<t}$，可以：

- **重访旧诊断**：在新证据下重新审视之前被否决的补丁
- **避免冗余编辑**：识别已失败的修改，不再重复
- **理解修订背景**：知道为什么某个修复在当时是合理的

决策历史充当**演化过程本身的持久记忆**。

## 实验结果与分析

### 基准测试

SkillHone 在两个深度研究基准上评估：

| 基准 | 侧重点 |
|------|--------|
| **GAIA** | 多步信息检索、跨异构源的事实锚定 |
| **WebWalkerQA-EN** | 网页导航与信息抽取 |

### 主要结果

| 方法 | 设置 | GAIA | WebWalkerQA-EN |
|------|------|------|----------------|
| 深度研究智能体 | 商业检索 | 48.8% | 63.2% |
| Existing-Skills | 原始开放网络 | 50.4% | 53.0% |
| Skill-Creator | 原始开放网络 | 44.1% | 38.1% |
| Hermes-SE | 原始开放网络 | 50.4% | 53.0% |
| **SkillHone** | **原始开放网络** | **64.6%** | **66.4%** |

**关键发现：**
- SkillHone 在不使用预集成搜索工具的情况下，**超越商业深度研究智能体 15.8 分**（GAIA）和 **3.2 分**（WebWalkerQA-EN）
- 相比同设置下的 Skill-Creator 提升 **+20.5 / +28.3 分**
- 相比 Hermes-SE 提升 **+14.2 / +13.4 分**

### 跨骨干迁移

将 SkillHone 产出的技能包直接迁移到 Claude Sonnet 4.6（无需额外优化）：

| 方法 | GAIA (Claude Sonnet 4.6) |
|------|-------------------------|
| Skill-Creator | 48.0% |
| Existing-Skills | 56.7% |
| Hermes-SE | 62.2% |
| **SkillHone** | **72.4%** |

这表明增益来自**技能程序本身**，而非对特定模型的过拟合。

### 消融实验

| 配置 | GAIA | WebWalkerQA-EN |
|------|------|----------------|
| SkillHone (完整) | 64.6% | 66.4% |
| 无决策历史 | 51.2% | 55.5% |
| 无角色分离 | 58.2% | 61.1% |

**消融分析：**
- 去掉决策历史 → GAIA 下降 **13.4 分**，WebWalkerQA-EN 下降 **10.9 分**
- 去掉角色分离 → GAIA 下降 **6.4 分**，WebWalkerQA-EN 下降 **5.3 分**

**结论：决策历史的贡献远大于角色分离。**

## 与博弈智能体的关联

### 1. 策略技能的跨博弈演化

在多智能体博弈场景中，策略技能（如谈判话术、欺骗检测、资源配置策略）需要持续适应对手的变化。SkillHone 的持久决策历史思路可以直接应用：

- **记住失败的策略修订**：避免在面对新对手时重复已证明无效的策略调整
- **评估证据的保留**：记录每次策略修订的博弈结果和对手反应，形成可审计的策略演化路径

### 2. 对手建模中的决策历史

博弈智能体需要建模对手行为。SkillHone 的 $h_t = (q_t, r_t, e_t, o_t)$ 框架可以扩展为：

- $q_t$：对手行为模式的诊断（"对手开始更多使用合作策略"）
- $r_t$：己方策略的调整提议
- $e_t$：博弈交互的脱敏反馈
- $o_t$：策略调整的结果

### 3. 多智能体协调中的技能共享

SkillHone 的跨骨干迁移能力表明，一个智能体开发的技能包可以有效迁移到其他智能体。在博弈场景中，这意味着：

- 团队中"资深"智能体的策略经验可以结构化地传递给新成员
- 技能包的可移植性使得策略知识不依赖于特定的模型架构

### 4. 持续博弈中的记忆治理

论文揭示了一个深刻的问题：**制品中心 vs. 决策中心**。在博弈智能体研究中，我们同样面临这个选择——是只保留最终的策略参数，还是保留策略演化的完整决策链？SkillHone 的答案是后者，这对博弈智能体的长期记忆治理有重要启示。

## 总结与启发

### 亮点

1. **问题定义精准**：识别出"制品中心 vs. 决策中心"这一关键差距，这在智能体技能研究中长期被忽视
2. **架构设计优雅**：双仓库 + 角色隔离 + 持久决策历史，三者协同工作
3. **实验充分**：跨基准、跨骨干、消融实验三位一体，验证了每个组件的贡献
4. **实用价值高**：在内部部署场景中平均提升 18.8 分，证明了实际可行性
5. **可迁移性强**：技能包可以跨模型骨干迁移，增益反映的是程序性知识而非过拟合

### 不足

1. **开发成本**：需要 Claude Opus 4.6 作为开发时控制器，成本不菲
2. **历史膨胀**：随时间累积的决策历史可能变得庞大，论文未讨论历史压缩或摘要机制
3. **评估偏见**：评估侧的"脱敏"边界如何设定？过于严格的脱敏可能丢失有用信息
4. **适用范围**：主要在深度研究（信息检索）场景验证，对其他类型的智能体任务（如代码生成、具身控制）的适用性待探索
5. **对抗鲁棒性**：未讨论恶意子智能体注入虚假决策历史的风险

### 核心启发

> **技能不仅仅是代码和指令——它是决策链的结晶。**

SkillHone 告诉我们，智能体的持续演化不能只看"最终产物"，而要保留完整的决策脉络。这对所有需要长期适应的智能体系统（博弈、协作、探索）都有深远意义。
