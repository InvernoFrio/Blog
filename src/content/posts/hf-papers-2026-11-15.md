## 一、论文基本信息

- **标题**：Modality-Aware Expert Pruning for MoE-Based Multimodal Large Language Models
- **链接**：<https://arxiv.org/abs/2611.05927>
- **作者**：Donggeun Kim（Nota Inc.，NetsPresso 团队）
- **发表**：NeurIPS 2026
- **代码**：<https://github.com/nota-github/MAEP>
- **关键词**：MoE、多模态大模型、专家剪枝、免训练压缩、显存优化

## 二、研究背景与动机

混合专家（Mixture-of-Experts, MoE）架构靠稀疏路由换取"总参数大、每 token 计算小"的红利，已经从纯文本 LLM 扩展到多模态大模型（MLLM）。但 MoE 有一个天然的**显存悖论**：每个 token 只激活 128 个专家中的 8 个，可所有专家参数都必须常驻显存。论文指出，在 InternVL3.5-30B-A3B、Qwen3-VL-30B-A3B 这类现代 MoE-MLLM 中，专家参数占模型体积的 **93–94%**（BF16 下约 58GB 模型中有 54GB 是专家权重）。计算是稀疏的，显存却是稠密的——这正是部署端最痛的瓶颈。

专家压缩（合并、剪枝、低秩分解、量化）在纯文本 MoE 上已被广泛研究，但直接搬到多模态场景会失效，原因有二：

1. **模态鸿沟**：文本 token 和视觉 token 走同一个专家池，但和专家的交互方式系统性不同。已有分析显示两种模态在专家层的分布存在稳定差距。把重要性统计在所有 token 上均匀聚合，会抹掉"同一个专家对视觉和语言可能扮演完全不同角色"这一事实。
2. **视觉令牌冗余**：视觉 token 本身高度冗余，其中还混有"注意力水池"（attention sink）这类吸引注意力却不携带语义内容的 token。用全量视觉 token 估计重要性，得到的专家排名随校准数据集漂移，域敏感严重。

更微妙的是，论文的实证发现：按文本 token 与视觉 token 分别用 ΔH 排序，两个排名的 Spearman 相关只有 **−0.11 ~ 0.05**，几乎不相关；删除一个专家引起的 LM head 输出分布偏移，在视觉位置上可达文本位置的 **29 倍**。模态不对称是真实且显著的——这正是 MAEP 的切入点。

## 三、核心方法与创新点

MAEP（Modality-Aware Expert Pruning）是一个完全**免训练**的框架：给定约 1K 校准样本（ShareGPT4V 图文对话），一次前向传播算完所有重要性分数，不反传、不更新权重。

### 3.1 ΔH Output：重分配感知的重要性指标

理想的专家重要性是"删掉它后模型输出分布变了多少"（OBD 原则），但逐专家实测 KL 散度需要 N×L 次完整前向（InternVL3.5 上是 128×48 = 6144 次），完全不可行。MAEP 改用 MoE 层输出扰动做代理：

$$\Delta H^{(l,j)} = \mathbb{E}_{x\sim\mathcal{D}}\left[\frac{1}{|x|}\sum_{h\in x}\left\|H^{(l)}_{\text{MoE}}(h) - H^{(l,-j)}_{\text{MoE}}(h)\right\|_2^2\right]$$

关键在 $H^{(l,-j)}$ 的构造——**路由器重分配**：把专家 j 的 logit 屏蔽、重新选出 top-k 并重归一化，剩余专家按 $w_i^{(-j)} = w_i/(1-w_j+w_{(k+1)})$ 承接被删专家的路由质量。这比"孤立贡献"更合理：它衡量的是删掉 j 之后、其他专家兜底接住之后**残余**的输出变化，ΔH 小意味着该专家与共激活专家功能冗余度高。

两个工程细节让 ΔH 几乎免费：(1) 缓存一次前向的 top-k 权重和专家输出后，所有反事实可以解析地算出来，单次前向全覆盖；(2) 固定 top-k 反事实（被提拔的第 k+1 专家不实际计算输出），与"提拔变体"几乎一致（跨模态平均 ρ > 0.98）。

**理论支撑**（Proposition 1）：把 MoE 层之后的网络视为 Lipschitz 复合，可以证明平均 KL 散度被 $\frac{L_{\Phi_l}^2}{4}\cdot\Delta H^{(l,j)}$ 上界控制。由于 $C_l = L_{\Phi_l}^2/4$ 对同层所有专家是常数，**层内按 ΔH 排序等价于按 KL 上界排序**。实证上 ΔH 与真实 KL 的层内 Spearman 相关在深层达到 0.8（视觉）~ 0.89（文本），浅层稍弱，与理论的深度依赖一致。

### 3.2 低注意力视觉令牌：稳定的剪枝信号

有了模态分解能力，视觉侧用哪些 token 估重要性？论文发现：

| 视觉 token 子集 | 跨数据集排名稳定性（Spearman ρ） |
|---|---|
| 全量视觉 token | ≈ 0.0 |
| 高注意力（top 20%） | ≈ 0.2 |
| （参照）文本 token | ≈ 0.5 |
| **低注意力（bottom 2%）** | **≈ 0.6** |

高注意力 token 跟着当前文本 query 走，跨校准数据集必然漂移；而低注意力视觉 token（文本→视觉注意力权重最低的 bottom q%，q=2%）反映的是非显著的背景内容，专家重要性排名**跨数据集最稳定**，可视为"模型固有视觉处理方式"的探针。

### 3.3 非对称组合与全局剪枝

两个信号用途相反：**文本侧 ΔH 是保留信号**（高→重要，别删），**低注意力视觉侧 ΔH 是剪枝信号**（高→专家把容量浪费在不重要的视觉内容上，该删）。组合得分：

$$s^{(l,j)} = (1-\alpha)\cdot\tilde{z}^{(l,j)}_{\text{text}} - \alpha\cdot\tilde{z}^{(l,j)}_{\text{la}}$$

其中 $\tilde{z}$ 是 log 变换 + 层内 z-score 归一化（原始 ΔH 跨层量级差 10³–10⁴ 倍，重尾分布）。分数最低的专家先剪。

α 不是调参调出来的，而是**闭式自适应**：$\alpha = a/(a+b)$，其中 $a=\bar\rho_{t,v}-\bar\rho_{t,la}$（低注意力信号相对全量视觉对文本的互补度），$b=\bar\rho_{v,la}$（视觉内部冗余度）。三模型算出 0.75/0.33/0.08（实用取 0.8/0.3/0.1），均落在经验稳定区间内。

最后，所有层的专家**全局统一排序**、剪掉分数最低的 r×N_total 个，而不是每层剪固定比例——因为各层专家冗余度差异很大，强制配额会误伤。消融显示全局分配在 MME、ChartQA 上仍优于重调 α 后的均匀配额。

## 四、实验结果与分析

**设置**：三个 MoE-MLLM（InternVL3.5-30B-A3B、Qwen3-VL-30B-A3B、Gemma4-26B-A4B，均为 128 专家 top-8），对比 HC-SMoE（层次聚类合并专家）和 REAP（路由加权激活范数剪枝），11 个基准（8 多模态 + 3 纯文本）。"平均保留率"是各方法相对未剪枝基线的逐基准得分保留百分比的均值。

**主结果（平均保留率 %）**：

| 模型 | 剪枝率 | HC-SMoE | REAP | MAEP |
|---|---|---|---|---|
| InternVL3.5-30B-A3B | 25% | 91.9 | 95.9 | **97.7** |
| InternVL3.5-30B-A3B | 50% | 74.1 | 88.5 | **91.2** |
| Qwen3-VL-30B-A3B | 25% | 96.0 | 94.8 | **96.6** |
| Qwen3-VL-30B-A3B | 50% | 85.5 | 86.6 | **88.3** |
| Gemma4-26B-A4B | 25% | 77.2 | 96.0 | **96.0**（并列） |
| Gemma4-26B-A4B | 50% | 39.3 | 80.9 | **86.7** |

MAEP 在每个"模型×剪枝率"配置上都取得最优或并列最优，且**剪枝率越高优势越大**（25% 时 REAP 只差约 2 分，50% 时差距拉大到 2–6 分）。Gemma4 上最戏剧化：HC-SMoE 的模态无关聚类混淆了模态角色不同的专家，50% 剪枝直接坍缩到 39.3%（MMBench 只剩 9.8 分），而 MAEP 稳在 86.7%。

**部署指标（InternVL3.5，A100 80GB 实测）**：

| 指标 | 数值 |
|---|---|
| 常驻权重显存（0 / 25% / 50% 剪枝） | 57.5 / 44.0 / 30.5 GB（50% 时 **−47%**） |
| B=1 解码吞吐比（50% 剪枝 / 未剪） | 0.96–1.02（持平，top-k 不变故每 token FLOPs 不变） |
| 40GB 显存上限下解码 | 未剪（约 33% 参数卸载 CPU）1.52 tok/s → 剪后全常驻 5.88 tok/s（**3.9×**） |
| 大 batch 解码吞吐比 | B=8: 1.13×；B=16/32: 1.29×；B=64: **1.37×** |
| B=64 每层每步唯一激活专家数 | 约 55（未剪）vs 约 39（剪后） |

**消融要点**（InternVL3.5，50% 剪枝）：去掉模态分解，MMStar 63.3→51.1、ChartQA 76.7→41.2，坍塌式退化；把低注意力换成高注意力（top 2/5/10%）直接 collapse，换成全量视觉信号 ChartQA 掉到 38.8。校准集侧，100 样本就够用（vs 默认 1K 几乎无损）；但**校准域不匹配**是真实风险——ShareGPT4V 缺图表内容导致 Qwen3-VL 的 ChartQA 偏弱，按 7:3 混入 300 条 ChartNet 后 ChartQA 回升 **13.9 分**、MMStar 还涨 4.1 分，无明显代价。

## 五、与 AI 基础设施的关联

这篇论文对 AI Infra 研究有几条直接的启发：

1. **LLM 推理服务与显存调度**：MoE 推理的显存瓶颈在"专家全常驻、激活稀疏"。MAEP 提供了一条免费的显存瘦身路径——50% 专家剪枝把 58GB 权重压到 31GB，单张 40GB A100/消费级卡即可驻留服务。3.9× 的端到端提速恰恰来自**避免 CPU offload**，这印证了 serving 系统设计中"权重常驻优先于一切优化"的经验法则。
2. **大 batch 吞吐的结构效应**：MoE 解码是带宽受限的，每步成本跟踪"唯一激活专家数"，该数随 batch 增长、上界是专家池规模。剪枝把池砍半，直接降低这个天花板（B=64 时 1.37×）。这对高并发 MoE serving 的容量规划和动态批处理策略有直接参考价值；用 fused grouped-GEMM 的引擎会更贴合带宽瓶颈，作者预计效应更大。
3. **与量化的正交叠加**：MAEP 是结构化剪枝，与量化、低秩分解正交，可组合使用。对 MoE-MLLM 的部署栈而言，"专家剪枝 + W4A4 量化"可能比单一手段更能跨过单卡门槛。
4. **压缩感知的 serving 协同设计**：剪枝后 top-k 不变、每 token FLOPs 不变，意味着**调度器、并行策略（expert parallel 的 all-to-all 通信量减半）无需重写**即可复用——这类"部署友好"的压缩范式值得 Infra 界推广。
5. **校准即部署域定制**：校准集组成会定向激活特定域的专家（图表、文档、OCR），运维上可以把它当作"部署域调优旋钮"，按业务流量混合校准数据来定制压缩后的模型画像。

## 六、总结与启发

**亮点**：(1) 抓住了"模态不对称"这个被忽视的结构性事实，用低注意力视觉令牌这一直觉反常但实证稳定的信号做剪枝依据；(2) ΔH 有 KL 上界理论支撑、单次前向即可全量计算，工程成本极低（1K 校准样本、A100 单卡、无反传）；(3) α 闭式自适应 + 全局跨层排序，几乎无可调超参；(4) 部署实测数据扎实，3.9× 提速的归因清晰。

**不足**：(1) 固定剪枝掩码、一次成型，不建模"互相兜底的专家对"的联合删除（两阶段重打分反而更差，说明一次性估计有其合理性，但交互效应仍未隔离）；(2) 校准域敏感性可控但存在，域未知时需要宽混合兜底；(3) α 规则是经验验证而非理论最优；(4) 未覆盖代码、数学等推理密集生成任务，且只针对 top-k 路由的 routed experts（共享专家不动）。

**启发**：模态（乃至更广义的"输入子群"）分解的思路可以推广到任何异构输入的 MoE 系统——比如多语言、多任务、Agent 工具调用混合负载下，"哪类流量的专家重要性该怎么加权"都是同一个问题。对 Infra 研究者而言，这篇工作再次说明：**好的压缩信号应当尽量贴近部署时的真实失效模式（输出分布漂移），而非停留于权重或路由统计的代理量**。后续把 LoRA 微调叠上去补残余差距、或与量化联合优化，都是顺手的延伸。
