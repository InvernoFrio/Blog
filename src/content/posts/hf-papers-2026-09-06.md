## 研究背景与动机

### 视频生成的"视觉流畅≠物理可靠"问题

当代视频生成系统（如 Wan 2.2）能合成视觉逼真、时间连贯的片段，但**感知上的合理性不等于物理上的有效性**。一个生成视频中的失败可能出现在任何可观测的物理后果上：

- 物体被遗漏、轨迹与隐含力不一致、交互违反接触或因果约束
- 音频流中预期声音缺失、时序错误或来源错误
- 跨模态不一致：视觉和音频编码了不兼容的事件时序或因果关系

一个球可能在重力下悬空、穿过刚性墙、碰撞时没有声音，或者撞击声先于接触出现。

### 为什么这对智能体研究很重要？

随着生成视频被用于**具身系统的训练与评估循环**——合成机器人训练轨迹、支持策略学习与评估、缩小 sim-to-real 差距——物理可靠性变得至关重要。更强的世界模型与更好的下游策略性能相关，但现有的评估方法要么给出单一质量分数，要么缺乏可审计的证据链。

### 现有评估方法的局限

- **规则级判断**、**时间定位**、**可控测量**、**音频-物理一致性检查**等能力分散在不同评估器中
- 现有评估器通常是 benchmark 特定的协议，围绕策划数据集、预定义现象或手工编写的评分标准
- AV-Phys Agent 虽然结合了推理-行动循环与确定性声学工具，但仍依赖 prompt 特定的人工编写评分标准和多模态模型的二元判断

**核心缺口**：不是缺少某个组件，而是缺少一个将 prompt 编译为类型化物理义务、让观测门控已声明的专家调用、用固定规则组合证据记录的**统一可审计评估系统**。

## 核心方法与创新点

### 系统架构概览

VeriPhy 是一个**可审计的多工具批评器**，包含四个角色：

```
┌─────────────────────────────────────────────────────┐
│  文本规划器（Plan）                                    │
│  在看到任何帧之前，将 prompt 编译为：                     │
│  - 类型化物理声明（claims）                              │
│  - 静态验证的执行计划                                    │
└──────────────────────┬──────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  执行引擎（Execute）                                    │
│  观测门控已声明的专家调用：                               │
│  - 分割与追踪（SAM 3）                                  │
│  - 计数、11种类型化物理测量                               │
│  - 单目深度、OCR、音频事件检测                            │
└──────────────────────┬──────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  确定性聚合器（Compose）                                │
│  每个动作返回携带溯源的证据记录：                         │
│  - 类型化测量 或 显式标记的学习状态                       │
│  - 映射到三值状态：支持/矛盾/未知                        │
│  - 每个判断可追溯到产生它的证据                           │
└─────────────────────────────────────────────────────┘
```

### 关键创新点

#### 1. Plan-before-Act：规划先于观测

这是 VeriPhy 最核心的设计原则。文本规划器在**看到任何帧之前**就完成所有规划工作：

- **第一遍**：遍历整个 prompt，为每个独立实体和事件建立共享命名空间
- **第二遍**：将声明分组（每组最多4个），独立规划，然后通过机械重命名汇编到共享命名空间
- **静态验证**：编译为有向图 $G_\Pi = (A, Q, E, b)$，验证约束包括：

$$\text{Valid}(G_\Pi) = \text{Parse}(G_\Pi) \land \text{Refs}(G_\Pi) \land \text{Typed}(G_\Pi) \land \text{Acyclic}(G_\Pi) \land [\forall i, \exists q \in Q : b(q) = i]$$

这确保了：解析正确、引用闭合、类型匹配、无环、每个声明至少有一个检查。

#### 2. 类型化的表面语言

规划器使用的表面词汇被刻意限制为有限的操作集合：

| 操作 | 功能 |
|------|------|
| `judge("assertion")` | 通用语义验证 |
| `exists("object")` | 存在性检查 |
| `eq(count("phrase"), N)` | 计数验证 |
| `before(window(A), window(B))` | 时序关系 |
| `during(window(A), window(B))` | 时间包含 |
| `rel("A\|\|B", relation)` | 空间关系 |
| `traj("phrase", relation, target)` | 轨迹谓词 |
| `sound("description")` | 音频事件 |
| `text("STRING", carrier=...)` | 文本渲染 |

#### 3. 三值逻辑与溯源

VeriPhy 使用三值逻辑 $\mathcal{V} = \{S, C, U\}$（支持、矛盾、未知），而非二元判断：

- 时序谓词 $\rho_R(W_A, W_B)$ 在两个事件都被支持时才评估顺序关系
- 使用 Allen 区间代数的一个容差子集，边界松弛为较短窗口的 1/4
- 不可用证据保持为"未知"，终端基础设施故障作为单独结果

每个判断都保留完整的证据链：prompt span → 声明 → 计划调用 → 本地化证据 → 组合规则。

#### 4. 物理引导的仿真流水线

为评估提供物理真值，论文构建了一个**仿真引导的生成管线**：

$$\text{pev} \xrightarrow{\text{Author}} S \xrightarrow{\text{Sim}} \tau \xrightarrow{\text{Render}} C$$

- **Author**：将文本描述编译为结构化场景规范（物体、初始状态、碰撞器等）
- **Sim**：运行物理求解器，通过验证循环确保轨迹满足物理谓词 $\Phi_{ev}$（最多3次修订）
- **Render**：将验证后的轨迹渲染为深度控制信号 $C_t(u)$，归一化为近亮远暗

生成器使用 Wan 2.2-VACE，通过控制分支注入物理约束：

$$h_i^{(\ell)} \leftarrow h_i^{(\ell)} + s W^{(\ell)} z_{\text{ctrl}}$$

其中 $s$ 是条件强度残差，控制通过分支注入而非像素粘贴。

### 一个具体的例子

论文中给出了一个多米诺骨牌的例子：

```
规划器写的行（在看到任何帧之前）：
check(c1, before(window("the first domino tips forward"),
                 window("the first domino triggers a chain reaction")))
```

执行过程：

1. **规划**：读取声明为 A → B 的顺序关系
2. **门控**：验证器确认 A 和 B 都发生
3. **测量**：事件时序返回 $W_A = [1.62, 1.67]$s，$W_B = [2.33, 7.96]$s
4. **判断**：$\rho_{\text{before}}$ 解析，$A_{\text{end}} = 1.67 < B_{\text{start}} + \varepsilon = 2.33 + 0.0125$，声明被支持

## 实验结果与分析

### 数据集

- **1,500 个生成片段**，包含 **2,582 条人工编写的、基于 prompt 的缺陷记录**
- 每条记录引用被违反的 prompt span，提供理由、严重性、置信度，以及（如有）时间范围和物体轨迹
- **149-clip 核心评估集**：承载 304 条标注缺陷

### 主要结果

| 方法 | 检出缺陷数 | 特点 |
|------|-----------|------|
| 问题分解评估器 | 164 | 每个声明问一个是/否问题，无测量追踪 |
| 单体 prompt | 222 | 相同骨干模型，无智能体组织 |
| **VeriPhy** | **228** | 每个决策保留证据记录和溯源 |

**关键发现**：仅凭召回率无法区分 VeriPhy 与单体 prompt（228 vs 222）；真正的区别在于**每个决策都保留了证据记录和溯源**，使追踪可逐条审计。

### 控制撤回实验

通过在不同噪声水平撤回物理控制信号，发现：

- 轨迹在 $\sigma \approx 0.94-0.96$ 的窄带内停止响应控制撤回
- **飞行阶段**被很好地复现，但**接触后行为**不是
- 水平分量和垂直分量在不同时间点固定：仅按水平分量设定的撤回时机对垂直分量来说太早
- 这揭示了视频生成器中**接触先验较弱**的已知问题

### 场景库广度

- 构建了 **66 种场景类型、1,314 个场景**
- 单物体场景能很好地复现模拟轨迹（相关性 0.9998+）
- 多物体交互（如台球开球）未能产生正确的碰撞——这是当前视频生成器的根本限制

## 与智能体认知模块的关联

### 1. Plan-before-Act 认知架构的启示

VeriPhy 的"先规划后执行"设计直接映射到智能体的认知架构：

- **推理模块**（规划器）在感知之前建立完整的依赖图
- **执行模块**（专家工具）在观测门控下按拓扑序执行
- **记忆模块**（溯源记录）保持完整的决策历史

这与 AGENTS.md 中描述的"规划-执行-验证"认知流水线高度一致。对于构建可靠的认知智能体，**静态验证的执行计划**比动态 ad-hoc 调用更可审计、更可调试。

### 2. 三值逻辑与不确定性建模

智能体在推理时常面临信息不完整的情况。VeriPhy 的三值逻辑（支持/矛盾/未知）提供了一个优雅的框架：

- **已知信息** → 支持或矛盾
- **未知信息** → 保持为"未知"而非强制二元判断
- **不可用证据** → 保守地回退到整个片段

这对智能体的**元认知**（知道自己不知道什么）和**有界记忆合约**有直接启发。

### 3. 类型化证据与可审计性

VeriPhy 的证据记录设计对智能体记忆架构有重要启示：

- 每个动作返回的不只是结果，还有**类型化测量值、溯源信息、成本和状态**
- 学习状态被显式标记，与确定性测量区分
- 这使得"回放审计"成为可能——可以追溯每个判断的完整证据链

### 4. 世界模型评估的新范式

VeriPhy 为世界模型评估提供了一个**形式化框架**：

- 将评估从"标量质量分数"升级为"可审计的证据链"
- 支持物理引导的生成与独立的物理验证
- 为未来的"诊断反馈→再生"循环提供了接口

## 总结与启发

### 亮点

1. **设计哲学深刻**："可审计性"不是一个附属特性，而是系统的核心设计目标。每个决策都保留完整溯源，这在智能体系统中极为重要。

2. **类型化规划语言**：将表面语言限制为有限操作集合，通过编译器自动展开依赖闭合，这是"代码即计划"范式的优雅实现。

3. **三值逻辑的实用价值**：在信息不完整时，"未知"比"是/否"更诚实，这对智能体的可靠性至关重要。

4. **物理引导的生成管线**：将物理仿真与视频生成解耦，通过深度控制信号注入物理约束，这是一个通用的架构模式。

### 不足

1. **评估是开发集**：149-clip 核心集不是 held-out 的，结果描述的是系统能力而非泛化性能。

2. **单标注者**：缺陷记录是单人标注的，缺少标注者间一致性分析。

3. **多物体交互仍是瓶颈**：台球开球等多物体场景的碰撞未能正确生成，这是视频生成器的根本限制。

4. **诊断反馈尚未实现**：论文将"将诊断写回生成"留作未来工作，这意味着 VeriPhy 目前只是评估工具，还不是闭环精炼系统。

### 启发

VeriPhy 给智能体研究的核心启发是：**可审计性应该是一等公民**。当我们构建推理、规划、记忆模块时，不应只关注性能指标，还应确保每个决策都有可追溯的证据链。这对智能体的可靠性、可调试性和信任建立至关重要。

正如论文所说："What separates them is that each decision retains its evidence record and provenance, making the traces auditable one verdict at a time."
