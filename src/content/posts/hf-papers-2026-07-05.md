# AutoMem: Automated Learning of Memory as a Cognitive Skill

## 研究背景与动机

人类在处理长时程任务时，认知科学中有一个重要概念叫**元记忆（Metamemory）**——即"知道什么值得记、什么时候该检索、如何组织已知信息"的能力。这是一种**可习得的技能**，而非固定机制。人类通过笔记、索引、文件等外部辅助工具来扩展工作记忆的边界。

LLM 面临类似瓶颈：上下文窗口就是工作记忆，固定大小的缓冲区限制了模型一次能关注的内容。长时程任务（如 NetHack 一局上万步）远超这个容量。现有方法（检索数据库、向量存储、摘要缓冲区等）通常将记忆视为**架构模块**——一个预先设计好的固定机制。

AutoMem 的核心洞察是：**记忆管理本身就是一个可训练的技能**，应该让模型自己决定存什么、查什么、怎么组织。这与把记忆做成固定管道的思路截然不同。

### 为什么手动优化行不通？

长时程任务中的单个 episode 可能跑上万步，一个记忆错误（比如第 50 步忘了记录地图坐标）可能到第 800 步才暴露——人类根本无法手动审查这么长的轨迹来定位问题。

## 核心方法与创新点

AutoMem 的架构分为三层：

### 1. 内层循环（Inner Loop）：文件系统即记忆

将文件系统操作（`read`、`write`、`search`、`append`、`create`）提升为与任务动作（如"向左走"、"攻击"）**同等级别的一等动作**。模型在每个时间步执行两个例程：

- **LOG 例程**："刚才发生了什么值得记录？" → 决定是否追加/创建/重写记忆文件
- **PLAN 例程**："现在需要回忆什么来行动？" → 搜索文件、读取条目、然后执行任务动作

关键设计：记忆动作和任务动作在同一个 action space 里，由同一次前向传播选择。这让记忆成为一个**可观察、可追踪的技能**——每条记忆决策都是轨迹中的一个动作，外层循环可以分析和优化它。

### 2. 外层循环 #1：优化记忆脚手架（Structure）

由一个强 LLM（meta-LLM）充当"代码审查员"，读取完整的 episode 轨迹（上万步的日志 + 记忆目录 + 智能体代码），诊断记忆使用中的失败模式，然后**迭代修改智能体的脚手架**（代码、提示词、文件 schema、动作词汇表）。

具体例子：meta-LLM 在审查 NetHack 轨迹时发现，地图文件积累了上千条重复坐标条目，淹没了有用信息。于是它引入了坐标去重的地图格式，大幅压缩了记忆体积。

每次修改都有门控：新版本必须在同一组种子上跑出更高的平均进展率才会被保留。通常 2-5 次迭代后收敛。

### 3. 外层循环 #2：训练记忆熟练度（Proficiency）

脚手架优化到头之后，瓶颈转移到模型的**参数化能力**——在给定的记忆结构下做出更好的记忆决策。

这个循环让 meta-LLM 充当"训练引擎"：
1. 从大量 episode 中筛选出**值得强化的记忆决策**（模型自己产出的文本，meta-LLM 只做筛选，不生成新内容）
2. 将这些好决策作为监督训练数据
3. 联合优化数据筛选逻辑、数据组合、LoRA 训练配置

**关键创新：记忆技能的可分离性。** 因为记忆被视为独立技能，只微调一个专门的**记忆专家模型（Memory Specialist）**，而执行任务动作的模型权重完全不动。这保证了：
- 训练信号聚焦于记忆操作，不会被任务动作的格式输出稀释
- 任务能力不会因记忆训练而退化
- 记忆增益可以干净地叠加在脚手架增益之上

推理时部署两个模型实例：记忆专家处理 LOG 和 PLAN 中的记忆部分，任务模型（原始未修改版本）负责执行世界动作。两者共享同一个对话历史。

### 统一视角

两个循环本质上是同一个模式的不同实例化：

| | 循环 #1（结构） | 循环 #2（熟练度） |
|---|---|---|
| 参数 θ | 智能体脚手架（代码/提示） | 记忆专家模型权重 |
| 更新信号 ∇L | meta-LLM 的代码修改 | meta-LLM 筛选的监督训练数据 |
| 优化对象 | 记忆操作的结构空间 | 模型在给定结构下的决策能力 |

脚手架设定了记忆操作的结构天花板，熟练度训练则将模型推向这个天花板。

## 实验结果与分析

### 实验环境

在 BALROG 基准的三个**程序生成的长时程游戏**上评估：

| 环境 | 特点 | 难度 |
|---|---|---|
| **Crafter** | 开放世界生存游戏，含合成、战斗、资源管理 | 中等 |
| **MiniHack** | NetHack 引擎中的谜题、导航、战斗任务集 | 中高 |
| **NetHack** | 经典 roguelike，episode 长达 10⁴–10⁵ 步，人类玩家通常需要数年才能精通 | 极高 |

选择游戏环境的原因：每局随机生成，预训练知识难以迁移；episode 足够长，仅靠上下文窗口管理无法维持性能；成功需要人类自然会做的记录——地图、物品清单、遭遇日志、策略笔记。

### 核心结果

以 **Qwen2.5-32B-Instruct** 为基础模型：

- 仅优化记忆（不修改任务动作权重），AutoMem 带来 **~2×–4× 的进展率提升**
- 优化后的 32B 模型**大幅超越 Qwen2.5-72B-Instruct**，说明在这些任务上，良好的记忆管理比模型规模更关键
- 达到前沿闭源系统（**Claude Opus 4.5**、**Gemini 3.1 Pro Thinking**）的性能水平
- 记忆熟练度训练在脚手架增益之上额外贡献 **~9–18% 的相对提升**

### 关键发现

1. **记忆管理是独立可学习的技能**：不需要改变模型的任务行为，仅优化记忆就能带来巨大提升
2. **记忆是高杠杆目标**：在长时程任务中，记忆优化的收益远超简单地增大模型规模
3. **开源模型可以匹敌前沿系统**：差距主要来自记忆管理能力，而非底层智能

## 与博弈智能体的关联

这篇论文对博弈智能体研究有几层重要启发：

**1. 博弈中的记忆即战略资产。** 在多轮博弈中（如德州扑克、星际争霸），智能体需要追踪对手行为模式、已出牌面、资源状态等。AutoMem 的思路可以迁移到博弈场景——让智能体自己学会"记什么"比人工设计记忆结构更高效。

**2. 长时程博弈的瓶颈在记忆而非策略。** 实验表明，32B 模型通过优化记忆就能超越 72B 模型。这意味着在复杂博弈中，与其一味增大模型，不如先优化智能体的记忆管理能力。

**3. 元记忆可对抗对手建模。** 博弈智能体需要不断更新对对手的建模（opponent modeling），这本质上是一种记忆管理。AutoMem 的 LOG/PLAN 双例程可以直接扩展为"记录对手行为"和"检索对手模式"。

**4. 脚手架优化思路可复用。** 博弈智能体的提示词、记忆 schema 也可以用类似的 meta-LLM 审查轨迹、迭代修改的方式自动优化。

---

## 总结与启发

AutoMem 的核心贡献是一个简洁而有力的洞察：**记忆不是架构，是技能**。

传统方法把记忆做成固定的管道（RAG、摘要缓冲区），AutoMem 让模型自己决定存什么、查什么、怎么组织，然后用自动化的方式优化这个技能。双层循环的设计很优雅——第一层优化结构，第二层优化能力，两者互补。

最令人印象深刻的结果是：仅靠记忆优化，32B 开源模型就能在长时程游戏中匹敌 Claude Opus 4.5 和 Gemini 3.1 Pro Thinking。这说明在复杂任务中，"聪明地记"可能比"更大的脑"更重要。

**不足之处：**
- 目前只在游戏环境验证，尚未扩展到现实世界的长时程任务（如代码开发、科学研究）
- 外层循环依赖强 meta-LLM（如 GPT-4 级别），优化成本较高
- 记忆专家模型和任务模型的双实例部署增加了推理开销
- 对于记忆结构的最优形式缺乏理论分析，主要靠经验迭代

**未来方向：** 如果将 AutoMem 的元记忆框架应用到多智能体博弈场景中，让每个智能体自动学会"记什么关于对手"，可能会产生有趣的涌现行为。这值得进一步探索。
