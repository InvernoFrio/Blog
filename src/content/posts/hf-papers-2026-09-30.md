# EMem-Bench：给长程具身智能体做一次记忆体检

> 记得住，才走得远。今天这篇来自浙大 OmniAI 团队的工作，用 2554 个交互式 episode 把"具身智能体的记忆"拆成了四种能力，然后逐项打分——结果是：即便是 Gemini-3-Flash 这样的旗舰模型，也只拿到 64.2% 的平均成功率。

## 研究背景与动机

在纯文本数字世界里，长程智能体（比如自动开发大型代码库、自动做研究并写报告的 agent）已经离不开长期记忆——保留交互历史、检索过去信息、跨任务复用经验，这已经是常识。

但当智能体走进真实 3D 物理世界，记忆的难度上了一个台阶。文本记忆只需要记"语言"，多模态记忆扩展到图片和视频，而**具身记忆**要求保留观察-动作-反馈之间的**因果连接**：动作改变了环境，动作的**结果**反过来揭示了视觉上看不见的世界状态和约束。这些交互还要在受干扰、会变化的环境中长时间展开。

作者做了一件很扎实的事：在 EmbodiedBench 的 EB-ALF 和 EB-Hab 任务上，人工检查 Gemini-3-Flash 和 Qwen3-VL-32B 的 **100 条失败轨迹**，结果发现四类失败占了 **91%**：

| 失败类型 | 占比 | 对应的记忆能力 |
|---|---|---|
| 忘记细粒度视觉线索 | 35% | **细粒度视觉记忆**：未来任务未知，但仍要记住看过的物体外观和位置 |
| 忽视环境变化 | 18% | **动态世界状态跟踪**：物体状态可能被人或其他机器人改变，必须持续更新 |
| 未记录交互揭示的状态 | 31% | **交互结果状态记忆**：抓取失败、抽屉锁住、容器不可用，这些视觉看不见的状态必须记住 |
| 无法从经验泛化 | 7% | **经验泛化记忆**：早期任务的成败和物理规律要能迁移到新任务 |

这个 91% 的数字非常有说服力——它说明长程具身任务的失败，本质上大多是**记忆问题**，而不是感知或动作执行问题。但现有 benchmark 并没有直接评估这些记忆能力：要么是单轮问答，要么是让智能体从零开始探索并执行任务，都不考察"从历史交互中构建记忆、再用记忆指导后续行动"这一闭环。

## 核心方法与创新点

### 1. EMem-Bench：以记忆为中心的任务定义

每个 episode 由三部分组成：一段按时序排列的多模态交互历史 $\mathcal{H}=\{o^{\mathrm{h}}_{1},\dots,o^{\mathrm{h}}_{N}\}$、目标任务 $\mathcal{T}$、可行动作空间 $\mathcal{A}$。智能体必须先"看懂"历史，从里面提取出完成目标任务所需的信息（不管隐式还是显式），然后在环境中一步步执行：

$$a_{t}\sim\pi\left(\cdot\mid\mathcal{H},\mathcal{T},o^{\mathrm{e}}_{1:t},a_{1:t-1}\right)$$

当执行轨迹最终到达满足 $\mathcal{T}$ 的环境状态时，episode 判定成功。四个任务族的差别就在于 $\mathcal{H}$ 和 $\mathcal{T}$ 如何构造：$\mathcal{H}$ 决定"要记住什么类型的信息"，$\mathcal{T}$ 决定"这些信息在后续交互中如何被用到"。

- **Passive Observation（1036 条）**：在物体密集场景里看一段无关任务轨迹，之后要找回当时出现过的目标物体。考验的是"未来任务未知时是否仍能记住细节"。
- **Dynamic Tracking（1052 条）**：历史里记录物体位置/状态的变化，后续任务要求按**最新状态**行动，而不是过时观察。考验的是记忆的**更新**能力。
- **Interaction Failure（263 条）**：历史里有一次失败的物理交互（比如开锁失败的抽屉），其反馈揭示了视觉不可见的状态，后续任务要求避开这个不可用目标。考验的是"从交互结果中学习"。
- **Experience Generalization（203 条）**：历史里有多个物体的"错误动作→纠正"案例，后续任务给出同类新物体，要求迁移共性规律。考验的是**经验抽象与泛化**。

### 2. 交互历史的四阶段构造管线

这是 benchmark 质量的关键，值得单独讲：

1. **选房间**：AI2-THOR 原生只有单房间场景，作者把不同房间类型的场景拼成虚拟住宅，并扩展动作空间（`LeaveRoom`/`EnterRoom`/`MoveToRoom`），且智能体重进房间时状态会恢复（保证记忆而非"碰巧看到"才是关键）；ProcTHOR 则筛选多房间住宅的连通性、可导航空间、物体可见性和可执行交互。
2. **构造记忆线索**：每个任务族设计不同的"必须记住的那条信息"。Passive Observation 选当前可见物体作为后续检索目标；Dynamic Tracking 在模拟器里改变物体位置/状态；Interaction Failure 执行一次失败动作让反馈揭示隐藏状态；Experience Generalization 用 Claude-4.6-Sonnet 生成结构化经验（规律+多个纠正案例+目标任务），再落地到具体场景物体并在模拟器里执行。
3. **注入干扰轨迹**：用 PDDL 规划器在记忆线索前后生成无关任务轨迹，让线索出现在 episode 的不同位置，并丢弃任何碰到关键物体、泄露答案、改变目标任务依赖状态或无法执行的轨迹。这一步直接杜绝"关键词匹配就能答对"的捷径。
4. **自动验证 + 人工复核**：自动检查场景可导航、关键交互可执行、目标任务可完成，并验证决定性证据确实出现在早期历史中且未被干扰轨迹泄露；之后人工复核每一条通过的候选，剔除指令模糊、轨迹不合理、线索不能唯一支持目标动作的 episode。这个流程最终**拒收 143 条**，保留的 2554 条全部通过双重校验。

规模上，EMem-Bench 共 2554 个 episode、1118 个场景，四个任务族分布为 1036/1052/263/203。

### 3. Embodied-Memorizer（EMem）：三类记忆的外挂系统

作者没有止步于"出题"，还给了一个简单有效的参考答案。EMem 把具身经验组织成三类互补记忆：

- **场景记忆（Scene Memory）**：把观察锚定到具体房间/场景，区分"厨房的杯子"和"卧室的杯子"。
- **空间记忆（Spatial Memory）**：维护物体的最新位置与状态，世界变化时**替换**过时关系。
- **事件记忆（Event Memory）**：保留动作、反馈和纠正，并把反复出现的经验**固化**为可复用知识。

整体形成 **观察 → 写入 → 检索 → 行动** 的循环。**EMem-8B** 则是在 Qwen3-VL-8B 上做监督微调（SFT），让模型自己学会"什么时候写、检索什么、怎么用"这三件事——把记忆管理本身变成策略的一部分，而不是外部规则硬编码。

## 实验结果与分析

评测覆盖 **16 个主流开源/闭源 MLLM** 以及代表性多模态记忆系统，指标包括成功率（SR↑）和错误复发率（ERR↓），平均值按四个任务族等权计算。

**主结果的核心事实：**

| 模型/系统 | 平均成功率 | 说明 |
|---|---|---|
| Gemini-3-Flash（最强闭源） | **64.2%** | 依然远低于人类水平 |
| 其他开源模型 | 绝大多数 **< 45%** | 且四个任务族间表现极不均衡 |
| GPT-5.4-mini + EMem | **58.9%**（vs 35.3%） | **+23.6 pts** |
| Mistral-Small-3.1-24B + EMem | **57.3%**（vs 40.9%） | **+16.4 pts** |
| EMem-8B（训练后） | **46.0%**（vs Qwen3-VL-8B 25.4%） | **+20.6 pts** |

**同骨干对比**下，EMem 在所有被评记忆系统中综合表现最好，且同时提升了开源和闭源模型；EMem-8B 在其骨干之上还有进一步提升。

**失败模式分析**很有信息量：在 400 条抽样失败中，**61.3%** 的失败始于模型依据一条**与交互历史相矛盾的记忆**行动。也就是说，模型不是"记不住"，而是"记错了还不自知"——这本质上是一个**元认知缺失**问题：没有机制在行动前校验"我此刻依赖的记忆是否和历史一致"。

## 与智能体认知模块的关联

这篇工作对智能体认知架构研究有几条直接启发：

- **记忆**：EMem 的三分法（场景/空间/事件）是比"短期/长期"更**功能导向**的记忆分类。场景记忆解决"在哪见过"，空间记忆解决"现在在哪"，事件记忆解决"发生过什么、学到什么"。这个分解可以直接迁移到数字智能体的记忆系统设计——比如把代码仓库的"模块-文件-符号"对应场景记忆，把当前工作树状态对应空间记忆，把调试日志和纠错经验对应事件记忆。
- **世界模型**：Dynamic Tracking 任务族本质上是在测试智能体内部世界模型的**状态更新**能力。"用最新状态替换过时关系"正是世界模型的核心维护操作——这与近期"编辑式世界模型"（AEWM 等）关注的状态污染问题一脉相承。
- **推理与规划**：Interaction Failure 揭示的"视觉不可见状态"（锁住的抽屉、不可用容器）实际上是规划中的**约束条件**。一个能记住失败反馈的智能体，等价于拥有一个不断丰富的约束集，后续规划自动避开已知不可行分支——这正是"从失败中学习规划"的最小可行形式。
- **元认知**：61.3% 的失败源于"按矛盾记忆行动"，强烈提示智能体需要一个**行动前一致性校验**机制。这与近期 Adaptive Consistency Graph（ACG）等工作在数字智能体上做的"需求-证据一致性检查"是同一个思路在不同模态的体现。
- **评估与基准**：EMem-Bench 的构造方法论（记忆线索 + 干扰轨迹 + 双重验证）为"如何评测隐性能力"提供了范本。干扰轨迹的设计尤其值得借鉴——它把"是否真的用了记忆"从"是否碰巧答对"里剥离出来。

## 总结与启发

**亮点：**

1. **问题定义精准**：从 100 条失败轨迹的实证分析出发，把"具身记忆"拆成四种可独立评测的能力，而不是笼统地说"记忆很重要"。91% 这个数字为整个研究方向提供了坚实的动机。
2. **Benchmark 构造严谨**：记忆线索 + 干扰轨迹 + 自动验证 + 人工复核的四阶段管线，尤其"拒收 143 条"这个细节说明数据质量把控是认真的。1118 个场景的规模也足够支撑有统计意义的结论。
3. **不只是评测，还有方法**：EMem + EMem-8B 提供了一个可复现的强基线，且证明了"记忆系统"和"学会使用记忆的策略"两层都可以改进，提升幅度（+16 到 +23 分）相当可观。
4. **资源开放**：数据集、代码、评测工具全部公开，还提供无需 GPU 的本地 demo，复现门槛低。

**不足：**

1. **任务族分布不均**：Passive Observation（1036）和 Dynamic Tracking（1052）占了绝大多数，Interaction Failure（263）和 Experience Generalization（203）样本偏少，而后者恰恰是最接近真实长程任务的类型。
2. **环境相对受限**：基于 AI2-THOR/ProcTHOR 的室内家居场景，动作空间是离散符号化的，与真实机器人的连续控制还有距离；Dynamic Tracking 的"变化"是脚本化注入的，还不是真正的开放世界扰动。
3. **EMem 的记忆管理仍是规则驱动**：三类记忆的写入/检索边界是预定义的，EMem-8B 虽然学会了调度，但记忆结构本身的可扩展性（比如自动发现新的记忆类型）未被探索。
4. **缺乏时间维度的衰减分析**：交互历史长度与记忆准确率的关系只在统计图中出现，没有系统研究"记忆什么时候该被遗忘"。

**对后续研究的启发：**

- **记忆可靠性 > 记忆容量**。61.3% 的失败是"按错误记忆行动"，提示未来工作应聚焦记忆的**一致性校验与冲突消解**，而非单纯扩大存储。
- **"记忆管理策略"可以被训练**。EMem-8B 证明 SFT 就能让模型学会写-检索-用的调度，那么用 RL 直接优化"记忆操作序列"是一个自然的下一步。
- **数字智能体可以借鉴同样的评测范式**。把"记忆线索 + 干扰轨迹 + 一致性校验"搬到软件工程、Web 导航等数字场景，能构造出同样严格的记忆基准。
- **与元认知机制的结合值得期待**：在行动前显式校验"当前依赖的记忆是否与历史矛盾"，可能比改进记忆结构本身收益更高。

---

**一句话总结**：EMem-Bench 把长程具身智能体的失败归因从"能力不足"精确到了"记忆缺陷"，并用严谨的 benchmark + 有效的记忆系统证明了这一点。如果你做智能体记忆、世界模型状态跟踪或元认知研究，这篇值得精读。
