# 确定性屏幕活动编译与智能体行为记忆架构

## 论文基本信息

- **标题:** Activity Frames: Deterministic Screen-Activity Compilation for Agent Memory and Replay
- **链接:** [https://huggingface.co/papers/2608.05784](https://huggingface.co/papers/2608.05784)
- **机构:** 独立研究者 (Nossa Iyamu)
- **发表时间:** 2026年8月6日

---

## 研究背景与动机

### 智能体的"行为盲区"

当前 LLM 智能体面临一个根本性问题：**它们只知道用户说了什么，不知道用户做了什么。** 当智能体被问到"今天应该优先处理什么？"时，它只能看到对话记录、文件和日历——却看不到用户上午一直在处理一个 PR、午饭后切换了四十次上下文、或者在 16:40 放弃了一封未完成的邮件。

现有的智能体记忆系统（MemGPT、Mem0、Zep 等）都是**对话记忆**——记录的是流经智能体的信息（消息、工具调用、任务轨迹），而非用户的实际行为。情景记忆（episodic memory）——一条按时间组织的经验记录——被认为是长期智能体缺失的关键拼图。

### 捕获已成商品，消费仍是瓶颈

屏幕捕获技术已经成熟：ActivityWatch 记录应用焦点已有十年，微软 Recall 在 Copilot+ PC 上存储周期性快照，OpenAI Chronicle 从屏幕内容构建记忆。但**消费**才是问题所在：

- **原始搜索**：一天的事件驱动捕获约产生 2000 行快照，序列化后达 126,812 tokens，智能体需要自己做会话化、去重和时长计算
- **LLM 摘要**：压缩效果好，但引入了摘要器的所有弱点——每次运行有成本、不确定性、长文本上可靠性下降、可能编造从未发生的活动

**两者都不能产出智能体可以缓存、审计或信任的记忆。**

## 核心方法与创新点

### 确定性编译：缺失的中间层

论文提出"确定性编译"作为原始搜索与 LLM 摘要之间的**缺失中间层**。就像编译器将指令转化为结构化产物而不需要观点一样，论文将快照流编译为**活动帧（activity frames）**：

```
活动帧 = 有界片段 {
    应用 (application)
    站点 (site) — 浏览器活动的 URL host
    起止时间 (start, end)
    基于停留的活跃时长 (dwell-based active time)
    类型化页面引用 (typed page references)
    输入量 (input volume)
    证据指针 (evidence pointers) → 原始行
}
```

**关键：没有模型参与。** 相同的数据库和窗口总是产生相同的文档，因此情景记忆变得可以自由重建、安全缓存、机械可审计。

### 两层架构：测量 vs 推断

这是论文最有洞察力的设计之一：

**第一层（测量层）**：完全由确定性代码从捕获数据派生。没有意图标签——因为代码无法观察意图。每个字段都是可复现的。

**第二层（推断层）**：接受带标签的推断，但必须满足三个规则：
1. 推断内容必须放在命名空间化的 `inferred` 块中
2. 必须携带置信度标签（{high, medium, speculative}）
3. 必须命名其证据——支持它的测量字段或原始行

**剥离推断层后，剩下的始终是一个纯粹的测量文档。** 这是信任的基础架构。

### 三个分割常数

编译器使用三个从捕获节奏中选择的常数（而非在结果上调优）：

1. **停留（Dwell, D=90s）**：一帧贡献 min(Δt, 90s) 的活跃时间，其中 Δt 是到其监视器流中下一帧的间隙。90s 上限约等于三个心跳周期，限制了单帧在捕获停滞或显示器睡眠时能获得的信用。

2. **会话间隙（Session Gap, G=300s）**：超过 300s 的间隙关闭当前帧，成为候选覆盖间隙。不跨越它计信用。

3. **闪烁合并（Flicker Merge, F=20s）**：模式 A → B → A，其中 B 持续最多 20s 壁钟时间且没有会话间隙介入，折叠为单个 A 帧。关键：B 不被丢弃——它作为中断记录在合并帧上，带有测量的秒数。

### 类型化页面引用：确定性 URL 解析

浏览器帧携带页面引用：通过确定性 URL 解析产生的类型化引用。解析分层进行：

1. 主机的定制解析器（覆盖专业网络、代码托管、搜索、文档、邮件、地图、视频、社交等 20+ 站点）
2. 通用搜索参数检测器
3. 子域名和路径启发式
4. 总回退——保证每个 URL 映射到某个类型

在语料库的 5,120 个不同 URL 中，分层解析器为 **81.3%** 产生非通用类型化引用，覆盖 46 种类型。

### 例程重放的确定性编译

编译器不仅能生成记忆，还能**将重复捕获缩减为可重放脚本**。对于一个 k 步例程，比较两种 token 成本：

$$C_{\text{agent}}(k) = k \left( \frac{wh}{750} + 350 + 180 \right)$$

其中 wh/750 是截图的图像 token（按 Anthropic 规则），350 token 是上下文读取，180 token 是推理输出。在典型 1512×982 捕获下，每步约 2,500 tokens。

**例程开销比 R** 定义为：

$$R = \frac{C_{\text{agent}}(k)}{C_{\text{replay}}(k)}$$

其中分母由编译器确定性地发射（无模型参与）。

## 实验结果与分析

### 语料库概况

论文在作者自己的实况语料库上进行表征：61 个日历天（46 个活跃天），包含 109,735 快照行、214,360 输入事件、8.4M 元素树行，跨 54 个应用。

### Token 成本：86 倍压缩

对于一个代表性全天（2,066 快照行），三种表示的 token 成本：

| 表示 | Tokens | 压缩比 |
|------|--------|--------|
| 原始行（JSON） | 126,812 | 1× |
| 编译的 schema-v1 文档 | 34,815 | 3.6× |
| 紧凑上下文块 | 1,469 | **86×** |

两种编译形式都不需要任何模型调用，因此压缩是免费的。1,469 tokens 足够小，可以包含在每个系统提示中。

### 下游问答：98.4% 准确率

在 8 个评测天、64 个地面真值问题上，两种模型层级（Claude Sonnet 4.5 和 Opus 4.5）的表现：

| 表示 | Sonnet 准确率 | Opus 准确率 | 时长误差 |
|------|-------------|-----------|---------|
| 原始行 | 82.1% | 91.1% | 25.7-39.7% |
| LLM 摘要 | 66.1% | 80.4% | 25.2-135.7% |
| **活动帧** | **98.4%** | **98.4%** | **7.3%** |

四个关键发现：

1. **差距是量性的，不是质性的。** 所有三种表示在缺席事实探测上都完美评分（幻觉率 0%）。摘要在数量上失败——在 Sonnet 层级，时间问题准确率仅 7.1%，主导应用活跃时长平均误差 135.7%。

2. **更强的模型缩小差距但不能消除它。** 前沿 Opus 模型从散文中重建时长好得多，但仍然比活动帧高 3.5 倍误差。**而读取活动帧时，两个模型不可区分（都是 98.4%）。**

3. **摘要是不确定性的。** 每天重新生成三次产生三个不同文本，而活动帧块在三次重新生成中是字节相同的。

4. **最忙的一天原始行达 257k tokens，超出上下文窗口**——两种基线都不可行；约 2k 的活动帧块不受影响。

### 编译延迟与可复现性

编译完整一天（分割、充实、实体类型化、发射）在消费级笔记本上中位耗时 **68 ms**。两次独立编译产生**字节相同**的文档。

### 例程开销比 R 的首次测量

| 指标 | 动作粒度 | URL 粒度 |
|------|---------|---------|
| R_inject（守卫计划，操作性） | 60× | 198× |
| R_info（最小脚本，天花板） | 343× | 198× |

- **可委托复发率 h**：样本内 9.0%，样本外 7.7%
- 全舰队上限 h(1 - 1/R_info) ≈ 7.7%

这意味着智能体重新推导一个例程的代价是重放它的 60-343 倍，而约 7.7% 的用户工作是可委托的重复例程。

### 日碎片化分析

43 天编译产生 17,514 帧，中位活跃时长 0.5 分钟——68% 的帧持续不到一分钟。但分解后：
- 52% 的亚分钟帧是单快照行程（transit），不是注意片段
- 排除行程后中位数升至 0.9 分钟
- 这与中断科学的测量一致：三分钟工作球、75% 的笔记本内容段不到一分钟

## 与智能体认知模块的关联

这篇论文对智能体认知架构研究有深刻启示：

### 1. 情景记忆是认知架构的基础设施

论文最有力的论点是：**情景记忆应该是基础设施，而不是推理。** 在 68ms 和零 tokens/天的成本下，记忆变成了一种确定性投影——可缓存、可审计、可测试。这对智能体认知架构的启示是：记忆系统不必总是依赖 LLM 来构建和管理，确定性编译可以提供一个可信赖的基础层。

### 2. 测量/推断边界是信任的架构保障

论文提出的两层架构——测量层（确定性事实）与推断层（带标签的推断）——直接回应了智能体记忆安全问题。在智能体推理/规划中，我们经常需要区分"观察到的事实"和"推断出的意图"。这个架构提供了一个原则性的分离：剥离推断层后剩下的永远是纯粹的测量文档。

### 3. 例程开销比量化了记忆的价值

R = 60-343× 是第一个量化"智能体重新推导已知例程的代价"的测量。这对智能体规划研究的启示是：**记忆驱动的例程重放可以比从头推理节省两个数量级的计算。** 论文首次测量了桌面工作的真实复发率（h ≈ 8%），为智能体成本模型提供了此前假设但未测量的关键参数。

### 4. 确定性 > 不确定性（在基础设施层）

论文实验证明，中端模型读取确定性编译块的表现（98.4%）匹配前沿模型（98.4%），而读取 LLM 摘要时两者差距 14 个百分点。这说明：**结构化的确定性表示比不确定的自然语言表示更有利于模型理解。** 这对智能体的记忆架构设计有直接指导——记忆的表示形式可能比读取记忆的模型能力更重要。

### 5. 屏幕活动是智能体的"行为接地"

当前 GUI 智能体将屏幕作为动作表面（action surface），但很少将其作为记忆来源。论文反转了这个视角：**编译用户做了什么，而不是智能体做了什么。** 这为"主动式智能体"（proactive agent）提供了基础——智能体可以在用户未明确指示时，基于行为记忆主动提出建议。

## 总结与启发

### 亮点

1. **"无趣即要点"的哲学。** 论文最深刻的洞见是：确定性代码（而非 LLM）是构建可信赖记忆的正确工具。68ms 和零 tokens 的成本使情景记忆从推理变为基础设施。

2. **测量/推断边界的架构设计。** 这是一个可以被广泛采用的模式——不仅适用于屏幕活动记忆，也适用于任何需要区分"事实"和"推断"的智能体系统。

3. **首次量化了例程开销比和复发率。** R 和 h 是智能体成本模型中此前假设但未测量的参数。论文诚实地报告了单用户数据，并明确了泛化边界。

4. **实验证据扎实。** 86 倍压缩、98.4% 准确率、字节级可复现性——每个数字都有明确的测量方法和诚实的限制讨论。

### 不足

1. **单用户语料库。** 所有数字来自一个专业人员的 51 天工作。节奏、碎片化和实体覆盖在不同角色和平台间会差异很大。论文坦诚地承认了这一点。

2. **R 的分子是建模的，不是计费的。** 例程开销比的分子（截图驱动智能体的成本）是按 Anthropic 图像 token 规则建模的，而非实际运行智能体。论文报告了首次实况执行确认（零模型 tokens），但完整的三臂实时计费仍被保留。

3. **OCR 是学习组件。** 确定性声明从存储的 OCR 文本向前成立，但不回溯到像素——不同的 OCR 模型可能产生不同文本。

4. **隐私与监控的张力。** 虽然整个流水线是本地的，但持续屏幕捕获本身就是敏感的。论文的隐私模型（操作者选择什么离开设备）是合理的，但部署场景需要仔细考量。

### 对智能体研究的启发

这篇论文最大的贡献可能不是技术本身，而是它提出的**范式转换**：智能体的记忆不应该总是"推断出来的"，而可以是"编译出来的"。确定性编译提供了推断无法提供的东西——可复现性、可缓存性、可审计性。在智能体认知架构中，这可能意味着我们需要一个"确定性记忆层"作为推断层的基础，就像操作系统需要确定性的文件系统作为应用程序的基础一样。
