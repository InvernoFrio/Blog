# DCAS: Decoupling CLI Agent Scaffolding to Internalize Planning across Scaffolds

## 📄 论文基本信息

- **标题:** DCAS: Decoupling CLI Agent Scaffolding to Internalize Planning across Scaffolds
- **链接:** [https://huggingface.co/papers/2608.06113](https://huggingface.co/papers/2608.06113)
- **机构:** Huawei Canada (Centre for Software Excellence), Queen's University
- **作者:** Kishanthan Thangarajah, Boyuan Chen, Ahmed E. Hassan
- **会议:** ASE 2026 (41st IEEE/ACM International Conference on Automated Software Engineering)

---

## 🔍 研究背景与动机

### 问题：跨脚手架性能崩塌

当前开源CLI编码智能体生态存在一个被忽视但严重的问题：**几乎所有开源轨迹数据集都在OpenHands环境下收集**（SWE-Gym、Nebius、SWE-Lego、CoderForge都是如此），导致微调后的模型在OpenHands上表现优异，但部署到其他脚手架时性能显著下降。

论文的实测数据触目惊心：

| 模型 | OpenHands | Claude Code | OpenCode | mini-swe-agent |
|---|---|---|---|---|
| SWE-Lego-Qwen3-32B | 52.6% | 44.2% | **8.4%** | 37.6% |
| Nebius-SWE-Rebench-30B | 49.7% | 46.0% | 35.8% | **20.4%** |

但关键发现是：**未训练的基座模型在不同脚手架间的表现差异远小于微调后的模型**。这意味着性能崩塌是微调引入的，而非模型本身的能力限制。

### 核心假设：规划结构是关键

作者将"规划"分为两个维度：

1. **显式规划 (Explicit Planning):** 执行前模型作为一等工件产出的计划，如Claude Code的Plan Mode
2. **隐式规划 (Implicit Planning):** 贯穿智能体循环每一轮的结构性约定——子步骤粒度、工具调用序列、何时从探索转向行动、失败后的重规划策略

不同脚手架在这两个维度上差异最大，但底层都共享类似的ReAct式执行循环。因此，跨脚手架性能下降的本质是**规划约定的错配**，而非能力缺陷。

---

## 🛠️ 核心方法与创新点

### DCAS架构：后端替换拦截层

DCAS的核心设计极为精巧——它是一个**透明的API流量拦截层**，位于CLI脚手架和后端模型之间：

```
CLI脚手架 → DCAS拦截层 → 后端模型
              ↕
          轨迹记录器
```

关键特性：
- **脚手架完全不变**：DCAS只路由API流量，翻译请求/响应格式以匹配目标模型
- **任意后端替换**：同一个脚手架可以接入不同的模型
- **规划感知轨迹收集**：记录的轨迹包含显式规划阶段和执行阶段的分离信息

### Planner-Executor实验设计

RQ1的实验设计堪称精妙：**固定执行器模型和脚手架，只改变计划来源**。

三种条件：
1. **无计划 (baseline):** 模型直接解决问题
2. **自计划 (self-plan):** 模型先生成计划再执行
3. **外部计划 (external-plan):** 由更强的模型（Claude Sonnet 4.5/Opus 4.5/Qwen3-480B）生成计划，执行器按计划执行

### 两种SFT数据集变体

为分解两种规划维度的学习效果：

- **PlanOnly:** 仅用规划阶段的轨迹训练（14,162样本），测试隐式规划约定是否能独立迁移
- **Plan+Exec:** 用完整两阶段轨迹训练（36,259样本），测试显式+隐式规划的联合学习

## 📊 实验结果与分析

### RQ1: 计划质量的杠杆效应

| 计划配置 | Pass@1 |
|---|---|
| 无计划 (baseline) | 42.8% |
| 自计划 | 48.2% (+5.4%) |
| Qwen3-480B计划 | 49.2% (+6.4%) |
| Claude Sonnet 4.5计划 | **57.8%** (+15.0%) |

**仅改变计划来源，就有15个百分点的提升！** 这个杠杆效应超过了论文观察到的跨脚手架性能下降幅度，直接证实了规划是高杠杆的性能组件。

一个有趣的发现：**Claude Sonnet 4.5作为规划器优于Claude Opus 4.5**（57.8% vs 54.2-56.0%），尽管Opus是更强的通用模型。这说明规划器与执行器的**校准度**比规划器本身的**绝对能力**更重要。

### RQ2: 规划可通过微调内化

| 变体 | 计划条件 | Pass@1 |
|---|---|---|
| 基座模型 | 无计划 | 42.8% |
| PlanOnly | 无计划 | 53.8% (+11.0%) |
| PlanOnly | 自计划 | 53.2% (+10.4%) |
| Plan+Exec | 无计划 | 52.8% (+10.0%) |
| Plan+Exec | 自计划 | **55.8%** (+13.0%) |

关键发现：
- **PlanOnly的无计划增益高达+11%**，证明隐式规划约定已被内化——模型学到了脚手架的结构性行为模式
- **PlanOnly自计划反而略降**（53.2% < 53.8%），因为它只学了生成计划，没学怎么用计划
- **Plan+Exec自计划达到55.8%**，接近外部前沿规划器的效果（56.0-57.8%），但不需要推理时的外部规划器！

两种规划维度在训练数据中**干净地解耦**，各自独立可学。

### RQ3: 学到的规划能力可跨脚手架泛化

| 脚手架 | 条件 | 基座 | Plan+Exec SFT |
|---|---|---|---|
| CC 2.0.76 (训练) | 自计划 | 48.2% | 55.8% |
| CC 2.1.73 (新版) | 自计划 | — | **57.2%** |
| OpenCode | 自计划 | 47.4% | 49.4% (+3.4%) |
| mini-swe-agent | 自计划 | 37.2% | 42.4% (+7.0%) |

Plan+Exec模型**只在CC 2.0.76上训练过**，但在从未见过的脚手架上依然有增益。这证明学到的是**结构性规划技能**，而非脚手架特定的记忆。

## 🧠 与智能体认知模块的关联

这篇论文对智能体认知架构研究有深刻启示：

### 1. 规划作为可学习的认知能力

传统观点将规划视为脚手架的设计特性（硬编码在系统提示或工作流中）。DCAS证明**规划可以作为模型的内在能力通过训练习得**，这与认知架构中"规划应是智能体核心能力"的观点高度一致。

### 2. 显式与隐式规划的解耦

论文对规划的二分法（显式/隐式）提供了一个分析框架：
- **显式规划** ≈ 认知架构中的"慢思考"、System 2推理
- **隐式规划** ≈ 认知架构中的"快思考"、System 1的结构化行为模式

两者可独立学习、独立迁移，这为设计更灵活的智能体认知架构提供了实证基础。

### 3. 校准度 > 绝对能力

Sonnet 4.5作为规划器优于Opus 4.5的发现，暗示智能体系统设计中**组件间的协调匹配**比单个组件的绝对能力更重要。这对多模块认知架构的设计有重要指导意义。

### 4. 小数据高效训练的启示

576条规划感知轨迹就实现了跨脚手架泛化，远少于传统数据集的数千到数万条。这说明**结构化的认知信号比数据量更重要**——训练数据的"信息密度"是关键。

## 💡 总结与启发

### 论文亮点

1. **问题定义精准:** 首次系统性地量化了CLI智能体的跨脚手架性能崩塌，并将其归因于微调引入的规划约定依赖
2. **方法设计巧妙:** DCAS拦截层实现了无侵入式的跨脚手架评估和轨迹收集，技术方案简洁有效
3. **实验设计严谨:** 三个RQ层层递进——从证明规划的杠杆效应（RQ1），到证明规划可内化（RQ2），到证明可泛化（RQ3）
4. **实用价值高:** 576条轨迹、30B模型、纯SFT就实现了接近前沿规划器注入的效果，成本可控

### 不足与展望

1. **仅在SWE-bench Verified上评估**，未验证对其他代码库或任务类型的泛化
2. **规划与其他因素（工具格式、上下文长度）的贡献未完全解耦**
3. **仅用Qwen3-Coder-30B作为执行器**，不同规模/架构模型的效果未知
4. **未探索RL训练路径**（论文提到SWE-RL和DeepSWE作为替代方向）

### 对智能体研究的启发

这篇论文最深刻的启示或许是：**智能体的"能力"不应被绑定在特定的系统架构上**。真正的通用智能体应该将关键认知能力（如规划）内化为模型本身的特性，而非依赖外部脚手架的硬编码。DCAS提供了一条可行的路径：通过结构化的轨迹收集和训练，将脚手架的隐性知识转化为模型的显性能力。
