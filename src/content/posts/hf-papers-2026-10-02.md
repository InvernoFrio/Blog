# MemLife：长期第一人称视频记忆的整理与推理

> 如果 AI 助手能通过智能眼镜把你的日常生活录成第一人称视频，它能不能回答关于你过去的任何问题？表面上看这是个 RAG 问题——但当视频积累到数百小时、跨越数月甚至数年，场景与事件反复出现、彼此只差微妙细节时，现有记忆系统就崩了：要么**写入时丢掉了关键证据**，要么**读取时在不断膨胀的检索空间里发生"检索竞争"**。Meta Reality Labs 这篇 MemLife 给出的答案是：把"写什么"当成一个可以被强化学习优化的一等公民问题。

## 二、研究背景与动机

长期第一人称视频是"个性化生活 AI"的理想数据源：智能眼镜、GoPro 录下的日常流，天然携带了用户的行为、物品、社交与时间线。但把它变成可问答的记忆，有两个硬骨头：

1. **数据侧**：视频按小时累积，场景高度重复（每天都在厨房、每天都做饭），事件之间只有细微差别。逐条重新处理原始片段在计算上不可行。
2. **系统侧**：延迟预算有限，要在长而相似的历史里筛出相关证据，传统 RAG 的"编码-检索"管线要么把记忆写得丢证据，要么检索时被海量相似条目淹没——论文称之为 **retrieval competition（检索竞争）**。

现有两类路线各有缺陷：检索导向系统（Video ReCap、EgoRAG 等）把片段压成扁平文本，信息保真度不足；流式压缩架构用固定预算的循环缓冲区不断压缩过去，长期细节被磨掉。更关键的是，几乎所有工作都把"记忆写入"当作固定的预处理步骤，**没有人认真优化"该写什么、以什么形式写"**。

MemLife 的核心洞察有两条：

- **写入格式本身就是检索接口**。如果写入时把实体名落地、以第一人称叙事、以时间锚定，未来查询与记忆之间的语义鸿沟会自然收窄。
- **只优化"写"，不优化"答"，就能显著提升 QA**。这是一步大胆的取舍：RL 不碰最终答案质量，只作用于 memory writer。

## 三、核心方法与创新点

### 3.1 MemLife 系统：episodic writer + time-indexed agentic reader

**Writer（写入端）** 采用三个设计，全部围绕"未来问题未知"这一约束：

- **多模态融合（Multimodal fusion）**：未来问题所需的证据可能出现在画面或语音任一侧，writer 联合解读帧序列与转写文本，把两侧证据合进同一条记忆条目。
- **实体落地（Entity grounding）**：转写里提到的实体名是未来 QA 的重要线索，writer 对齐语音与记忆片段，用识别出的名字指代视觉所指对象（例：把"食物处理器里的黄色颗粒"落实为"玉米粒"）。
- **第一人称叙事（First-person narration）**：第一人称视频的问题天然以"我"发问，记忆也用第一人称写，查询与记忆在人称上对齐。

技术上，每个 clip **独立**生成描述与 embedding——刻意避免顺序依赖与误差传播，让计算与存储随历史长度线性增长。论文还试过让 writer 依赖前序片段的文本/多模态上下文，聚合精度没有提升，因此保持独立写入。

**Reader（读取端）** 是一个 agentic 检索器：语义搜索 + **时间范围取数（time-scoped memory fetching）**，把检索到的情节按**时间顺序**组织后再推理。消融显示：时间锚定主要提升检索命中（recall），而时间排序主要提升对已检索证据的推理质量（accuracy），两者互补。若允许访问原视频，reader 可按需调用视频检索工具采样原始帧（MemLife-V 变体），但默认关闭。

### 3.2 MemOpt：只训练 writer 的强化学习

MemOpt 固定 reader，只更新 writer 参数 θ。其理论基础是一次干净的信息论分解。记问题与答案为 Q、A，视频历史为 𝒱，写出的记忆为 ℳ，reader 检索的上下文为 C_Q。联合分布可分解为：

p(Q, A, 𝒱, ℳ, C_Q) = p(Q, A, 𝒱) · p_θ(ℳ | 𝒱) · p(C_Q | Q, ℳ)

在只允许 reader 从 ℳ 取证据的约束下，用记忆上下文替代原视频带来的额外不确定性**恰好**分解为两项：

**H(A | Q, C_Q) − H(A | Q, 𝒱) = I(A; 𝒱 | Q, ℳ) + I(A; ℳ | Q, C_Q)**

- 第一项 Δ_inf 是**写入损失**：答案相关的信息在 𝒱 → ℳ 的压缩中丢了 → 对应 *informativeness* 奖励；
- 第二项 Δ_ret 是**召回损失**：信息在记忆里但没被检索到 → 对应 *retrievability* 奖励；
- 两项都不衡量 ℳ 是否忠于 𝒱，因此再加 *faithfulness* 奖励，直接对照源视频惩罚幻觉条目。

三者合成 **FIRM（Faithful, Informative, Retrievable Memories）** 奖励，用 GRPO 训练 writer，token 级 advantage 做组内归一化。特别的是 retrievability 的实现：通过**检索轨迹的收集与回放**近似"这条记忆未来被检索到的难易度"，让写入端感知检索端的失败模式。

## 四、实验结果与分析

评测覆盖四个长程基准：SuperMemory-VQA、EgoLifeQA，以及两个扩展设定——SuperMemory-LVQA（合并全部 10 个被试的历史、加入跨被试干扰项，扩大检索空间）和 EgoLife-EQA（对反复发生事件的问题，证据经人工核对）。writer/reader 统一用 Qwen3.5-9B（泛化性实验另测 Qwen3.6-27B）。指标为准确率（Accuracy）与证据召回率（Recall）。

几个要点：

- **免训练的 MemLife 已经大幅领先**：对最强免训练基线提升 4.6–12.0 个百分点，且四个基准的 recall 同步上涨——说明收益同时来自"写得更好"和"检得更准"。
- **MemOpt 再加 2.7–5.0 个百分点**，MemLife+MemOpt 较最强先验系统整体领先 4.0–17.0，同时记忆体积最多缩减 **31 倍**（附录 E）。
- **允许回看原视频（MemLife-V）只有边际收益**，证明增益不依赖查询时重访原始录像。
- **Oracle 上限仍有约 6–10 个点的差距**，说明记忆压缩与检索还有明确的改进空间。

消融实验（Table 4）显示组件贡献可分离：writer 侧，实体落地主要涨 accuracy（尤其 MemOpt 后），第一人称叙事则稳定提升 EgoLifeQA recall；reader 侧，时间锚定在优化后的记忆上收益最明显，时间排序进一步涨 accuracy。在 RelationMap 类问题上，EgoRAG 甚至在低 recall 下追平了优化后的 MemLife，说明"检索到标注证据"并不总是回答所需的全部——记忆还需保留实体间的关系结构。

## 五、与智能体认知模块的关联

MemLife 对智能体记忆研究的启发相当直接：

1. **记忆写入是一种可优化的策略，而非固定预处理。** FIRM 的三元奖励（忠实/信息量/可检索）等价于给"编码器"施加了面向未来任务的归纳偏置。这对任何长期记忆智能体（不只视频）都成立：**写入格式就是检索接口**。
2. **信息论分解给出了记忆系统的诊断坐标。** Δ_inf（写入损失）与 Δ_ret（召回损失）可分别度量、分别优化——做记忆系统的同学可以直接套用这个框架定位瓶颈。
3. **时间索引是长程记忆的一等结构。** 时间锚定管检索、时间排序管推理，与智能体"事件记忆 + 时间线"的认知架构高度一致；也和 MemLife 之前我们读过的"持久空间记忆需要时间索引信念"（EvolvingNav）形成呼应。
4. **"只优化写端"的杠杆效应。** 训练后的 writer 迁移到 EgoRAG 等其他记忆系统、其他 backbone 甚至域外视频/问题分布都持续有效——说明"学会记住什么"是一种可迁移的通用能力，而非对某个 pipeline 的过拟合。
5. **对上下文管理的启示。** 31 倍记忆压缩、线性增长、无顺序依赖误差传播，正是长程智能体在有限上下文窗口下维持数月记忆所需要的工程性质。

## 六、总结与启发

**亮点**：把"记忆写入"从工程细节提升为可学习的组件，并用一个信息论分解把写入损失与召回损失解耦——方法论干净，实验扎实（四个基准、两组基线、完整消融、跨 backbone/跨系统迁移验证）。免训练版本就有强竞争力，训练版本进一步拉开差距且记忆更小。

**不足**：Oracle 上限显示仍有明显天花板；RelationMap 类关系型问题上召回高不等于答对，记忆中的关系结构建模仍是未解问题；评测集中在第一人称生活场景，向更通用的智能体长期记忆外推仍需验证。

**启发**：对做智能体记忆的同学，这篇最值得抄的是两件事——**(1) 给 memory writer 设计面向未来查询的奖励（忠实/信息量/可检索）并用 RL 训练它；(2) 用 Δ_inf / Δ_ret 分解诊断记忆系统瓶颈**。当智能体需要在数月尺度上记住工具使用历史、任务经验、用户偏好时，"写什么"和"怎么写"可能比"用多大的向量库"重要得多。
