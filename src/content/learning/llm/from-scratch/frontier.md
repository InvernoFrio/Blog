## 先确定能知道什么

这一章的资料核对时间是 **2026-10-08**。选择公开信息有代表性的近期模型来研究，并不宣布它们在所有任务上排名第一。架构报告能解释计算方法，系统卡常更关注数据概述与行为评估，产品发布页则更侧重结果。

阅读时把笔记分成“明确披露”“根据数学推导”“尚未披露”。本文的小实验是完整可运行的；以下企业案例是公开资料分析。参数、数据、集群和后训练配方缺任何一项，都不能据此宣称完整复现。

## 先用自己的小实验理解企业训练阶段

下面是一条用于阅读报告的通用流程，不表示每家企业都按同样顺序或采用同样配方。

首先固定数据定义。一个训练 token 到底是文本子词、图像片段还是其他表示，决定预算中的单位。去重、来源混合和留出评估发生在模型更新之前，却已经在决定模型会学什么。看到“更多 token”，应继续问是否更独立、更多样，还是重复处理同一来源。

其次建立小规模可验证实现。企业系统即使很大，也要先确保目标、因果性、梯度缩放和恢复语义正确。本实验的数学检查与连续/恢复对照对应的就是这一层问题；它们能证明链路正确，不能预测大规模质量。

然后才是资源与规模选择。参数、token、上下文和数据比例共同影响质量，精度与并行决定能否在预算内训练。报告若只给峰值硬件性能，我们还不能算出实际训练时间；需要有效吞吐、总计算与非训练开销的口径。

预训练检查点之后，SFT、偏好学习、RL 或蒸馏可能进一步改变输出行为。每个阶段的输入数据、优化状态和评估目标应重新辨认。训练 rollout 的工具环境与部署时的工具环境若不同，跨环境泛化也应独立测量。

最后，模型与推理系统一起决定用户看到的结果。采样、推理预算、缓存、检索和工具框架都能改变表现。比较发布结果时，先确认是基础模型比较、后训练模型比较，还是整套 agent 系统比较。

## DeepSeek V4.1：把训练与部署成本共同设计

[DeepSeek-V4.1-Flash 技术报告](https://arxiv.org/html/2609.19969v1)于 2026 年 9 月公开，报告了 Causal Encoder–Decoder、稀疏压缩 Attention 与跨层 KV 复用。其骨干总参数为 552B，prefill 与 decode 的激活参数分别为 8B、16B。

报告披露使用 45T 多模态 token 预训练；线性矩阵使用 Muon，非矩阵参数使用 AdamW，embedding 和输出头使用专门的平衡更新。后训练包含 agent 任务、异步生成与多教师 on-policy 蒸馏。其 FP4 描述针对主要 KV cache，不能据此说全部训练是 FP4。（对应报告第 2、4、5 节。）

把这些信息放回我们已经学过的框架，可以提出三个研究问题：

1. **同样预测下一个 token，为什么可以改变网络？** 自回归因子分解约束信息流，不强制只有一种 Decoder 结构。因果 encoder–decoder 仍要保持正确的可见性。应读清 prefill 与 decode 分别计算哪些层、读哪些状态。
2. **为什么不同参数使用不同优化器？** 本实验统一 AdamW，便于验证。矩阵的谱结构、embedding 行列频率与标量参数可能有不同需求。替换优化器需要比较更新尺度、稳定性和训练结果；名称新并不构成优越性的证明。
3. **为什么缓存设计会影响训练？** 模型训练要适应部署时的表示和可见信息。把稠密模型训练完后直接删除大部分缓存，通常不是等价操作；架构、训练与部署需要联合考虑。

以上三点是本文的分析与学习方向，不能替代报告里的消融实验。

## Muon 的数学入口

一种理解方式是先构造矩阵动量 $M_t$，再对它做近似正交化。若 $M=U\Sigma V^T$，理想化的极分解方向是 $UV^T$，实际算法常以迭代近似避免昂贵的完整 SVD。

与 Adam 对每个元素用二阶矩缩放相比，这种方向处理利用矩阵结构。完整实现还涉及尺度校正、形状处理、weight decay 与分布式同步。这个概念解释为什么“换优化器”不是把学习率调小一点；它也不意味着能直接把企业的超参数搬到 120K 模型。

练习：取对角矩阵 $M=\operatorname{diag}(10,1)$。其极分解正交因子是单位阵；比较两个方向的奇异值。再思考：抹平奇异值对一步更新的尺度有什么影响，为什么还需要校正整体大小？

## 矩阵方向的算例到底说明了什么

对角动量 $M=\operatorname{diag}(10,1)$ 的 SVD 可取 $U=V=I$、$\Sigma=\operatorname{diag}(10,1)$。理想化方向 $UV^T=I$ 把原来 10:1 的奇异值变成 1:1，改变的不是一个统一学习率，而是不同矩阵方向的相对尺度。

原矩阵 Frobenius 范数为 $\sqrt{101}\approx10.05$，正交因子的范数为 $\sqrt2\approx1.414$。即使方向处理有意义，整体更新大小也已经变了，因此还需要按形状和实现定义尺度校正。实际迭代近似未必得到严格的 $UV^T$，不能把理想算例当成生产实现的逐元素输出。

长方形矩阵还要区分行正交和列正交，秩不足时也有边界问题。这里的二维满秩算例只是数学入口。读优化器报告时，应确认哪些参数采用哪种处理、更新尺度怎样匹配、哪些消融隔离了优化器与数据变化。

## Qwen 3.7：扩展的是训练环境

[Qwen3.7 官方说明](https://github.com/AlibabaCloud-Official/Qwen3.7-max-readme/blob/main/README.md)强调在之前的路线之上扩大 agent 训练环境的质量和多样性，并关注长程执行与不同 agent 框架中的泛化。这里只采用其公开方向，不推测未公布的完整预训练规模、硬件账单或奖励权重。

从训练目标看，普通文本建模的样本是 token 序列；agent RL 的样本是带环境反馈的轨迹：

$$
\tau=(s_0,a_0,o_1,s_1,a_1,\ldots),\qquad
J(\theta)=\mathbb E_{\tau\sim\pi_\theta,\mathcal E}[R(\tau)].
$$

$\mathcal E$ 是环境分布，$o$ 是工具或环境返回的观察。增加环境类型，会改变模型能遇到的状态、行动与奖励，也改变泛化问题。只增加同类轨迹数量与增加环境多样性，应该分开比较。

一个可做的小项目是创建计算器、文件整理、代码修复三类环境，统一记录观察、动作、退出条件、预算和成功判定；留出未训练环境做测试。先只收集和评估轨迹，再加入策略更新，避免把 agent scaffolding 的改进误记为模型训练提升。

## Claude Opus 5.5：公开概述与未知边界

[Anthropic 透明度页面](https://www.anthropic.com/transparency)说明 2026 年 9 月发布的 Opus 5.5 先在多样数据上预训练，再接受大量后训练；数据概述包含公开、私有、用户与合成数据，并提到去重和分类等清理方法。它没有在这一概述中给出足以完整重建训练的参数规模、逐来源配比或优化器配方。

因此能得出的结论是训练阶段和数据类别的公开概述；不能把通用的 MoE、GRPO 或 Muon 方法直接写成该模型已采用的事实。产品行为也不足以反推出模型究竟用了哪种架构。

这类系统卡值得学习另一件事：验收除了能力，还需要检查诚实性、可靠性和长任务表现。我们的验证 loss 是训练仪表；部署评估则应包含真实使用场景，两者回答不同问题。

## 异步后训练的系统推导

假设 rollout 服务每秒完成 $\lambda$ 个样本，训练每次消耗 $B$ 个样本且耗时 $t_u$。若 $\lambda<B/t_u$，训练器容易等待；反之样本队列增长，策略版本滞后会加大。实际还有长尾、资源共用和动态任务比例，不能只靠平均速率控制。

把每个样本的旧策略 log-prob、策略版本、奖励与有效长度一起存储，才能做重要性比率和过期判断。优先收集短轨迹可能改变长度分布，即使 reward 公式不变，实际训练目标也会偏移。

这段队列分析是通用推导。研究具体企业系统时，应检查它的调度粒度、模型更新边界、样本保留规则和专家路由状态，再判断它解决了哪种偏差。

## 一次性能提升，怎样判断因果解释是否成立

假设一份报告同时换了 tokenizer、数据配比、Attention 和 optimizer，验证 loss 与任务成功率都提高。它可以支持“整套方案在这个评估设定下更好”，却不能单独证明“提高来自某个 optimizer”。原因是多个因素一起改变了，缺少控制变量。

更有解释力的证据是单项消融：其他条件尽量固定，只修改一个因素；再补重复种子与等预算比较。即使这样，也需要写清固定的是 token、step 还是 FLOPs，因为更贵的结构可能只是看到了更多计算。

Agent 评估还要固定工具、可执行权限、超时、尝试次数和完成判定。如果新系统每题尝试十次，旧系统只尝试一次，成功率变化同时包含了推理预算变化。隐藏测试和未见环境可以检查是否只适应了公开任务，但不能自动排除所有污染。

阅读时可写一句有边界的结论：“在文中披露的预算与任务条件下，这个组合方案达到某结果；该单项机制的贡献需要看对应消融。”这样既能学习有效设计，也不把未知部分补成确定配方。

| --- | --- | --- |
