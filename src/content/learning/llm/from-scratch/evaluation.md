## 为什么生成漂亮的句子不能替代验证

一次生成包含随机性，容易挑出好看的样本。验证损失遍历固定样本，衡量正确下一个 token 的概率，是更稳定的训练信号。但它仍不是事实正确性、数学推理或工具使用的充分证明。

小语料上的 loss 改善可能主要来自标点、拼写和重复模式。随附资料只有 32 篇短文，我们不能用它的验证 PPL 宣称获得专业知识。真正的能力评估应使用未参与训练和调参的任务集，并检查污染与来源重合。

验证函数使用 `model.eval()` 与 `torch.no_grad()`。前者改变 dropout 的行为，后者关闭梯度图；两者作用不同。完成验证后恢复训练模式，避免后续训练悄悄失去 dropout。

## 温度怎样改变条件分布

对于 logits $z$，温度 $\tau>0$ 的采样概率是：

$$
p_i(\tau)=\frac{\exp(z_i/\tau)}{\sum_j\exp(z_j/\tau)}.
$$

$\tau$ 接近零时趋向最大分数；增大时分布更平。例子：分数 $(2,1)$ 在 $\tau=1$ 时约为 $(0.731,0.269)$，在 $\tau=0.5$ 时约为 $(0.881,0.119)$。温度不是训练能力的提升，它只改变从同一模型中选 token 的方式。

top-k 只保留分数最高的 k 项，再归一化；top-p 按概率排序，保留累计概率达到阈值的最小集合。实验实现 top-k，不实现 top-p。生成时禁用 BOS 与 PAD，允许 EOS 结束。

```bash
python minillm.py generate --checkpoint runs/base/last.pt --prompt "Learning " --temperature 0.8 --top-k 40 --seed 17
python minillm.py generate --checkpoint runs/base/last.pt --prompt "Learning " --temperature 0.5 --top-k 10 --seed 17
```

使用同一提示词与种子比较策略，同时保留全部输出。不要只选最顺畅的一次作为能力证据。

## top-k 与 top-p：用四项分布看差别

假设模型概率从高到低为 $(0.5,0.25,0.15,0.1)$。top-k 取 $k=2$ 时，只保留前两项，总质量为 0.75，再归一化为 $(2/3,1/3,0,0)$。它固定候选数量，不关心这两项一共覆盖多少概率。

top-p 取阈值 0.8 时，前两项累计只有 0.75，不够；加上第三项达到 0.9，因此保留三项，再归一化为 $(5/9,5/18,1/6,0)$。对于非常集中的分布，top-p 可能只保留一项；对于较平的分布，可能保留很多项。

本脚本按第 k 大分数作为阈值遮住更低项。如果阈值处有并列分数，保留数量可能超过 k；例如所有 logits 相同，仅按阈值就无法只选出 k 个。常见的 top-k 概念与具体实现的平局规则要分开理解。

温度、禁用特殊 token、截断候选集合的执行顺序也应记录。温度为正时不改变分数排序，但它改变概率，因而会影响 top-p 的保留集合。生成 seed 固定能方便复查一条结果，却不能代表采样结果的完整分布。

## 字节模型的输出为什么有乱码

一个 UTF-8 字符可能跨多个 token。采样可能产生非法字节组合，或在字符中间达到最大长度。实验用 `errors="replace"` 解码，因此可能出现替代字符 `�`。这暴露了基线的限制，不能靠显示时隐藏字符解决模型问题。

升级为子词分词器能改善序列效率与解码结构，但还要正确处理特殊 token、边界和 tokenizer 版本。也可以实现 UTF-8 有效前缀约束，但那是新的解码策略，应单独记录。

## KV cache 省去哪些重复工作

朴素生成每次对整个前缀重新做前向。因果 Attention 中旧 token 的 K/V 不依赖未来，可以缓存；新 token 只产生自己的 Q/K/V，再读取旧缓存。

普通多头的缓存大小近似为：

$$
\mathrm{bytes}_{KV}=2\,B\,L\,T\,H_{kv}\,d_h\,s,
$$

$L$ 是层数，$s$ 是每元素字节数，系数 2 对应 K 与 V。GQA 减小 $H_{kv}$，缓存压缩与低精度也能改变成本。注意训练激活和推理 KV cache 是不同的存储对象。

当前脚本重新计算最后 64 个 token，不实现 KV cache。加入缓存时要处理绝对位置、截窗、每层状态、batch 中已结束样本，并与不缓存的 logits 比较。先验证正确，再测加速。

## KV cache 的正确性与一个显存算例

因果网络中，旧位置的隐藏状态只依赖当时的前缀，新 token 加入后不会改变旧位置，所以可以复用它们在每一层产生的 K/V。当前 token 仍然要经过所有层，各层的新 query 读取各自缓存；不是缓存一次全模型最终向量就能代替全部计算。

假设 batch 为 1、32 层、上下文 4096、8 个 KV 头、每头 128 维、每元素 2 字节。代入公式得到 $2\times1\times32\times4096\times8\times128\times2=536870912$ 字节，即 512 MiB。若 KV 头改为 32，在其他条件相同时变为 2 GiB。这仅是 K/V 元素，不含模型权重、临时缓冲和分配开销。

实现缓存时，位置编号必须与不缓存版本一致。对于本实验的可学习位置表，截掉最早 token 并把剩余位置重新从零编号，会改变它们的位置 embedding，旧 K/V 也就不能原样继续复用。这是基线滑动窗口与缓存衔接时的实质问题，不能只加一个 `past_key_values` 参数就宣称等价。

最小正确性检查是在窗口尚未溢出、关闭 dropout 时，用相同前缀比较“完整重算的最后位置 logits”与“逐 token 缓存版本 logits”。先检查多个长度和每层缓存 shape，最后再测速度；性能收益建立在相同预测语义上。

## 概率指标与任务指标为什么可能分歧

假设两个模型对真实目标的概率分别为 0.51 和 0.9，且真实项都是最大概率项。它们的 argmax 正确率相同，但交叉熵分别约为 0.673 和 0.105。反过来，一个模型可能更准确预测常见标点，使平均 loss 降低，却仍然不会回答某个稀有专业问题。

因此要同时保留概率验证和任务评估。前者检查大量 token 的概率分配，后者定义用户关心的完成标准。最终测试集应在方案选择之后再使用；如果反复根据测试分数改模型，它就承担了验证集的角色，再报这个分数会高估对新任务的泛化。

## 建立最小评估表

| 维度 | 本实验怎么检查 | 扩大规模后的补充 |
| --- | --- | --- |
| 数学与因果性 | 手推梯度、未来扰动测试 | 多精度、缓存与分片对照 |
| 概率预测 | 固定验证集的 loss、PPL | 多来源、长文本与时间留出 |
| 输出行为 | 固定提示与多种采样 | 标准任务、人工盲评、多随机种子 |
| 数据隔离 | 文档级切分、精确去重 | 近重复、评测污染、来源审计 |

练习：两个验证批次分别有 10、90 个 token，loss 分别为 2、4。合并结果应为 3.8，PPL 为 $e^{3.8}$；先平均两个批次的 PPL 也不正确。
