## 这次要亲手完成什么

从随机参数出发，训练一个能预测下一个 token 的小型语言模型。自己准备数据，计算损失，更新参数，检查验证集，保存状态，继续训练，最后生成文本。完成这条链后，再研究大模型怎样扩展它。

实践模型是两层 Decoder Transformer，默认只有 **120,768 个独立参数**。它使用 UTF-8 字节词表、Pre-LayerNorm、手写因果 Attention、GELU 和共享输入输出权重。这个规模适合普通 CPU 上检查数学与工程关系；随附的 32 篇原创短文用于实验，不足以训练出可用的通用助手。

“从零”指预训练不加载已有权重。后面的 SFT 实验加载我们自己训练的检查点，演示训练阶段的衔接。企业案例则研究公开报告，无法据此复现一家公司的完整数据和集群。

## 把整条训练链放在一个例子里

以原文 `AB` 为例。字节编码把它变成 `[65,66]`，加入起止标记得到 `[256,65,66,257]`。训练输入取前三项，标签取后三项：模型先根据 BOS 预测 A，再根据 BOS、A 预测 B，最后根据 BOS、A、B 预测 EOS。

Embedding 把三个输入 ID 各变成 64 维向量，位置表告诉模型它们位于哪里。Transformer 在合法前缀内混合信息，最终为每个位置输出 259 个 logits。交叉熵只取对应真实标签的对数概率，求平均后得到一个标量 loss。

反向传播从这个标量出发，求出每个参数的梯度。AdamW 使用梯度和自身历史状态更新参数。下一轮再输入同样或不同的文本，预测概率就可能改变。训练后的生成则没有现成标签：模型产生 A 后，必须把 A 放进前缀，才能决定下一项。

这里有三类不同的数字：token ID 是离散索引，隐藏向量是连续表示，logits 是候选项分数。ID 66 并不比 ID 65“多懂一点”，64 维隐藏向量也不是 64 个候选词的概率。只有经过输出头与 Softmax 后，才得到词表上的分布。先分清这些对象，后面的张量形状会容易理解很多。

## 每章怎么读，才不会只记住术语

第一遍先回答“这一步在解决什么问题”。例如移位标签解决预测对象，因果遮罩解决可读取的信息，loss 的分母解决样本权重。它们都影响训练，但作用不同，不能靠一个笼统的“mask”概念带过。

第二遍拿小数字算。一个三分类预测、一个两位置 Attention，足以暴露许多概念错误；不要一开始就用巨大的 batch，让错误藏在复杂 shape 里。第三遍读代码，指出哪一行对应刚才的数学。最后做一次有明确预期的改动，先写下自己预计会发生什么，再运行实验。

正文中的练习附有解答，建议先遮住解答自己做。做错时回到造成分歧的那一步，而不是重新背最终公式。[逐步算例](../worked-examples/)用于串联多个模块，[数学工具箱](../math-toolbox/)用于补查求导、期望和误差，不必在开始之前一次学完。

可以把学习记录写成四句：输入是什么，输出是什么，改变哪一个量会怎样影响输出，怎样检查我的实现。这比只记录“学了 Attention、AdamW、DPO”更能说明自己掌握了什么。

## 下载与第一轮实验

下载 [完整实验包](../../../../learning/llm-from-scratch/llm-from-scratch.zip)，解压并进入其中的目录。Python 建议 3.10–3.13；CPU 环境固定 PyTorch 2.8.0，便于复查。终端中的 `python` 应指向你创建的实验环境：

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS / Linux:
# source .venv/bin/activate
python -m pip install -r requirements-cpu.txt
python math_checks.py
python smoke_test.py
python minillm.py train --out runs/base --steps 200
python minillm.py generate --checkpoint runs/base/last.pt --prompt "Learning "
```

若 PowerShell 的脚本策略不允许激活，可以直接用 `.venv\Scripts\python.exe` 替换命令中的 `python`。CPU 依赖文件仅供 CPU 实验；GPU 环境按 [PyTorch 官方安装入口](https://pytorch.org/get-started/locally/)选择与驱动兼容的版本。

## 三种成果要分别检查

数学成果是手推梯度与自动求导一致；工程成果是训练、验证和恢复状态正确；模型成果是对未见数据的能力改善。前两项通过，不自动意味着第三项达到实用水平。

每章都有一个可检查的问题，最后的实验页提供完整验收标准。读论文时也沿用这三个维度：公式改变了什么，系统怎样实现，哪些评估证明它有效。
