## 为什么需要在位置之间传递信息

Embedding 将每个 token 变成向量，但单独查表只知道这个 token 本身。“苹果很好吃”和“苹果发布新品”中的“苹果”需要结合上下文理解。Attention 的作用是：让当前位置根据自己的状态，从可访问的其他位置读取信息，形成新的表示。

每个位置有三种投影。Query（Q）用于表达当前位置怎样寻找信息，Key（K）用于与 query 匹配，Value（V）提供实际被读取的内容。可以借用“检索条件、索引、内容”的直觉，但它们都是训练出来的向量，不是人工指定的关键词，也不保证每个维度具有可命名的语义。

为什么分开 K 和 V？用于判断“是否相关”的特征，不必与希望传递的内容相同。为什么还要 Q？不同当前位置可以用不同的状态寻找信息。三个向量来自相同输入，但使用不同的可学习线性变换。

## 一个头的前向：匹配、归一化、读取

暂时省略 batch 和头数。输入 $X$ 是 $[T,d]$，$T$ 为序列长度。计算 $Q=XW_Q$、$K=XW_K$、$V=XW_V$；$Q,K$ 形状为 $[T,d_h]$，$V$ 为 $[T,d_v]$。实验还使用 bias，这里先省略以突出结构。

第一步匹配：第 $i$ 个 query 与第 $j$ 个 key 的点积是 $\sum_a Q_{ia}K_{ja}$。把所有位置一起计算，就是 $QK^T$，形状为 $[T,T]$。**行是正在读取信息的位置，列是被读取的位置。**

第二步归一化：对每一行做 Softmax，得到该 query 分配给各个 key 的权重。第三步读取：用权重对 value 向量加权求和。因此：

$$
S=\frac{QK^T}{\sqrt{d_h}}+M,\qquad
P_{ij}=\frac{e^{S_{ij}}}{\sum_k e^{S_{ik}}},\qquad
O_i=\sum_jP_{ij}V_j.
$$

$P$ 的每行在没有 dropout 时相加为 1，所以 $O_i$ 是可访问 value 的加权组合。分数相近时，输出混合多处信息；某一项明显较大时，输出更接近该项的 value。后面的输出投影和残差还会继续变换这个结果。

## 因果遮罩为什么允许读取当前位置

语言模型用位置 $i$ 的表示预测下一项 $x_{i+1}$，输入 $x_i$ 已经属于已知前缀。因此这个位置允许读取 $j\le i$ 的输入，不能读取 $j>i$。对四个位置，遮罩结构如下：

| query / key | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| 0 | 允许 | 遮住 | 遮住 | 遮住 |
| 1 | 允许 | 允许 | 遮住 | 遮住 |
| 2 | 允许 | 允许 | 允许 | 遮住 |
| 3 | 允许 | 允许 | 允许 | 允许 |

在 $M$ 中，“允许”填 0，“遮住”填 $-\infty$。Softmax 后 $e^{-\infty}=0$，被遮住的位置不会参与 value 的加权。遮罩必须在 Softmax 之前加；先 Softmax 再简单清零，会使每行不再是对允许位置归一化的正确分布。

两处机制共同保证任务正确：标签向后移一位，因果遮罩阻止读取那个真实目标。只做标签移位而没有遮罩，模型可能直接看见下一位置答案；只做遮罩而标签不移位，模型又可能学复制当前位置。

## 手算两位置的完整前向

取一个标量头，$d_h=d_v=1$，$Q=(1,2)^T$、$K=(1,0)^T$、$V=(3,5)^T$。因为 $\sqrt{d_h}=1$，未遮罩分数为：

$$
QK^T=\begin{bmatrix}1&0\\2&0\end{bmatrix},\qquad
S=\begin{bmatrix}1&-\infty\\2&0\end{bmatrix}.
$$

第一行只能看自己，Softmax 是 $(1,0)$。第二行有两个允许位置，其概率是 $a=e^2/(e^2+1)\approx0.880797$、$b=1/(e^2+1)\approx0.119203$。于是：

$$
P=\begin{bmatrix}1&0\\a&b\end{bmatrix},\qquad
O=\begin{bmatrix}3\\3a+5b\end{bmatrix}
\approx\begin{bmatrix}3\\3.238406\end{bmatrix}.
$$

第二个输出不是更相似的 key 本身，而是两个 **value** 的加权结果。这能帮助区分 Q/K 的匹配用途与 V 的内容用途。第一行只有一个候选位置，无论它的允许分数怎样变化，概率都是 1。

## 为什么除以根号下的头维度

若 query、key 的各维近似独立，均值为零、方差为 1，则一个乘积 $q_ak_a$ 的均值为零、方差为 1。再假设不同维度乘积之间不相关，$d_h$ 项之和的方差就是 $d_h$，标准差为 $\sqrt{d_h}$。

维度越多，原始点积越容易产生很大的正负差值。Softmax 可能在初始化时就过度集中，使训练不好调。除以 $\sqrt{d_h}$ 后，按照上述近似，分数方差回到 1。这是初始化附近的尺度解释，不是说训练中每一层都严格服从这些独立性假设。

请区分模型宽度 $d$ 与一个头的维度 $d_h$。缩放用后者，因为一次点积只在一个头内求和。

## 从单头到多头：逐步读懂形状变化

默认模型 $d=64$、$H=4$，所以 $d_h=16$。以 $B=2,T=5$ 为例，输入为 $[2,5,64]$。一次线性层输出 $[2,5,192]$，表示每个位置的 Q、K、V 三组 64 维向量。

实验先把最后一维拆成 `3 × H × d_h`，再把轴调整为“QKV 类别、batch、头、位置、头内特征”。取出 Q/K/V 后，各自形状是 $[2,4,5,16]$。矩阵乘法只作用在最后两个轴，batch 与头互不混合：

| 运算 | 形状 |
| --- | --- |
| Q 与转置后的 K 相乘 | $[2,4,5,16]\times[2,4,16,5]\to[2,4,5,5]$ |
| Softmax | 最后一轴归一化，仍为 $[2,4,5,5]$ |
| P 与 V 相乘 | $[2,4,5,5]\times[2,4,5,16]\to[2,4,5,16]$ |
| 交换头与位置轴 | $[2,5,4,16]$ |
| 拼接头内特征 | $[2,5,64]$ |
| 输出线性投影 | $[2,5,64]$ |

拼接是把同一位置不同头的特征放到一起，不是在时间轴拼接。输出投影允许模型进一步混合这些头。多个头提供不同的可学习信息通道，但并没有事先指定“某头学语法、某头学事实”。

转置后的张量可能不连续，实验用 `.contiguous().view(...)` 拼头。shape 正确不保证元素排列正确，所以还应拿小输入与逐头参考实现比较。

## 用最小代码复现刚才的手算

```python
import torch

q = torch.tensor([[1.0], [2.0]], dtype=torch.float64)
k = torch.tensor([[1.0], [0.0]], dtype=torch.float64)
v = torch.tensor([[3.0], [5.0]], dtype=torch.float64)
allowed = torch.ones(2, 2, dtype=torch.bool).tril()
scores = (q @ k.T).masked_fill(~allowed, float("-inf"))
p = scores.softmax(dim=-1)
out = p @ v
print(p)
print(out)
```

输出应接近前面的 $P$ 与 $O$。随后可把头维度增大，并补上 `/ q.shape[-1] ** 0.5`。这个小算例刻意没有投影层、batch 和 dropout，让我们先检查 Attention 本身，再加工程细节。

## 反向第一步：加权结果怎样影响 P 与 V

忽略 dropout，令上游梯度 $G=\partial L/\partial O$。由 $O=PV$，直接应用矩阵乘法反向：

$$
dV=P^TG,\qquad dP=GV^T.
$$

为什么 $dV$ 要对 query 位置求和？同一 $V_j$ 可以被多个位置读取，所以所有读者的贡献加在一起。为什么 $dP_{ij}$ 是 $G_i$ 与 $V_j$ 的内积？稍微提高这个权重，$O_i$ 就会沿着 $V_j$ 的方向变化。

继续使用两位置例子，临时令 $L=O_1+O_2$，所以 $G=(1,1)^T$。得到 $dV=(1+a,b)^T\approx(1.880797,0.119203)^T$，以及 $dP$ 的每行都是 $(3,5)$。这仍不是分数 $S$ 的梯度，因为权重由 Softmax 耦合产生，不能把两项权重当成独立参数。

## 反向第二步：Softmax 为什么要减加权平均

对一行概率，有 $\partial P_j/\partial S_k=P_j(\mathbf1[j=k]-P_k)$。设该行上游梯度为 $D_j$，链式法则要对全部概率项求和：

$$
\frac{\partial L}{\partial S_k}
=\sum_j D_jP_j(\mathbf1[j=k]-P_k)
=P_k\left(D_k-\sum_j P_jD_j\right).
$$

也就是矩阵逐行公式：

$$
dS_{ij}=P_{ij}\left(dP_{ij}-\sum_kP_{ik}dP_{ik}\right).
$$

减去加权平均是因为增大一个分数不只提高自己的概率，还会降低同一行其他概率。公式综合了这些影响，不能只保留 $P_{ij}dP_{ij}$。

例子中第一行只有一个有效概率，$dS$ 为 $(0,0)$。第二行的加权平均为 $3a+5b$，得到 $dS_{21}=-2ab\approx-0.209987$、$dS_{22}=2ab\approx0.209987$。提高第二个分数会增加 value 为 5 的权重，从而增加我们临时定义的 $L$，所以导数为正；梯度下降会朝相反方向更新。

## 反向第三步：回到 Q、K 与投影参数

分数来自 $QK^T/\sqrt{d_h}$，再次应用线性代数反向：

$$
dQ=\frac{dSK}{\sqrt{d_h}},\qquad
dK=\frac{dS^TQ}{\sqrt{d_h}}.
$$

两位置算例给出 $dQ\approx(0,-0.209987)^T$，$dK\approx(-0.419974,0.419974)^T$。Q/K/V 都由同一输入投影，因此输入梯度还要合并三条路径：$dX=dQW_Q^T+dKW_K^T+dVW_V^T$，投影参数梯度则各用上一章的公式。

被遮住的概率为零，对应的分数梯度也为零。在实现手写反向时，应明确让被遮住的项为零，而不是依赖可能出现的无效浮点运算。`math_checks.py` 比较 $dQ,dK,dV$ 与自动求导，并对一个 query 分量做中心差分。

训练代码在 Softmax 后使用 attention dropout：保留项乘 $1/(1-p)$，丢弃项变零。因此一次随机前向中的权重行和未必为 1，只是缩放保持了元素的期望。反向先经过同一张 dropout 遮罩，再使用原始 Softmax 概率求导；不能将丢弃后的权重直接代进 Softmax Jacobian。

## 已知整段答案，为何仍然可以正确训练

Teacher forcing 使用真实文本构造每个位置的前缀。虽然整个输入张量包含后续 token，但因果遮罩阻止它们流向较早位置，逐 token LayerNorm 和 MLP 也不跨时间读取信息。因此所有位置可以并行计算，数学上仍是各自基于前缀预测下一项。

生成时下一项不存在，必须依次生成。训练使用真实前缀，生成使用自己生成的前缀；错误可能改变后续输入分布，所以低验证 loss 并不保证长文本生成不会走偏。

PAD 也要结合信息流理解。本实验仅右侧补齐，真实位置不能看见尾部 PAD，PAD 标签不计损失。如果改成左 padding 或其他遮罩，必须重新检查访问规则。每个有效 query 至少要有一个允许的 key；整行都为 $-\infty$ 会使 Softmax 无法正常归一化，产生 NaN。

## 如何检查因果性，而不只检查遮罩存在

在 `model.eval()` 下输入 `[BOS,A,B,C,D]`，再只把 C、D 换掉。B 及之前的 logits 应保持一致，因为它们的合法前缀没有改变。较后位置可以改变，不要求所有输出相同。

`smoke_test.py` 对整张网络做这个测试，能检查遮罩方向、位置处理和其他模块是否泄漏未来。先关闭 dropout，否则不同随机遮罩本身就能让前面输出改变，无法把差异归因于未来输入。

## 性能边界与练习解答

显式分数和概率矩阵含 $BHT^2$ 个元素，序列长度翻倍时，这部分元素数变为四倍。FlashAttention 通过分块、重算与在线 Softmax 减少内存读写，避免完整概率矩阵常驻高带宽内存；它仍计算稠密 Attention，不能据此把稠密计算量说成线性。进阶对照[算子专题的在线 Attention](../../../ai-infra/operators/fusion-attention/)。

**练习一。** 为什么 `softmax(dim=-1)` 不能改成 query 轴？每个 query 需要在自己可访问的 key 之间分配权重；跨 query 归一化会变成“多个读者对一个 key 分配比例”，改变运算含义，且可能让较早输出依赖较后 query。

**练习二。** 第一行只有一个允许位置，为什么 Q/K 的分数梯度为零，V 的梯度却可以非零？概率恒为 1，不依赖允许分数；但输出就是该 value，改变 value 会改变输出。这也说明不能把匹配分支和内容分支混为一条路径。

**练习三。** 为什么多头不是减少总模型宽度？每个头只有 $d/H$ 维，但最后把 $H$ 个头拼回 $d$ 维。多个头各有一个 $T\times T$ 权重矩阵，显式实现的概率矩阵开销反而含有头数 $H$。

原始结构见 [Attention Is All You Need](https://arxiv.org/abs/1706.03762)，内存高效实现见 [FlashAttention](https://arxiv.org/abs/2205.14135)。先把这里的输出和梯度算对，再比较 kernel 的速度与显存。
