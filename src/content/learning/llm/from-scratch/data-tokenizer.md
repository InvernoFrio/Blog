## 文本到 token 是一个建模决定

本实验把 UTF-8 编码的每个字节作为 token，ID 为 0–255；BOS、EOS、PAD 分别为 256、257、258。无需训练分词器，无未知字符，编码完全可逆。代价是序列较长：多数常用汉字有三个字节，一个 token 可能只是字符的一部分。

现代子词分词器用更大的词表换更短的序列。BPE 可以从字节开始，反复统计相邻对，合并最常见的一对，并保存合并规则。例如训练串 `a b a b a` 中 `a b` 出现两次，先合并为 `ab ab a`。应用到新文本时使用已学规则；不能临时重新统计测试文本来改变词表。

这个小模型先用字节词表，是为了把训练过程做完整。升级时应在训练语料上学习分词器，固定版本与特殊 token，并重新计算 embedding、输出头、上下文长度和吞吐。替换词表后，原有检查点通常不能直接加载。

## 先分文档，再制作窗口

随附 `demo.jsonl` 每行是 `{"text":"..."}`。`load_documents` 做 NFC 归一化、去首尾空白和精确去重；`split_documents` 使用固定种子，将约 20% 的独立文档作为验证集。

如果先把一篇长文章切为窗口，再随机把窗口分到训练和验证，它们可能共享大量原文。验证 loss 会因此过于乐观。生产语料还需要近似去重、来源分组或时间切分，以及评测题污染检查；本实验的精确去重没有完成这些工作。

原文件 SHA-256 被保存在检查点里。即使只修改空白，哈希也会变；续训会拒绝不同文件，防止无意改变实验条件。归一化后的内容相同与原始文件相同是两种不同的判断。

## 标签移动一位到底是什么

对于序列 `[BOS, A, B, EOS]`：

```text
输入 x:  BOS    A      B
标签 y:  A      B      EOS
```

位置 $t$ 的隐状态只能读取 $x_{\le t}$，监督它预测下一项 $x_{t+1}$。如果输入和标签完全相同，模型会学习复制当前位置，损失可能很漂亮，却无法证明 next-token 预测成立。

窗口长度为 $T$ 时，读取 $T+1$ 个 token，前 $T$ 个作输入，后 $T$ 个作标签。实验以步幅 $T$ 切窗，边界有一个 token 作为下一窗口的输入，因此每个目标恰监督一次。下一窗口没有更早的历史；这是一种明确的短上下文近似。

## PAD 与 EOS 为什么不同

EOS 是需要学习的目标，告诉模型一篇文档或一段回答可以结束。PAD 只是补齐批次，输入用 PAD ID，标签用 `-100`，被 `ignore_index=-100` 排除。

```python
loss_sum = F.cross_entropy(
    logits.flatten(0, 1), labels.flatten(),
    ignore_index=-100, reduction="sum",
)
count = (labels != -100).sum()
loss = loss_sum / count
```

本实验只有右侧 padding，加上因果遮罩，真实 token 不能看到尾部 PAD，因此不必再为这些有效位置遮住 PAD。改成左侧 padding、双向注意力或多文档 packing 后，这个推理不再适用。

本实验一条窗口只属于一篇文档。生产环境为了减少 padding 会 packing 多篇文档，需要同时确定文档间是否允许注意力，以及 position ID 是否重置；加入 EOS 并不自动阻断注意力。

## 可检查的实践

用 `make_windows([{"text":"AB"}], 5)` 查看结果。输入应是 `[256,65,66,258,258]`，标签为 `[65,66,257,-100,-100]`，有效目标数为 3。

把相同文档添加两次，独立文档数应不增加。再用两个相似但不相同的句子测试：当前精确去重会保留两者。由此提出升级方案：使用相似度或 MinHash 做近似去重，再检查训练与验证是否共享近重复。
